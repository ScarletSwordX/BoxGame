## 0. 本次到底改什么

### 0.1 用户明确要求与本版实施选择

| 分类 | 内容 |
|---|---|
| 用户要求 | 加入玩家推动物体，以及登上相邻一格高物体的能力 |
| 用户要求 | 不再受金字塔主题限制，以物品和性质容易理解为优先 |
| 用户提出的方向 | 使用推动状态区分“推物”和“登上”；讨论用 PUSH / STOP 整合 BLOCK 的实体性 |
| 本版选择 | 按住 Shift 进入推动模式，松开退出；不是永久开关，也不要求先绑定一个目标 |
| 本版选择 | 普通方向键走路或登上一格；Shift＋方向只平走或尝试推动，推失败绝不自动登攀 |
| 本版选择 | 删除可拼词 BLOCK；PUSH 自带实体性和可推性，STOP 提供实体阻挡与承托；PUSH＋STOP 仍可推 |
| 本版选择 | JUMP 属性统一改名为 BOUNCY，原地跳动作仍称 JumpInPlace；弹起落下者三格的语义不变 |
| 本版选择 | 主体改为 ROBOT / ROCK / CLOUD / SPRING / FLAG；颜色只作辅助识别 |
| 延续 | 一格身体、世界默认下落、YOU 默认实体、可动文字也下落、HOVER / FLY 是重力例外 |
| 延续 | 同格进入空心 WIN；无邻接兜底；四槽斜俯视；完整撤销与编辑器隔离试玩 |
| 不加入 | 自由定向跳、两格身体、拉箱、自由空中推物、边缘支撑、实时物理、任意换体或多个 YOU |

键位、组合优先级与接触细节是本版为了消除实现歧义采用的方案，不冒充用户逐字指定，也不声称已经通过玩家易用性测试。

### 0.2 最重要的两条变化

**动作从“遇文字自动推”改为“松手走／爬，按住才推”，对文字和普通物体一致。**

**属性从“BLOCK 加 PUSH 才能推”改为“PUSH 本身就足够”，不再让玩家拼两个词才能得到一个普通箱子。**

内部仍必须有统一的 `EffectiveSolid` 查询。删除一个玩家词汇，不等于删除碰撞与承托判断，也不是把判断散落到 ROCK、CLOUD 等各类脚本里。

### 0.3 这不是对参考游戏的机制复刻

本文定义本项目自己的 PUSH / STOP / BOUNCY、推物模式和三维支撑规则。不承诺它们与任何参考作品的同名词、优先级或内部实现完全一致。规则是否“更直观”是待验证的设计假设，不能以本文或有限脚本检查当作玩家实验结果。

## 1. 要验证的体验：先认识一个东西，再改变它的用途

一句话：**玩家能移动物品和文字，改变物品的性质，并通过推、登攀、弹跳与搭乘使用自己改造的路线。**

核心循环：观察物品和规则 → 选择推走物品还是登上它 → 改写一句话 → 看见同类物品变化 → 利用新性质抵达空心目标 → 必要时撤销。

首批关卡的认知顺序是：

```text
石头可以推动，也可以踩上去。
STOP 石头与 PUSH 石头的差别，来自规则，不来自模型。
云会悬停，但未必能踩；加 STOP 才形成平台。
弹簧有弹性，需要真实落到上面才会弹。
把 BOUNCY 从弹簧移给石头，石头同样能弹人。
云的 HOVER 换成 FLY，从静止平台变成升降平台。
```

典型组合用于建立预期，非典型组合用于展示“规则可改写”。不能让弹簧永远弹、云永远浮、石头永远挡路，再把规则文字当成装饰标签。

本版不追求同时演示所有属性组合。`ROCK IS HOVER`、`FLAG IS PUSH` 等可作为后续实验，先完成六关已经覆盖的核心关系。

## 2. 物品身份与表现目录

| 主体 | 最低可识别表现 | 教学中的典型规则 | 不能藏在模型里的默认能力 |
|---|---|---|---|
| ROBOT | 一格内的小机器人，有脸和明确的朝向反馈 | ROBOT IS YOU | 不因名字叫 ROBOT 就绕开 YOU；不把两格视觉身体塞进一格碰撞 |
| ROCK | 有平顶与石纹的独立岩块，能看清一格占用 | ROCK IS PUSH，或 ROCK IS STOP | 不天然可推、不天然免重力；失去实体属性后应显示为虚像 |
| CLOUD | 一格范围内的云团，雾状轮廓与石头明显不同 | CLOUD IS HOVER；需要承托时加 STOP | 不因外形像云就隐藏 HOVER；云团默认也会掉 |
| SPRING | 一格高的弹簧台，顶盖与实际承托高度一致 | SPRING IS STOP AND BOUNCY | 弹性来自 BOUNCY，拆掉后同一个弹簧仍在，但不再弹 |
| FLAG | 小旗图标置于一格空心目标框内，不用大块实体门堵住入口 | FLAG IS WIN | WIN 不暗中消除 PUSH / STOP；只有非实体目标才能直接进入 |
| Text | 带词与图标的文字牌，和对应实例明显区分 | 固有可推、实体；除锁定文字外都受重力 | 写着 ROCK 的文字不是 ROCK 实例，不跟着 ROCK IS FLY 上浮 |
| Terrain | 连续、固定的底板与结构台面 | 固定场景结构，不参与名词规则 | 不与独立 ROCK 使用完全一样的轮廓、标记和材质组合 |

固定规则显示在只读规则板，不能藏在组件里。可动规则在玩法格子内；锁定文字显示铆钉或固定底座，不能看起来可推却因为谜题脚本而推不动。

### 2.1 身份与属性叠加，不互相替换

ROCK 获得 BOUNCY 后仍是原来的石头，用顶面弹性纹、压缩与释放表现新性质；不把模型直接换成普通弹簧。SPRING 失去 BOUNCY 后保留其外形，但解除发光弹性标记、没有压缩发射反馈。

CLOUD 获得 STOP 后增加清晰的顶面与实体边界，不必变成金属箱。HOVER 显示水平悬停标记；FLY 显示上升方向与实际高度变化；二者不能共用同一套持续上行提示。

任何物品只凭颜色都应当还能区分。可改写 ROCK 与不可改写 Terrain 必须有冗余身份线索。

## 3. 用 PUSH / STOP 整合实体性

### 3.1 给玩家的定义

| 属性 | 玩家看到的含义 | 不包含的效果 |
|---|---|---|
| YOU | 由我控制；受控对象默认有实体表面 | 不自动具有 PUSH；不是永久绑定 ROBOT 模型 |
| PUSH | **可推动的实体**，也可以承托、可以登上 | 不自动悬停；不会被普通走路误推 |
| STOP | **阻挡穿入的实体**，也可以承托、可以登上 | 不是“停止所有运动”，不取消重力，不禁止 FLY |
| HOVER | 保持当前高度，不主动下落或上升 | 不自动实体化；不禁止外力推动 |
| FLY | 自动向上移动，直到受阻 | 不自动实体化，也不自动载人；载人还要实体表面 |
| BOUNCY | 实际落到其实体顶面的物体被弹高三格 | 不自行跳跃，不自动提供实体表面 |
| WIN | 另一个 YOU 实体与它同格时获胜 | 不包含邻接获胜，不覆盖碰撞，也不自动悬停 |

中文辅助标签使用“STOP｜阻挡”，不用“停止”。若后续玩家仍反复把 STOP 理解成冻结，可统一评估更名为 SOLID；本版不同时放入 STOP、SOLID、BLOCK 三个近义词。

### 3.2 精确真值表

下面针对普通 Object，不包括 YOU、Text、Terrain 的基础来源。

| STOP | PUSH | 有实体顶面 | 能被主动推／顶／压 | 正常重力 |
|---|---|---|---|---|
| 无 | 无 | 否 | 否 | 仍会下落，除非 HOVER / FLY |
| 有 | 无 | 是 | 否 | 仍会下落，除非 HOVER / FLY |
| 无 | 有 | 是 | 是 | 仍会下落，除非 HOVER / FLY |
| 有 | 有 | 是 | 是 | 仍会下落，除非 HOVER / FLY |

**STOP 的意思是“阻挡直接穿入”，不是“反对 PUSH 的禁令”。**所以 `ROCK IS STOP AND PUSH` 不是冲突；PUSH 给它增加手动可动性。只有 STOP 时不可手动搬动，是因为缺少 PUSH，而不是 STOP 另行禁止一切位移。

因此：

```text
ROCK IS PUSH             一个词就得到可推、可踩的石块。
CLOUD IS STOP AND HOVER   一个静止在空中的实体平台。
SPRING IS STOP AND BOUNCY 一个不能直接搬走，但能弹起落下者的弹簧。
ROCK IS PUSH AND BOUNCY   一个可以搬动的弹跳石。
CLOUD IS STOP AND FLY     一个会上浮且能够承托乘客的平台。
```

`CLOUD IS HOVER` 单独成立时只是悬停云影，不能站。`SPRING IS BOUNCY` 单独成立时没有实体接触面，因此不会拦住并弹起玩家；编辑器应明确警告，而不是偷偷补 STOP。

### 3.3 内部推导，不新增可拼 BLOCK

```text
ExplicitProps(e) = 固定规则板和当前可动句子对 e.subject 的属性并集

对于 Object：
  EffectiveSolid = YOU ∈ ExplicitProps 或 PUSH ∈ ExplicitProps 或 STOP ∈ ExplicitProps
  CanManualDisplace = PUSH ∈ ExplicitProps 且当前不是 YOU

对于 Text：
  EffectiveSolid = true
  CanManualDisplace = !anchored

Terrain：固定、实体，不进入上述名词属性解析。

有效重力：
  明确固定的文字／地形 → Anchored
  否则 FLY → Up
  否则 HOVER → Hover
  否则 → Down（世界默认）
```

固定约束不是一种偷偷给 Object 勾选的免重力属性。首版 `anchored` 只允许用于 Text；固定墙和地板用 Terrain。

FLY 与 HOVER 同时出现时采用 Up，并在来源面板显示 HOVER 被覆盖。六关不以这种优先级冲突作为谜题；第六关实际替换文字，不依赖“有两个重力词时猜谁赢”。

### 3.4 合并的代价要承认

本版不能表达“可推但完全非实体”这种组合，也不会保留一个独立 BLOCK 来补它。这是有意缩减的规则空间，不是程序缺陷。

`FLAG IS PUSH` 会让旗标实体化：可以推它，却不能再直接进入其格子。需要取消 PUSH 后才能按同格目标使用。初批六关不教这件事，但表现与规则不能自相矛盾。

## 4. 输入：走／登攀与推动由玩家明确选择

### 4.1 默认键位

| 玩家阶段 | 输入 | 逻辑意图 |
|---|---|---|
| Grounded，未按 Shift | WASD／方向键 | Move：平走；相邻是一格实体台阶时登上去；不自动推 |
| Grounded，按住 Shift | WASD／方向键 | Push：前方为空则平走；前方为可推物则推链；不自动登阶 |
| Grounded | Space | 原地跳一格，执行既有的顶起／落地接触；无水平分量 |
| BounceApex | 新的方向按下 | 顶点横移一格，然后恢复下降；不推、不爬 |
| BounceApex | Space | 原位恢复下降 |
| 可观察状态 | Q / E | 切四个视角槽，不推进模拟 |
| 游玩状态 | Z / R | 整步撤销／重开 |

**Shift 选择的是水平推动意图，不是增加力气、不改变物品属性、不把 STOP 临时变为 PUSH。**

推动状态采用按住，不采用“点一下切换、再点一下退出”。按下/松开 Shift 不消耗回合，不让世界运动，不增加撤销记录。首版不做“先抓住一块，再绕着它走”的锁定目标系统。

代码中的 `PushMode` 是输入与表现状态，不是需要保存进关卡或模拟快照的新物理属性。回放直接记录 Move 或 Push，不记录玩家按了多长时间的 Shift。

### 4.2 推动时的最低反馈

按住 Shift 时角色进入推物姿态，HUD 显示“推动中”；输入方向或指向相邻物体时显示本次会移动的链条、目标格，或具体拒绝原因。文字与石块使用同一套提示。

松开 Shift 后立即恢复“移动／登攀”。失去窗口焦点、结束试玩、撤销或重开时清除输入层遗留的按住状态，避免出现看不见的持续推动模式。

推不动的原因要区分“没有 PUSH”“末端被挡”“文字已锁定”“顶部或边界问题”；不能只用一个无说明的失败音。

### 4.3 组合键与空中输入边界

地面同帧 Space 与方向同时按下时只提交原地跳，不缓存方向为后续侧移。Shift＋Space 也只是原地跳；Shift 不让它变成定向跳。

到弹跳顶点必须有一次新的方向输入，长按走路不能自动吃掉选择机会。顶点阶段方向统一映射为空中侧移，Shift 不把它变成空中推物。外部回放直接提交 Push 到顶点时应拒绝。

P0 每次按下最多提交一条世界命令；长按重复移动属于后续输入便利性，不得改变单条命令规则。

## 5. 动作的精确定义

统一坐标 `(x,y,z)`，Y 向上；身体占一格，四向为 ±X / ±Z。人物站在 Y=0 的地板上时身体在 Y=1。

### 5.1 普通移动与一格登攀

令玩家身体格为 `p`，水平方向为 `d`，相邻格 `q = p+d`。

- 若 q 可进入：进入 q，再按重力结算。这允许走出边缘下落，不会跨过空洞。
- 若 q 是可承托的实体，且 `p+Up` 和 `q+Up` 都可进入：进入 `q+Up`，表示登上一格。
- 否则拒绝。**不转成 Push，不继续尝试登两格。**

登攀前检查起点上方与终点上方的净空，防止穿顶或穿墙角；主动作按一个已经预检的原子移动组提交。起点上方只用于净空预检，不是独立的可停留决策格，动画经过不单独触发 WIN。

ROCK、具有实体性的 CLOUD、SPRING、Text、Terrain 的顶面采用同一支撑判断。是否可推不影响能否登上；PUSH 岩块也可以原地保留后登上。

登上 BOUNCY 顶面不算向下落地，不立即发射。需要从台上原地跳起再落下，或从更高处真正落到它上面。

### 5.2 水平推动

Shift 方向在前方为空时只平走，不登阶。前方存在实体时，沿 d 收集连续的 `CanManualDisplace` 对象，允许文字与物品混合推链。

每个对象只能水平移动一格。链中有 STOP-only、锁定文字、Terrain、不可推 YOU 或越界，或末端不能容纳该链，整条拒绝。

预检成功后，同时移动整条链与走入第一块旧格的玩家；这个原子组结束才重算规则。不能先挪开 STOP、让 ROCK 临时虚化，再把 PUSH 挪进句子，除非它们本来就是两条独立操作。

不支持连锁拉动、斜推、向上推整塔或水平搬运箱塔。推走支撑体时，其上普通物体保留水平坐标，随后依照重力结算；不凭“站在上面”自动水平随动。

没有物品重量等级、推两块要两人等新系统。链条长度只有地图和阻挡约束，不加隐藏力量上限。

### 5.3 原地跳、顶起与下压

原地跳保留一格高度，不允许普通跳顶点横移。正上方为空则上移一格，之后下降；正上方为单个可手动移动的实体且其上方可进入时，可原子顶起该对象一格。

**本版统一：主动顶起和落地压低也要求被操作物具有 PUSH（Text 使用默认可推），STOP-only 不被手动搬动。**这是与旧 v0.5 相比的明确变更；不要只改水平推动而让 STOP 仍能被另一动作随意搬动。

只有一个被顶体，不能连顶整摞。普通文字被顶高后仍会下落，没有隐藏悬浮；HOVER 物品被顶高后可以保持新高度。

真实下降后接触一个可推支撑体，其下方可进入时，保留“一条指令最多压低一格一次”的旧接触机制；持续站立不重复压。它主要用于悬停可推体等组合，六关不强迫使用。BOUNCY 优先消费接触，不同时下压。

### 5.4 BOUNCY：弹起落下者，不是弹起自己

只有下落者在这一接触段实际发生过 -Y 位移，并撞到某个**有效实体＋BOUNCY** 的上表面，才触发。

```text
弹台身体在 Y=1。
落下者接触时身体在 Y=2。
逐格上升 Y=3 → Y=4 → Y=5。
正常顶点在 Y=5；三格从接触位置算，不从起落高度算。
```

侧撞、静止站立、等高走到顶面、登攀到顶面、从下面顶碰都不触发。顶棚会逐格截断上升，不穿透，不顺便顶起顶棚上的物体。实际上升为零时不创建假顶点，也不补发下压。

YOU 到达顶点后允许一次侧移，或者原位下降。侧移受阻保留机会；成功后不能再在空中推、爬或补一次普通跳。落到另一弹台可以产生新的顶点。

非 YOU 物体同样可以被弹；其新顶点记录为暂停状态，在下一条有效世界指令中恢复原位下降，不在同条指令中无限循环弹跳。等待观察、切镜头、被拒绝输入不推进它。

### 5.5 上浮与载人

FLY 物体按世界 +Y 逐格上移，HOVER 物体不主动移动。STOP 和 PUSH 都不会妨碍其获得 FLY；`STOP AND FLY` 的含义是“会上浮的实体”，不是冲突。

FLY 平台只有在自身有实体表面、YOU 正站在其直接上方且不是弹跳顶点或强制下降时，才能携带玩家。平台和玩家的目标格全部检查后原子上移。

玩家头顶被挡时整组停下，不挤压、不穿顶、不让平台穿过玩家。玩家离开后平台仍有 FLY，应继续到自身受阻。P0 不承运整摞普通物品或文字；这些接触会阻挡平台，不能偷搬整塔。

## 6. 同格、碰撞与胜利：保持一致

### 6.1 本版统一的接触模型

为了使新加入的可推物品与空心对象有一致的双向规则，本版对 v0.5 的特殊接触组合进一步简化为：

| 两者关系 | 是否可以同格 | 是否可以互相承托 |
|---|---|---|
| 动态实体＋动态实体，双方都是 EffectiveSolid | 否 | 可以，按直接下方接触 |
| 两个动态对象中至少一个非实体 | 是，与谁主动运动无关 | 不可以，非实体既不提供也不接受这种动态实体承托 |
| 任何动态对象＋Terrain | 否 | Terrain 可承托包括空心目标在内的动态对象 |

这里“动态”包括可动 Text；锁定 Text 仍按实体文字处理。首版空心对象可以穿过动态石块或文字，但不能穿过固定 Terrain；目标的落点应放在 Terrain 上，不靠空心交互产生隐形承托。

这是公开的规则边界，不是对真实物理的模拟。它避免“石头能占入空心旗标，但旗标反向移动却被石头卡住”的隐蔽方向差异。

支撑要求 `StrictBelow`：直接下一格有可碰撞的实体承托面；没有侧面、边角、同层互托。可推性与支撑分开，默认重力与支撑也分开。

### 6.2 唯一胜利条件

```text
存在不同 ID 的两个对象 a,b：
  YOU ∈ a 的有效属性
  WIN ∈ b 的有效属性
  a.cell == b.cell
```

不看模型包围盒、屏幕投影、面邻接、距离或触碰外壳。自己同时具有 YOU 和 WIN 不能自己与自己配对获胜。

每个合法原子位移及随后规则重算完成后，先校验状态，再检查 WIN；命中立即记录终局并停止后续自动运动。玩家进入旗标、旗标下落到玩家格、载人或弹跳途中真正进入目标格都有效。

WIN 不覆盖 PUSH / STOP。`FLAG IS WIN AND PUSH` 仍是实体，走近或登在上面不算获胜。六关 FLAG 均无 PUSH / STOP，清楚表现为可以填入的空间。

### 6.3 规则改变实体性造成非法同格

两个已经同格的对象若因规则变化同时成为实体，首版不自动挤开、压碎或随机选方向传送。返回明确 `RuleConflict`，整条命令回滚，提示冲突对象与来源句子。

这是一项明示的原型限制，不允许看起来规则已经永久生效却偷偷跳过冲突。六关参考解不依赖此行为。未来设计“在体内实体化”谜题必须另订语义，不能直接沿用本版检查结论。

## 7. 规则系统与确定性结算

### 7.1 词库与语法

```ebnf
Sentence = Subject, { AND, Subject }, IS, Property, { AND, Property } ;
Subject  = ROBOT | ROCK | CLOUD | SPRING | FLAG ;
Property = YOU | PUSH | STOP | HOVER | FLY | BOUNCY | WIN ;
```

同一高度、沿世界 +X 或 +Z 连续直线读取；不读反向、Y 轴、对角、拐弯或镜头投影句。四视角不改变规则。

属性取并集，不按文字摆放先后“最后一句覆盖前一句”。同一名词作用于本关所有同类实例；模型颜色不额外限定作用对象。

支持最长有效前缀：`ROCK IS PUSH AND` 仍保留 PUSH；`ROCK IS PUSH AND BOUNCY` 再增加 BOUNCY。重复句子不重复弹跳或上浮。

固定规则板和玩法文字采用同一个词库与属性查询。固定句保留 sourceId；空间句保留词 ID、轴和位置。每次有效文字位移，包括下落、顶起、推动或弹跳，都重建 RuleSet，不能只听主动推字事件。

### 7.2 一条命令就是一条撤销事务

```text
已有可操作状态 S0
  → 在副本上预检 Move / Push / JumpInPlace / ApexStep / ResumeDescent
  → 拒绝则原世界与历史不变
  → 原子主动作
  → 重算规则和默认来源、校验、检查 WIN
  → 完成玩家本段下降与落地／弹跳
  → 环境上浮与下落结算，直到稳定或待决策顶点
  → 提交最终状态与一条 S0 快照、阶段事件
```

动作被接受后，即使普通跳最后回到原格，也是一条有效命令；它可以推进此前暂停的非玩家弹跳。单独按住 Shift、观察、切视角、无效输入不是时间步。

沿用有序微步，而非物理引擎或不明确的“全部同时发生”：环境 Up 按 Y 降序、稳定 ID 排序，每轮每体上升一格；Down 按 Y 升序、稳定 ID 排序，逐格下降到接触或模式变化；必要时重复。

每个原子变化后读取最新规则，不能用已失效的 HOVER / FLY 继续运动。规则与默认重力不是两个依次施加的力。采用其他调度方式会改变谜题，必须作为新玩法版本处理。

### 7.3 终止、快照与初态

新增 BOUNCY 顶点暂停，避免单条命令无限弹跳；同时保留重复状态检测及防御微步上限。C# 建议起始上限 4096 原子变化并可配置，超限属于模拟诊断，不是玩家步数限制。

快照包括所有对象 ID、位置、存在性、锚定状态、运动阶段、顶点与待恢复下降、终局与胜利记录。派生索引和属性恢复时重建；不把旧 UI 材质当属性缓存。相机槽与推动键按住状态不是物理世界快照的一部分。

原型初态必须稳定、未获胜且恰有一个 YOU。先解析规则再检查重力；不能先让云掉落，再发现它有 HOVER。无法运行稳定化时报告具体问题，不偷偷应用到作者关卡。

零个／多个 YOU、受控体获得未设计输入协议的 HOVER / FLY 等首批未支持组合，校验与运行时都给出明确诊断，不以卡死表现。六关控制句固定为 ROBOT IS YOU。

## 8. 镜头、可读性与教学反馈

保持正交斜俯视和四个相差 90° 的视角槽；不做自由旋转、透视错觉成路或投影成句。默认斜角只为看清顶面和高度，不照搬特定作品的美术。

输入适配器把屏幕方向转换为世界命令；一个可采用的槽位映射为：

| 槽 | W／上 | D／右 | S／下 | A／左 |
|---|---|---|---|---|
| 0 | +Z | +X | -Z | -X |
| 1 | -X | +Z | +X | -Z |
| 2 | -Z | -X | +Z | +X |
| 3 | +X | -Z | -X | +Z |

相机与地面方向提示必须按同一槽位配置，使提示箭头与实际画面匹配。回放只存 E/W/N/S 的世界方向，不能存 W 键再受镜头影响。切镜头不修改实体位置、语法、顶点机会或回合。

至少提供：当前有效规则、推动模式、被选对象的身份与属性来源、下一步可到达格、撤销／重开、失败原因。上层遮挡采用分层淡出或轮廓提示，不能让通关依赖猜背后的文字。

规则改变时按日志展示：句子变化 → 受影响同类物品标记 → 状态外观变化 → 运动结果。每次只重点高亮本次改变，不持续闪动所有物体。

提示按“观察问题 → 规则原理 → 具体操作”逐级展开。提示由行为事件触发，不凭在屏幕上等待几秒来催促玩家。不得用教学完成标记替代 WIN 条件或隐藏锁住出口。

## 9. 程序框架：沿用边界，替换语义

采用已确定的纯 C# Core、Unity Runtime、Editor、Tests 分层。规则与空间以整数数据为唯一真相，不用 Transform、Collider、刚体质量或动画事件决定结果。

保留实际工程的 Unity 2022 版本、输入后端、渲染管线、目录和程序集约定；不要为更换游戏工作名重建整个仓库。手动 Bootstrap 组装依赖，不新增重型 DI、ECS、热更或通用 DSL。

| 模块 | 本版职责 |
|---|---|
| EntityDefinition / EntityState | kind、subject、token、cell、稳定 ID；不再用 color 选择规则 |
| RuleParser | 同高度 +X/+Z 和 AND，输出属性与来源 |
| PropertyResolver | EffectiveSolid、CanManualDisplace、GravityMode、BOUNCY、YOU、WIN 的唯一来源 |
| GridOccupancy / CollisionPolicy | 每格实体集合、实体双向共享判断、Terrain 阻挡、StrictBelow 支撑 |
| MovePlanner | 普通移动／登上一格；不推物 |
| PushPlanner | 预检文字与物品的混合推链；不登阶 |
| Contact / Bounce / Vertical Resolver | 原地跳、PUSH 顶压、真实落地、三格弹跳、平台载人与世界重力 |
| SimulationEngine / GameSession | 整条事务、拒绝与冲突、快照撤销、终局与事件 |
| InputAdapter / PushModePresenter | 按住 Shift、键位优先级、焦点与新按下检测；不修改属性 |
| PresentationCatalog / WorldView | 主体图标与外形、属性叠加、目标空心表现；不反推碰撞 |
| LevelEditSession / Validator | 作者数据、编辑撤销、结构与初态校验、与试玩隔离 |
| EditorWindow / SceneGridPainter / PreviewHost | Unity 工具界面与预览，复用相同 Core |

这些是职责，不要求一行对应一个接口或几十个空类。只为实际替换点保留接口。Core 不引用 UnityEngine / UnityEditor；Runtime 不引用 UnityEditor。

表现配置可用已有项目的 ScriptableObject 目录，映射 `subject → prefab/icon` 与属性效果；不要在 Prefab 中再维护一份“石头天然 PUSH、云天然 HOVER”的规则真相。

| 编辑器能力 | 具体要求 |

## 11. 六关教学与可复建灰盒

以下是本版全新布局，不是把旧色块模型换名。目标是六个短教学切片，不是六个已经证明成熟的谜题。

坐标中 Y 是身体格高度；地形范围端点包含。关卡底部均有真实 Terrain，失败尝试主要通过撤销恢复，不依赖看不见的虚空死亡或计时压力。

每关固定规则板与网格文字同时生效。固定规则板不占格；标注“锁定”的网格文字占格且能承托，但不能移动。参考路径中的 `E/W/N/S` 是世界 ±X/±Z，`PE/PW/PN/PS` 是推动模式的世界指令，`J` 为原地跳，`WAIT` 为顶点原位下降。

**参考路径事件是验收观察点，不是额外通关条件。**存在另一路径时不能以未完成教学标记为由拒绝玩家同格获胜。

关卡边界应以可见托盘轮廓或空间边框表达；越界不会成为隐藏的第四种动作。第六关的电梯停止依靠真实顶板，不依靠高度触发器或看不见的停止脚本。

### 11.1 L01｜推走它，还是登上它

**核心问题：我要把这块石头推到哪里，才值得登上它？**

本关引入：普通方向可登一格；按住 Shift 才推物；进入空心旗标才获胜。

岩块位于玩家面前，远处出口台面比地面高两格。三次向东推动把岩块放到高台旁，松开推动键后依次登岩块和出口台面。

固定规则板：

```text
ROBOT IS YOU
FLAG IS WIN
ROCK IS PUSH
```

边界：`(0,0,0) ～ (8,7,2)`，端点包含。

| 地形盒 | 最小格 | 最大格 |
|---|---|---|
| T1 | `(0,0,0)` | `(8,0,2)` |
| T2 | `(6,1,0)` | `(8,2,2)` |

| 实体 ID | 身份／词 | 身体格坐标 | 是否锁定 |
|---|---|---|---|
| `player` | ROBOT | `(1,1,1)` | 否 |
| `rock` | ROCK | `(2,1,1)` | 否 |
| `goal` | FLAG | `(7,3,1)` | 否 |

参考指令：

```text
PE PE PE E E E
```

| 步 | 指令 | 玩家结果格 | 阶段 |
|---|---|---|---|
| 0 | 初态 | `(1,1,1)` | Grounded |
| 1 | `PE` | `(2,1,1)` | Grounded |
| 2 | `PE` | `(3,1,1)` | Grounded |
| 3 | `PE` | `(4,1,1)` | Grounded |
| 4 | `E` | `(5,2,1)` | Grounded |
| 5 | `E` | `(6,3,1)` | Grounded |
| 6 | `E` | `(7,3,1)` | Won |

**逐级提示**

1. 这块石头既是障碍，也可以成为台阶。
2. 按住 Shift 才会推动；松开后，方向键会尝试登上它。
3. 把岩块推到高台旁的 X=5，再松开 Shift 向东走。

**关键检查点：**前三次 PE 使岩块由 (2,1,1) 到 (5,1,1)；之后 E 只改变玩家高度，不移动岩块；最终进入 (7,3,1)。

**布局约束与绕解风险：**出口台面覆盖整个关卡宽度且高两格，不能从侧面找到一格台阶绕上去。没有额外可动文字可当替代箱子；固定规则板不占格。

**表现要点：**第一次接近岩块时同时预览“普通方向：登上”与“Shift 方向：推动”的两个不同目的格。不要强制弹窗中断动作。

### 11.2 L02｜换一个词，石头就能搬

**核心问题：还是同一块石头，为什么换一个词后就推得动了？**

本关引入：STOP 与 PUSH 的差别；推动实体文字，原子替换属性；所有移动文字同样使用推动键。

低一层的规则槽中已有 ROCK IS STOP，PUSH 位于 STOP 前方。一次向北推链将 PUSH 推入属性槽，同时把 STOP 推到句子外。随后玩家登上操作区地面，将岩块推到高台边，再登顶。

固定规则板：


| T3 | `(8,2,0)` | `(10,3,5)` |

### 12.3 边界案例与不做的事

本包参考模型是单 YOU、封闭有底托盘、有限灰盒验证；不是完整物理系统。复杂相向自动移动、多个 YOU、零 YOU 恢复、自由飞行受控体、任意实体化冲突、空中连推、载运整塔、无底死亡、边缘支撑，都不能凭六条路径通过而宣称已支持。

没有自动求解器，也没有唯一解／最短解／无绕解证明。无限撤销降低失误成本，不保证规则上没有死锁。

## 13. 旧工程和旧关卡的迁移

| 旧内容 | 本版处理 |
|---|---|
| color: RED / BLUE / PINK | 改用 subject；根据实际关卡职责选择 ROBOT/ROCK/CLOUD/SPRING/FLAG，不能全局机械映射 BLUE 为一种物体 |

| JUMP 属性 | v0.5 的落地弹跳语义更名 BOUNCY；更早版本的横撞 JUMP 不可这样机械迁移 |
| FALL 或文字免重力 | 不恢复；所有非固定动态对象默认下落 |
| Move 自动推字 | 改为普通 Move 走／爬；推字和推物都必须使用推动意图 |
| 无自动登阶 | 明确被本版一格登攀替换，必须重查旧关卡可达性 |
| 所有实体都能被顶／压 | 改为仅 CanManualDisplace 对象；STOP-only 不接受这种手动搬动 |
| YOU 与空心对象的特殊单独接触层 | 统一为动态双方实体才互斥、Terrain 阻挡所有对象；不能混着调用两版 CanShare |

| 旧 schema=5 / RP-v0.5 | 正常加载器拒绝当作新规则直接运行；明确迁移后另存，不原地覆盖唯一副本 |

不擅自删除旧资产。把旧规格和旧关卡归档，主实施入口只指向本版。若已有 C# 模块可以复用，就修改其合同和测试，不为重命名工程从零复制一套平行系统。
