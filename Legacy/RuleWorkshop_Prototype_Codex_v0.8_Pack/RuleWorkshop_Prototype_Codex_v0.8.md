## 1. 本次的硬性要求

### 1.1 用户要求与实现选择分开

| 类型 | 本版约定 |
|---|---|
| 用户要求 | 关卡总数限定为 **12 关**，不以附赠第 13 关填补教学 |
| 用户要求 | **第 2 关起**，通关需要与规则文字或物品发生有效互动，不能只靠走路、登攀、跳跃走到终点 |
| 用户要求 | 至少三分之一的关卡解法不唯一，即 **至少 4/12 关**存在不同解法 |
| 本版加强 | 将“不唯一”落实为**不同解法类别**：改变可达路线、改变 WIN 对象、转移 YOU、让目标移动、选择不同上升机制；绕路、交换无关动作顺序不算 |
| 本版安排 | **L08—L12 共 5/12 关**各有至少两类解法；L12 有三类。共提供 18 条参考解 |
| 本版扩展 | YOU 可在不同实例间转移；旧身体能成为 WIN 目标。当前至多一个受控实例，允许可撤销的 NoControl 状态 |
| 用户最新要求 | **允许 `ROBOT IS FLAG` 等名词到名词的实体变形**，不仅是模型换皮或控制权转移 |
| 本版边界 | 不做一变多复制、多个 YOU 同步输入、混合名词／属性右侧或自身 YOU+WIN 立即获胜；具体冲突显式诊断 |
| 不采用 | “先碰一下任意方块，出口才放行”的任务计数门槛、解法 A/B 模式按钮、按照参考解顺序才解锁的脚本 |

**现在两种方法都存在：**第 9 关仍可给原机器人 WIN、换控旗帜，原机器人身份不变；第 12 关还可以先换控唯一弹簧，再拼 `ROBOT IS FLAG`，把原机器人真正变成旗帜。两者都必须由另一个 YOU 实例进入目标，不能同一实例自胜。详细变形时序、属性重算与范围见 3.5—3.12。

### 1.2 交付不是从 6 个单解房间简单翻倍

前七关逐步建立操作与性质知识；后五关在同一初态下开放策略选择。第一次通关即完成关卡，不要求玩家把所有解法再做一遍。通关后可以显示“还有另一种思路”，但不直接剧透或把正确的短解视为作弊。

首七关只是以一个教学解组织内容，**不宣称它们只有唯一解**。后五关的两／三类解法必须能从各自同一份初始 JSON 独立回放，不通过重开时换词、换布局或修改规则集实现。

## 2. 保留的世界与动作合同

### 2.1 世界与物品

世界使用 `(x,y,z)` 三维整数格，Y 向上；每个实例占一格。Terrain 是固定结构；Object 的名词为 `ROBOT / ROCK / CLOUD / SPRING / FLAG`；Text 是词牌。写着 ROCK 的词牌不是 ROCK 实例，不响应 `ROCK IS FLY`。

所有未固定动态对象默认下落，包括空心目标和可动文字。没有新的 FALL 词。HOVER 表示保持当前高度，FLY 表示向上运动，优先级为 `FLY > HOVER > 默认 Down`。固定规则板属于可见只读配置；空间中的固定词牌用铆钉或底座表示 `anchored`。不得给普通 Object 隐藏免重力开关。

本轮 12 关都有实际的底板，不借助不可见边界地板完成解法。生产核心继续区分横向／顶部边界和底部虚空；Python 参考模型只覆盖有实际底板的布局，不验证坠入虚空的死亡／移除。

### 2.2 属性与实体性

| 属性 | 定义 |
|---|---|
| YOU | 接收当前玩家输入，隐含实体性；不是永远绑定 ROBOT，也不隐含 PUSH |
| PUSH | 可手动推动的实体，可承托、可登上；不免重力 |
| STOP | 阻挡直接穿入的实体，可承托、可登上；不是冻结，不否定 PUSH 或 FLY |
| HOVER | 不主动升降，失去支撑也保留高度；不自动实体化 |
| FLY | 自动逐格上升直到被阻挡；需要实体表面才能承运玩家 |
| BOUNCY | 实际下落到其实体顶面的对象，从接触格向上弹三格；不自带 STOP |
| WIN | 与另一个具有 YOU 的对象同格时胜利；不覆盖碰撞规则 |

```text
Object.EffectiveSolid = 有 YOU 或 PUSH 或 STOP
Object.CanManualDisplace = 有 PUSH 且当前不是 YOU
Text.EffectiveSolid = true
Text.CanManualDisplace = !anchored
```

`PUSH + STOP` 仍可推；没有 PUSH / STOP / YOU 的普通物品是非实体。BLOCK 已从词库删除，内部仍有统一的 EffectiveSolid，不在各物品脚本里各写一份。

两个动态对象只有在**双方都实体化**时才互相排斥、承托；至少一方非实体时允许同格，方向对称。Terrain 阻挡并承托所有动态对象，包括空心目标。支撑只看正下方，没有边缘、角点或同层互托。

WIN 不隐含非实体：`ROCK IS WIN AND PUSH` 仍不能被直接进入。L08、L12 的改目标解法会真正移走 PUSH 或 STOP，再赋 WIN，而不是让胜利检测穿透实体。

### 2.3 输入与意图

| 阶段／输入 | 行为 |
|---|---|
| 普通方向 | 前格可进入则走入；前格为实体且起点、终点上方净空满足时，登上一格；不自动推 |
| 按住 Shift＋方向 | 前格为空则平走；有可推体则预检并推动整条连续推链；推失败不自动爬 |
| Space | 原地跳一格；没有水平分量，不缓存成定向跳 |
| 弹跳顶点的新方向输入 | 侧移一格，再恢复下降；不推、不爬、不补跳 |
| 弹跳顶点 Space | 原位恢复下降 |
| Q/E | 切换四个斜俯视角槽；不推进模拟 |
| Z/R | 撤销整个上一条命令／重开 |

Shift 是按住的输入意图，不是永久开关，不修改物品属性，不消耗回合。松开、失去焦点、撤销、重开后清除遗留输入状态。文字与物品使用同一套推法。

普通登攀是一个预检后的原子动作：`p → p+d+Up`，要求 `p+Up`、`p+d+Up` 可进入；不把动画经过 `p+Up` 当成一次独立的逻辑停留或获胜。没有自由定向跳、拉箱、两格身体或自动爬两格。

水平推链统一移动所有成员与操作者，再重算规则。不能逐个移动链成员，让中途断句产生实际不存在的短暂属性。移动支撑物时不自动水平搬运其上整摞物体。

### 2.4 原地跳、顶压、弹跳和上浮

顶起只处理正上方一个可手动移动对象；不连顶整塔。落地压低也要求被操作体可手动移动，且其下方可进入；每条指令最多对该下落者执行一次下压，静止站立不重复。BOUNCY 优先，不同时下压弹台。文字被顶起后仍会按默认重力回落。

BOUNCY 必须有一次真实的下降位移后接触上表面。走上、爬上、侧撞都不触发。弹台身体在 Y=1 时，玩家接触格为 Y=2，正常顶点为 Y=5，而不是从起跳前的位置加三。沿上升路径逐格检查顶棚，截断后不穿透。

受控体在弹跳顶点获得一次新输入机会；非受控体的顶点暂停到下一条有效世界命令再恢复下降，避免同一回合无限弹跳。只有物品实际被移动或规则改变才计入互动审核，单纯站上固定弹簧弹跳不算主动改造。

FLY 平台与正站在它上面的当前 YOU 成组逐格上升；双方目标格都预检，头顶堵住则整组停下。它只承运直接站在顶面的受控实例，不搬运整摞普通物品或文字。离开后平台仍会继续上升到受阻。

本轮利用移动规则的方法是**弹台／石台／云平台改变玩家路线**。不新增受控体直接获得 HOVER／FLY 后的自由飞行输入。当前 YOU 具有这两种模式时应显式诊断并回滚不支持的改写，而不是让操作失常；这项范围限制必须在编辑器规则预览中可见。

## 3. YOU 与 WIN：本版最重要的扩展

### 3.1 胜利公式不变

```text
存在不同实例 a、b：
  a 有 YOU
  b 有 WIN
  a.cell == b.cell
  且本次原子变化后的状态合法
```

同一个实例同时有 YOU 与 WIN，不能拿自己的 ID 配对获胜。不加入邻接、模型接触、投影重叠、接近距离或教学完成计数等兜底。

每次合法原子位移和随后的规则更新完成后，检查胜利；首次满足就记录 `youId / winId / cell / cause` 并停止后续自动运动。只因规则改变而让已经同格的两个实例成为 YOU 与 WIN，也会立即胜利。一次推链中尚未整体提交的临时位置不检查。

### 3.2 控制权转移与身份变形是独立操作

不要再写：

```text
GetEntity("player") 就是当前受控对象。
ROBOT Prefab 永远接收输入。
目标永远叫 goal 或者永远是 FLAG。
```

应从当前规则查询唯一受控实例与全部 WIN 实例。数据中的 `robot_01` 只是初始机器人的稳定 ID；即使控制权交给 `goal` 这个旗标实例，两个 ID 都不重命名。

失去 YOU 的对象只失去该默认来源：若没有显式 PUSH / STOP，它会变成非实体；若仍有显式 STOP，它仍然阻挡。取得 YOU 的对象获得默认实体性，但不会凭空得到 PUSH、HOVER 或其他能力。

### 3.3 一次推动完成安全换控

L09 的换控台采用相邻两行（L12 对应的目标主体为 SPRING）：

```text
初态：             将 IS 往下一行推一格后：
ROBOT  IS  YOU      ROBOT  [ ] YOU
FLAG   [ ] YOU      FLAG   IS  YOU
```

“下一行”是世界 +Z，同一 Y。移动的是一个实体词牌 IS。整条位移完成后扫描规则，旧 YOU 消失、新 YOU 成立，只有一个控制对象。先在另一处拼出 `ROBOT IS WIN`，旧身体失去 YOU 后就成为可进入的空心机器人目标。

这是第 9 关的纯换控用法，不执行名词变形。它不是两条程序脚本 `DisableRobot(); EnableFlag();`；来源仍是实际文字布局。第 12 关则先将控制权给 SPRING，随后另拼 ROBOT IS FLAG，实际改变原身体的身份。两类操作都不凭空改位置、身体格数或镜头槽位。

### 3.4 零个或多个 YOU

稳定初态必须恰有一个 YOU，且未获胜。

游玩中拆掉 YOU 可以进入 **NoControl**：完成本条指令剩余环境结算后，保留残局、提示撤销或重开；不偷选机器人继续操作，不丢失撤销历史。环境自动位移若在同条事务中重新拼回 YOU，则按最终状态继续。

本版未实现多个 YOU 同步输入。新规则让多个实例同时 YOU 时，返回明确 `MultipleYOU`，整条命令回滚，不随机挑第一个。编辑器应提前标出所有受影响实例。这是公开的原型范围限制，不是关卡里的隐藏规则。

输入、自动载人、落地处理、顶点状态、摄像机关注与 HUD 都要在规则变化后重新确定当前受控 ID，不能继续引用回合开始时的旧对象。动作阶段绑定实例，不绑定某一个名词或模型。

### 3.5 IS 的两种类型：赋性质与变身份

用户本轮明确允许 `ROBOT IS FLAG`。因此，名词变形现在是 **P0 正式机制**，不再用“给原身体 WIN”或“换控”代替。操作输入不新增按键，依然通过推、顶、压、下落等方式调整文字。

| 句子 | 实际含义 | 是否改变 subject | 拆掉句子后的结果 |
|---|---|---|---|
| `ROCK IS WIN` | 当前所有 ROCK 获得 WIN | 否 | 无其他来源时失去 WIN |
| `ROCK IS FLAG` | 当前所有 ROCK 实例就地变成 FLAG | 是 | 已完成的变形保留，不自动变回 ROCK |
| `ROBOT IS FLAG` | 当前所有机器人实例就地变成旗标 | 是 | 原机器人 ID 仍存在，但当前 subject 是 FLAG |
| `ROCK IS CLOUD` | 岩块变成云，并按现有 CLOUD 规则重新计算性质 | 是 | 是否悬停取决于 `CLOUD IS HOVER`，不是云的隐藏天性 |

名词变形作用于整关所有匹配 **当前 subject** 的 Object。无需场内预先存在目标类型实例；不会吸收现有旗帜，也不会移动到它的坐标。`ROCK IS FLAG` 不把写着 ROCK 的 Text 变成 FLAG 文字，也不改 Terrain。所有物种仍是一格，模型外观不扩大逻辑体积。

这是原型自己的明确语义，不声称完整复刻其他游戏的变形细则。

### 3.6 变的是身份，不是实例；性质不跨物种继承

变形批次保留 `id / cell / 当前运动阶段`，只改 `subject`，然后重新计算属性、实体性、重力、控制权和目标身份。不能把原属性位直接复制给新类型。

例如：

```text
ROBOT IS YOU
ROCK IS PUSH
FLAG IS WIN
ROCK IS FLAG  ← 玩家刚刚拼成
```

岩块成为旗帜；原来的 `ROCK IS PUSH` 即使还存在，也不再作用于它。若 FLAG 没有 PUSH/STOP/YOU，原岩块会成为可进入的空心旗标，由 FLAG 的 WIN 规则提供目标性质。这里不是 WIN 自动删除 PUSH，而是对象已不再是 ROCK。

反之，若同时存在 `FLAG IS STOP`，变出来的旗帜仍然阻挡，不能通过胜利判定强行穿入。若存在 `FLAG IS HOVER`，它立即悬停；若目标类型无运动例外，恢复世界默认下落。

`initialSubject` 可以用于作者显示和复盘，但不能作为 PropertyResolver 的查询依据。稳定 ID 中的 `rock`、`robot_01` 只是名字，不随着变形重命名，也不能用它们继续选择旧模型、旧碰撞或旧操控对象。

### 3.7 变形后 YOU 不自动跟随；支持真正改造原身体

只存在 `ROBOT IS YOU` 时，拼出 `ROBOT IS FLAG` 会让原身体不再满足 ROBOT 的 YOU 规则。若没有其他受控对象，进入可撤销的 NoControl；不能偷偷给新旗帜补 YOU，或回退到一个叫 player 的实例。

如果新类别确有 `FLAG IS YOU`，变形后的旗帜会受控；但这条规则作用于全部 FLAG。存在多面旗帜时会触及本版保留的单 YOU 限制，返回 MultipleYOU 并回滚，不能随意只选“刚变出的那一面”。本版允许名词变形，不等于顺带承诺多 YOU 同步移动。

第 12 关用一个不需要多 YOU 的流程展示用户提出的真实变形：

```text
步骤 1：移动 IS，把 ROBOT IS YOU 换成 SPRING IS YOU。
        原机器人失去控制；唯一弹簧成为受控对象。
步骤 2：操控弹簧拼出 ROBOT IS FLAG。
        原机器人实际变为旗帜，按 FLAG IS WIN 成为目标。
步骤 3：操控弹簧进入该旗帜所在格。
        YOU=spring 与 WIN=robot_01 是两个不同实例，合法同格获胜。
```

与之对照，第 9 关仍用 `ROBOT IS WIN` 和换控旗帜，原机器人的身份不变。两关有意区分“同一种东西变了性质”和“它已经成了另一种东西”。

### 3.8 持续生效的句子与已完成的变形分开

本版采用**状态改变型变形**：句子有效时转换匹配实例，移除句子只停止之后的转换，不撤销已经发生的身份变化。

- 想恢复此前局面，使用整步 Undo。
- 想在游戏世界中反向变形，可以另拼 `FLAG IS ROCK`；它同样作用于全部 FLAG，不只作用于曾经是 ROCK 的个体。
- 将句子推开再推回，可以让之后出现的新源实例发生变形；不会无条件复制已有对象。
- `ROCK IS ROCK` 是无操作句，不消耗变形次数，也不产生“免疫变形”的隐藏保护。它与 `ROCK IS FLAG` 并存时不阻止变成 FLAG。

这项默认值会增加不可逆选择，但不取消无限撤销。提示应区分“停止变形规则”和“撤销刚才的变形”，不要宣称拆句即可还原。

### 3.9 同步批次与链式转换：每实例每指令至多一次

为防止 `ROCK IS CLOUD` 与 `CLOUD IS ROCK` 在同一回合无限互变，本版明确采用：

> **每条被接受的世界指令中，每个实例最多发生一次非平凡的身份转换。**

每次进入规则结算点，先从同一份变形前状态捕获所有待变形实例，再统一提交。不能在遍历第一个岩块后就让它继续匹配下一条规则，而其他岩块还没处理。

```text
ROCK IS CLOUD
CLOUD IS FLAG

某个 ROCK 在一次有效指令中变为 CLOUD。
它在同条指令的后续下落、词牌移动或 WIN 检查中，不会再变为 FLAG。
下一条有效指令才可能把它变为 FLAG。
初态本来就是 CLOUD 的另一个实例，则可在第一条指令中变为 FLAG。
```

两向转换会随着有效指令交替，不随动画帧、镜头旋转或真实时间自动变化。失败输入、只按修饰键、不合法的 WAIT 不推进变形。受控弹跳顶点的一次侧移或释放属于新的有效指令，重新给予一次变形机会。

词牌在自动下落中拼出新句子时，未在本条指令变过形的源实例仍应立即响应；不能只在手动推词的那一刻扫描。批次中的控制权、碰撞和 WIN 都在全部身份替换后检查，不检查半批次中间态。

`transformedIdsThisCommand` 属于事务上下文，不存进作者关卡文件；若有子步调试快照，必须一起保存它。完整回合前快照不需要保存上一回合的临时标记，下一指令开始清空。自动结算的循环判重需要包含该集合，不能仅看坐标。

### 3.10 当前支持范围与冲突

| 情况 | 本版处理 |
|---|---|
| `ROBOT IS FLAG` 等任意已登记名词对 | 支持，统一规则，不硬编码几个特例 |
| `ROCK AND CLOUD IS FLAG` | 支持，多个源类别映射到同一个目标 |
| 重复的 `ROCK IS FLAG` | 去重，只变一次，不复制实例 |
| 同时 `ROCK IS CLOUD` 与 `ROCK IS FLAG` | MultipleTransformTargets；明确回滚，不按扫描顺序挑一个 |
| `ROCK IS FLAG AND CLOUD` | 暂不支持一变多；诊断，不复制、不仅执行前半句 |
| `ROCK IS FLAG AND WIN` 或 `ROCK IS WIN AND FLAG` | 暂不支持混合右侧；分别写 `ROCK IS FLAG` 与 `FLAG IS WIN` |
| 文字本体变形／固定 Terrain 变形 | 不支持；Text 与 Terrain 不属于这些名词的实例集合 |
| 两个同格非实体因变形同时实体化 | RuleConflict，整条回滚，不自动挤出、吞并或穿透 |
| 变形后多 YOU，或 YOU 直接 HOVER/FLY | 延续公开范围限制，明确诊断并回滚，不凭模型补另一套输入 |
| 变形后零 YOU | 允许 NoControl 残局，完成当前环境结算后可撤销／重开 |

这些组合限制应在编辑器预览与拒绝提示中可见。不要通过无声忽略句子来伪装兼容，更不要把已经获准的全部名词变形功能一并退回“以后再做”。

### 3.11 WIN 的时机与变形批次

每个原子操作的顺序统一为：

```text
旧状态预检 → 整组位移 → 重读规则 → 同步身份变形
→ 按新身份派生性质 → 校验最终状态 → 检查不同实例同格 WIN
→ 尚未获胜才继续重力、上浮或弹跳的后续原子步骤
```

例如，非实体 ROCK 与机器人已同格，本次合法变化让 ROCK 变为 FLAG，且 FLAG 有 WIN，则可以立即获胜。反过来，如果 ROCK 原有 WIN 但本次变为不带 WIN 的 CLOUD，不能在变形前的瞬间抢先记胜。

同一个实例变为 FLAG 后即使具有 YOU+WIN，也仍不能与自己配对。名词变形不改胜利公式，不重新引入接近、邻接或身份名称等兜底。

### 3.12 加载、撤销与保存

生产 `WorldFactory` 必须在读规则后检查初态：恰有一个 YOU、没有初始胜利、没有待自动位移，且没有会把现有实例立即改变的非平凡变形。固定板可以写变形规则但当前没有源实例；初态就有源实例则要求作者明确重做初态或将句子留到游玩中再拼成，不能在玩家第一步偷偷变形。

配套 Python `Model` 是底层测试模型，局部单测可以构造含待变形的原始状态测试算子；正式十二关由 `main()` 额外检查无待变形。不得把这个测试便利当成生产加载合同。

Undo 恢复每个实例的当前 `subject`、ID、位置、运动阶段、控制权和胜利记录；恢复后只重建派生索引，**不再次执行变形**。否则撤销回 ROCK 后马上又变 FLAG，玩家将无法真正撤销。

作者 JSON 仍保存初始 subject。试玩停止必须丢弃运行中的变形残局，不能把作者的岩块默认保存成旗帜。存续运行快照和回放状态摘要则必须包含当前 subject，否则同位置、不同物种会被错误认为同一搜索状态。

## 4. 如何把“必须互动”变成关卡结构，而不是额外开关

### 4.1 有效互动的最低定义

以下行为计入设计审核：

- 玩家成功推动、顶起或压低至少一个非受控 Object 或可动 Text，坐标真实改变。
- 或由该操作链引起有效规则集合变化，包括名词、IS、属性或 AND 的有效重排。

单独按下 Shift、推失败、走到旁边、登上静止物体、原地看一会、切镜头、只在已有弹台上弹跳，均不计。仅把 `Push` 命令次数加一不够，因为推动模式下走空格也是 Push 输入；原地跳造成真实顶字反而应该计入。

L02—L12 每条通关路径都应需要至少一次这种有效改变。L02 可以只推物、不改字；L09 的关键可以是改 WIN 和推 IS；L08、L12 可以真正改变物种。不要求每条解法触发所有机制。自动变形本身不单独计为主动互动，必须追溯真实手动物体位移或文字规则变化；不把首次移动触发的预置变形当作满足互动要求。

### 4.2 不能把互动写进胜利条件

错误做法：

```text
if (overlapYouWin && hasTouchedAnyBox) Win();
```

正确做法：地图本来就不能仅靠移动通过；推物或改规则让某条路线／某个胜利配对成为可能。运行时仍只判断合法的不同实例同格。

`designContract.requireActiveInteraction` 是**关卡制作与审核元数据**，不是运行时门锁。删掉审核模块后，正常游戏结果不能改变。

### 4.3 无互动子图搜索

配套脚本从实际关卡初态尝试全部十类命令：四向 Move、四向 Push 意图、原地跳、顶点释放。命令后若有真实的非受控体手动位移或规则改变，就把该边排除；其余走、爬、跳、下落、弹跳、空格推动模式行走仍照常模拟。

若此受限状态图存在胜利路径，关卡不满足本条设计要求，报告完整绕过序列。若搜索穷尽仍无胜利，得到**当前有限参考模型内**的无互动不可通关结论。达到状态上限只能记 `INCONCLUSIVE_LIMIT`，不能记通过。

本版 L02—L12 在参考模型中分别穷尽这一子图；这比“把 Shift 禁掉试走一次”更严格，因为它也覆盖普通跳造成的顶字、普通落地造成的压物等路径。

这不是全状态空间的完整求解，也不证明某一块指定词、某一种指定属性是所有解法必需。玩家推文字搭成另一种台阶，只要合法且符合通关公式，可以是可接受的新解法。

## 5. 如何定义至少四关“真正多解”

### 5.1 不计入多解配额的差异

绕障碍左边或右边、额外走几步、独立动作交换次序、同一机制的镜像位置、通关前无意义地推回原位，都不作为第二个解法类别。不能仅通过参考回放字符串不同就声称多解。

### 5.2 本版五个多解关的区别

| 关卡 | 解法 A | 解法 B | 解法 C | 可检查的实质差别 |
|---|---|---|---|---|
| L08 | 推石搭阶，机器人进入原旗标 | ROCK IS FLAG，把近处岩块真正变为旗帜 | — | 最终 WIN 实例不同，B 产生身份转换 |
| L09 | 机器人登台进入旗标 | 先让机器人有 WIN，再换控旗帜进入原机器人 | — | 最终 YOU 与 WIN 实例互换 |
| L10 | 推动弹簧，弹入高处旗标 | 拆掉旗标 HOVER，让目标下落后进入 | — | 移动玩家与移动目标；获胜高度、运动过程不同 |
| L11 | 同一石台通过 BOUNCY 发射 | 把同一规则槽换成 FLY，搭乘上升 | — | 有弹跳事件／有载人上浮事件，双方不可互相冒充 |
| L12 | 推弹簧登高进入原旗标 | ROCK IS FLAG，进入变出来的近处旗帜 | 先换控弹簧，再 ROBOT IS FLAG，进入原身体 | 路线、外部物品变形、原身体变形三类选择 |

每类解法都从同一初态开始，不能先用 A 改地图再宣称残局中的 B 是独立解。L11 的 FLY 解法会先把 BOUNCY 暂时放入规则槽以清出取词空间，但**不发生弹跳**，随后真的替换为 FLY 并搭乘。共同的准备步骤不等于两条解法必须互不相交；最终解决障碍的机制必须不同。

脚本记录机制签名：`youId, winId, winCell, usedBounce, usedLift, transferredControl, usedTransformation`，并为参考解指定必须出现／禁止出现的事件。签名可辅助验收，**不能代替设计判断**：任意改变最终坐标并不自动成为新策略。

### 5.3 教学不把另一条正确路变成“错误答案”

前七关提示较直接；后五关先给观察问题，再根据玩家正在操作的区域给分支提示。不要在 L08 的 WIN 解法成功时弹出“请先推动石头”，也不要要求 L09 必须换控才能算完成。

通关后保持撤销与重开入口，可显示轻量的“另一种可能：你也能改变谁是终点”，但不强制补做。没有按步数或路线给某一种策略判定为标准答案。

## 6. 确定性模拟、数据与编辑器重构

### 6.1 规则解析与事务

```ebnf
Sentence = PropertySentence | TransformSentence ;
SubjectList = Subject, { AND, Subject } ;
PropertySentence = SubjectList, IS, Property, { AND, Property } ;
TransformSentence = SubjectList, IS, Subject ;
Subject  = ROBOT | ROCK | CLOUD | SPRING | FLAG ;
Property = YOU | PUSH | STOP | HOVER | FLY | BOUNCY | WIN ;
```

仅同高度的世界 +X／+Z 连续直线，不读取反向、Y 轴、对角线、拐弯或屏幕投影。AND 保留最长有效前缀；同名词的有效属性按并集，不按“最后一句”覆盖。每次文字的合法位移后全量重建规则，包含推、顶、压、重力和弹跳。规则结果分成属性集合与源名词→目标名词映射；Parser 本身不改变实体。名词变形按 3.9 的每实例每指令至多一次合同执行，右侧多名词或混合属性有公开诊断。

沿用 v0.6 的命令事务：预检副本 → 原子手动变化 → 规则重算／同步名词变形／派生属性／合法性／WIN → 当前受控体本段下降或顶点 → 环境上浮与下落 → 稳定或决策点 → 提交一次撤销快照。新旧控制体必须在规则更新后重新查询。

环境 Up 按 Y 降序、稳定 ID 排序，每轮每体一格；Down 按 Y 升序、稳定 ID 排序，逐格处理下降到接触／模式变化；每个原子变化后读最新规则。不要换成物理引擎或任意字典顺序，还继续使用本包的参考解结论。

规则让原本同格的两个对象同时实体化时，明确 RuleConflict 并整条回滚，不自动挤出、穿透或杀死其中一个。多 YOU 和未支持的受控重力模式同样是明确的回滚诊断。无效输入不推进世界、不增加历史。

快照保留所有对象 ID／当前 subject／位置／存在性、顶点与待恢复下降、终局和胜利配对；恢复时重建属性、占用索引与受控 ID。相机槽与 Shift 按住状态不属于逻辑物理快照。观察和切镜头不推进重力。

### 6.2 程序框架保留，不另造一套引擎

继续使用纯 C# Core、Unity Runtime、Editor、Tests 的边界，规则与整数数据为唯一真相。保留实际工程的 Unity 2022 版本、渲染管线、输入后端与目录约定，不因工作名或新关卡重建项目。

| 模块 | 本轮实际改动 |
|---|---|
| Entity／Occupancy | subject 是可变运行状态；ID 与物种及 YOU 无关；同格集合在变形后重新校验 |
| RuleParser／PropertyResolver | 对右侧名词与属性作类型区分，保留来源；只按当前 subject 派生属性；不复制旧类型的属性 |
| TransformationResolver | 全局源快照、批次替换、每指令已变形 ID 集合、多目标冲突；恢复快照时不重复执行 |
| ControlResolver | 从规则计算 0/1 个受控对象，识别不支持的多 YOU；禁止名字回退 |
| Move／Push／Vertical | 所有运动从当前受控 ID 查询；角色切换后不要继续推动或下落旧引用 |
| WinResolver | 计算实际不同实例配对；不读关卡通关回放、互动次数或提示状态 |
| GameSession | 原子日志、整步撤销、NoControl 恢复、胜利后撤销 |
| Presentation | 属性变化保留身份轮廓；名词变形才换主体模型，保留稳定 ID 的空间连续性；控制光环按新规则查询 |
| LevelDefinition | 12 关、多条 referenceSolutions、独立 designContract |
| ReplayRunner | 同一初态运行 A/B/C；核对每步受控 ID、阶段、胜利对象与机制事件 |
| InteractionAudit | 只在开发／验证工具中运行无互动搜索，报告绕解或穷尽／超限 |

不新增重型 DI、ECS、通用 DSL、网络、热更或资源框架。Core 不引用 UnityEngine／UnityEditor；表现和输入只适配核心，不通过碰撞回调决定解谜。为了教学高亮保留规则来源，不从材质或模型猜属性。

### 6.3 关卡文件合同

JSON 仍是布局唯一持久源。磁盘 LevelDefinition、编辑草稿、试玩 WorldState 三者深拷贝隔离。以 `(id, kind, subject/token, cell, anchored)` 保存实体；Terrain 用**两端包含**的整数长方体列表。

```text
schemaVersion: 8
mechanicsVersion: RW-v0.8
id / title / bounds / terrain / entities / fixedRules / options / camera

designContract:
  requireActiveInteraction: true（L01 为 false）
  minimumSolutionFamilies: 1 / 2 / 3
  interactionIsAuthoringConstraint: true

referenceSolutions[]:
  id / name / family / commands
  mustControlAtWin / mustWinWith（适用时）
  requireEvents / forbidEvents（适用时）
  expectedTrace / expectedWin / status / claim
```

`designContract` 与 `referenceSolutions` 只能帮助作者与测试，不得参与游戏胜利判定。保留 v0.7 的 `referenceSolutions[]` 多回放字段；本版更新 schemaVersion/mechanicsVersion 并新增 transformationMode。旧版本提示显式迁移，不能混用规则语义，也不能把第一条参考解当唯一通关脚本。

本包 options：

```text
actionMode = MoveClimbHoldPush
winMode = DistinctEntitiesSameCell
gravityMode = WorldDownExceptHoverOrFly
collisionMode = SolidPairsTerrainUniversal

controlMode = SingleYouTransfer_NoControlUndo
```

脚本中的 `ActiveInteraction`／`RulesChanged` 记录只用于验证，没有给实体加一个隐藏的“已经互动”物理属性。文本字段中的状态不等于 Unity 通过，参考回放状态统一注明 `ReferenceModelPassed_NotUnityVerified`。

### 6.4 编辑器新增内容

保留 IMGUI 工具界面、按 Y 层的 XZ 画布与三维预览、四相机槽、打开／保存／另存、作者撤销／重做、校验、隔离试玩与停止试玩。试玩永不覆盖作者初始草稿。

| 面板／工具 | 需要支持 |
|---|---|
| 交互预览 | 同一位置分别预览普通“走／爬”和 Shift“推链”；显示头顶净空与拒绝原因 |
| 规则与角色预览 | 显示当前 YOU 的真实 ID、所有 WIN 实例、控制权变更前后、默认实体性来源 |
| 变形预览 | 高亮全部将受影响的 Object；显示 id、源／目标 subject、转换后属性／实体性／重力、YOU 数量与可能 WIN 配对；标出同回合转换限额 |
| 规则冲突预览 | 给多目标变形、混合右侧、多 YOU、受控 HOVER/FLY、非法实体同格明确诊断；显示全部来源句 |
| 解法页签 | A/B/C 回放各自从初态创建新会话，不能复用上一回放残局；可逐步看规则、控制对象与获胜格 |
| 互动审核 | 运行无互动子图检查；发现通关路径就列出可回放命令；超限显示未证实，绝不显示通过 |
| 多解审核 | 显示两条解法的最终 YOU/WIN、目标格、弹跳／上浮／换控／变形事件；标出只是绕路的重复候选 |
| 内容报告 | 总关卡数 12、至少四关多策略、L02—L12 互动审核状态；未通过的关卡标注原因 |

镜头、规则高亮、选择目标不能绑定 `robot_01`。多个空心 WIN 同时存在时都显示可进入轮廓；选择不看模型颜色。拿到 YOU 的旗帜保留旗帜身份、加控制反馈；失去 YOU 的机器人在无 PUSH/STOP 时显示空心轮廓。

### 7.1 数据与回放读法

- 每个长方体 `(x0,y0,z0) → (x1,y1,z1)` **含两端**，长方体叠加取并集。
- 物体坐标是身体占据格，不是脚下支撑格。地板 Y=0 上的物体通常在 Y=1。
- `E/W/N/S = +X/-X/+Z/-Z` 是世界方向；`PE/PW/PN/PS` 是对应方向的推动意图。实际键盘方向由当前镜头槽映射。
- `J` 是原地跳；顶点阶段 E/W/N/S 自动代表唯一一次侧移。`WAIT`／顶点 J 为原位恢复下降。
- 稳定 ID `robot_01` 表示初始机器人，不保证它始终受控或始终是 ROBOT。部分旧词牌 ID 如 w_win 在本版内容中显示 FLAG；以 token 为准，严禁从 ID 猜内容。回放表会显示当前 actorId。
- “固定词”依然在地图中占一格并可登上；只读固定规则板则不占玩法格子。

## L11｜同一块石头，两种上升

**教学意图：**同一个物品可以通过不同运动性质解决同一个高度问题。

**首次观察：**同一石台和同一规则槽旁，既有 BOUNCY 也有 FLY；出口在两种机制都能到达的高度。

**为什么不能只走过去：**未改规则时石台只能提供 Y=2 的站立面，普通跳不够到 Y=5；必须利用一个运动属性。

### 解法 A｜将 BOUNCY 推入句子，在石台上起跳

直接将 BOUNCY 向 +X 推入 ROCK 句，身体恰好登乘石台；原地跳后被弹到 Y=5，向 +Z 进入旗标。

### 解法 B｜不用起跳，改成 FLY 后搭乘上升

先将 BOUNCY 推入规则槽清出取词空间，但不要跳；绕到 FLY 后侧，将它推到待装位置，再回登乘侧推入 FLY，将 BOUNCY 整体推出句子。石台通过持续上浮载玩家到限位下，再走入同一个旗标。

| 1 | 出口只要求到达这个高度，不要求用某一种上升方式。 |

| 3 | 可选择 BOUNCY 后原地跳，或把槽中的词替换成 FLY 后搭乘。 |

## L12｜改路线、造终点、改变原来的自己

**教学意图：**综合比较改路线、把外部物品变成目标、先换控再把原身体变成目标。

**首次观察：**高台旗标、可推动弹簧、近处岩块和两套 FLAG 名词槽同时可见；YOU 可从 ROBOT 行移到 SPRING 行。

**为什么不能只走过去：**各分支都需要真实推物或推字。初态弹簧位置不足以直接到达高空旗标；近处岩块仍为 STOP；也不存在初态控制弹簧的隐藏规则。

### 解法 A｜推弹簧，弹上高台

保持所有句子，把弹簧沿 +X 推两格，松开 Shift 登上它，原地跳起再落下。弹高三格后向 +X 侧移一格，进入原旗标。

### 解法 B｜把附近岩块真正变为旗标

绕到 ROCK 规则台，从南侧把 FLAG 推进 STOP 的位置。近处岩块真实变为 FLAG，失去 ROCK 的 STOP 来源，得到 FLAG 的 WIN。回到它的原位置并进入，原高台旗帜无需触碰。

### 解法 C｜先换控弹簧，再把原机器人变为旗标

先从 (3,1,2) 将 IS 沿 +Z 推到 SPRING IS YOU 行，切换到唯一弹簧；旧机器人停在 (3,1,3)，失去 YOU 但暂时还不是 WIN。操控弹簧走到 (2,1,2)，向 -X 推 FLAG 补成 ROBOT IS FLAG。旧机器人在原位置真正变成旗帜，成为 WIN。弹簧再走入 (3,1,3)，两个不同实例同格获胜。

### 分层引导

| 提示层级 | 文案 |
|---|---|
| 1 | 你可以改路线、改变外部物品，或改变曾经的自己。 |
| 2 | 只拼 ROBOT IS FLAG 可能让你失去控制，先看看有没有别的 YOU 来源。 |
| 3 | 换控弹簧后再推 FLAG，使原机器人变成旗帜，然后操控弹簧进入它。 |

**重点检查：**C 分支必须先换控，不能保留旧版“先 WIN 再换控”的操作序列。不得给变形后的旗帜偷偷保留 YOU。BOUNCY 在弹簧受控后也不让静止或平走触发弹跳。胜利以两个稳定 ID 配对，不按模型名字判断。

## 8. 编辑器与可读性验收补充

### 8.1 相机方向保持固定合同

| 相机槽 | W／上 | D／右 | S／下 | A／左 |
|---|---|---|---|---|
| 0 | +Z | +X | -Z | -X |
| 1 | -X | +Z | +X | -Z |
| 2 | -Z | -X | +Z | +X |
| 3 | +X | -Z | -X | +Z |

实际镜头和地面箭头必须匹配这张表。回放只存世界方向 E/W/N/S，切镜头不改变回放结果。切到被遮挡一侧时，对前景结构作透明或轮廓处理，不要求玩家猜 IS 在哪里。

### 8.2 让“改规则”看起来确实改变了原来的物品

**两种视觉反馈必须区分：**`ROCK IS WIN` 保留岩块身份，只改变目标和实体表现；`ROCK IS FLAG` 则让同一格内的岩块实际变为旗帜外形，同时按 FLAG 规则显示空心或实体。给旗帜 YOU 只加控制反馈，不换成机器人；`ROBOT IS FLAG` 才改变原机器人的主体模型。变形使用原地连续动画或轮廓交接，标出同一稳定 ID，不能让人误以为旧物被删除、另处旗帜被传送过来。

同时显示当前 YOU 与所有 WIN，特别是 L09：机器人刚得到 WIN 时仍然由 YOU 提供实体性，不能显示“现在你已经通关”。提示可写“一个物体不能与自己配对；让另一个 YOU 来到这里”。

规则变化的表现顺序为：词牌完成原子位移 → 相关句子变更 → 指向受影响实例 → 身份变形（有时）与新属性／控制外观变化 → 后续运动 → 胜利。动画不能再次决定规则、支撑、获胜或选择旧的受控对象。

后五关的提示不要先问玩家“选 A 还是 B”。允许观察同一组物品后自行形成意图；提示只是解释操作与规则，不是开启分支的按钮。

### 9.1 已验证和未验证严格分开

上述“无互动不可通关”只针对当前有限 Python 模型、这 12 张有实际底板的灰盒布局以及本文列出的动作合同。没有触及状态上限；若之后地图改大、添加物品或改变规则，必须重新运行，旧结论失效。

未验证内容：Unity／C# 编译、真实 Shift 输入与焦点行为、Unity 动画或镜头遮挡、编辑器保存与资产生命周期、正式构建、不同设备上的操作、真人教学效果、全体互动解法的枚举、最短解与唯一解。

Python 模型不覆盖底部虚空死亡／移除，不能拿它证明生产核心的坠落行为；也不实现多个 YOU 同步操作、直接 YOU+HOVER／FLY 的输入协议、一变多复制或混合右侧语法；本版单目标名词变形已实际加入模型。它不是完整游戏运行时。

本包的 `validation_results.json` 是机器可读证据：含每关数据哈希、每条解法的回放、实际胜利对象、互动事件、控制变化、实际身份转换记录、最终 subject、机制签名，以及无互动搜索状态数。任何布局或语义修改后都应刷新报告，不能手改 status 字段冒充运行成功。

### 9.2 至少补到 Unity 核心的回归用例

除了原有推链、登攀、文字重力、云载人、弹跳与整步撤销，应覆盖：

1. 不同 ID 的 YOU／WIN 同格，才可获胜；一个 YOU+WIN 不自胜。
2. 推一个 IS 原子地撤销旧控制句、建立新控制句；下一输入作用于新 ID。
3. 旧身体失去 YOU 的默认实体性，但显式 STOP/PUSH 不被删除。
4. 推规则后零 YOU 可以撤销；多 YOU 不随机选主角；不支持组合明确回滚。
5. 规则变化使已同格的两个实例构成 YOU／WIN，立即记录胜利。
6. 胜利判定不读取 designContract、互动标记、referenceSolutions 或提示进度。
7. 无互动搜索包含普通跳造成顶字、普通下降造成压物，不能只禁用 P 指令。
8. A/B/C 回放各从同一初态开始；完整撤销与演员 ID 一并恢复。
9. 搜索超限输出未证实，不能作为关卡通过标志。
10. 真正的名词变形保留 ID/位置、按新 subject 重新派生属性，不影响同名 Text。
11. 同步交换、两段链式转换、每指令每实例一次、重复句去重、无自变形锁。
12. 变形失去 YOU、合法的先换控后变形、多 YOU 冲突、同格实体化冲突全部可撤销。
13. 无效输入、旋转相机、快照恢复不触发变形；身份改变后保存／读档及状态哈希正确。
14. 转换导致同格 WIN 时及时获胜，不在批次中间抢先获胜；恢复撤销不能马上重新变形。

详细的 80 项已执行有限检查名与结果见报告；C# 移植后必须重新执行，不能把 Python 成功写成 Unity 测试成功。
