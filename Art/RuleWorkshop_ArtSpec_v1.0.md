## 1. 目标与现状

### 1.1 本轮目标

在保留当前关卡布局、模型和交互表现的基础上，建立统一的暖砂配色，让环境、物件和词牌容易区分，使文字保持清晰，并用稳定的主体颜色帮助辨认物件身份。

优先顺序：文字与关卡信息可辨认 → 物件身份容易区分 → 整体配色协调。主体颜色帮助识别物件，不负责单独解释所有规则和物理状态；颜色不足以解决的造型、遮挡或反馈问题单独记录。

本规范替代 VA-v1.0 的完整表现层改造要求。造型、动画、相机、HUD 重构和新功能标记不作为本轮配色优化的前置条件。不要求制作独立样板场景、全面替换几何、扩展规则接口或改造整套编辑器。

### 1.2 当前配色基线

以下依据当前运行时 `WorldView` 的材质映射、配置材质及运行场景核对，不是实际截图的测色结果。

| 内容 | 当前用色／映射 | 本轮要改善的问题 |
|---|---|---|
| 背景与固定地形 | 偏深蓝背景、灰色地形 | 统一为暖砂环境，保持顶面、侧面和边界可辨 |
| ROBOT | 红色材质 | 降低刺激度，保留独立身份色 |
| ROCK / CLOUD | 共用蓝色材质 | 区分岩块与云 |
| FLAG / SPRING | 共用粉色材质 | 区分旗帜与弹簧 |
| WALL / 固定地形 | 共用地形材质 | 区分规则物件墙与固定地形 |
| 词牌 | 统一浅黄主体、黑色正文；另有历史 anchored 材质分支 | 按真实词汇类别区分，保持所有词牌正文清晰 |
| 编辑器独立预览 | 自有环境、物件及选择色 | 记录差异，后续再统一，不用编辑器截图代替游戏验收 |

有效词库中的名词为 ROBOT、ROCK、CLOUD、SPRING、FLAG、WALL；属性为 YOU、PUSH、STOP、HOVER、FLY、WIN、BOUNCY；连接词为 IS、AND。`JUMP` 不是当前属性词。历史 anchored 材质分支不构成新增固定词牌的授权。

### 1.3 当前工程与行为边界

权威顺序为：用户最新明确要求 → [当前玩法合同](../docs/PROTOTYPE_SPEC.md)及其最新修订 → 本文配色约定。当前实施情况见 [实施状态](../docs/IMPLEMENTATION_STATUS.md)。实际实装前重新核对仓库，不能用本节快照覆盖更新的用户决定。

- 玩家与作者试玩固定第 1 视角；编辑态可以旋转。不能把玩家旋转镜头作为配色可读性的补救方案。
- 物件不随 STOP / PUSH / YOU 或实体性变化而透明、缩小或切换虚体材质；名词变形仍更新当前身份及其颜色。
- 保留现有以 YOU 为中心的玩家前方圆形遮挡剖切、固定玻璃表现及相应碰撞。固定玻璃的透明不表示可以穿越。
- 保留 BOUNCY 顶点时停的外围压暗、轻微 RGB 色散、延迟文字与方向箭头；它们属于已有功能反馈，不能因统一配色而删除。
- 所有显式规则继续来自真实空间词牌；配色不改变读句方向、规则、控制权、实体性、重力、同格胜利条件、撤销或阶段切换。
- 本次仅修改本文，不新增代码接口、配置资产或关卡字段。后续实装优先复用已有配置和材质，不升级 Unity、不迁移渲染管线、不改关卡布局。

## 2. 色板与对象映射

所有 HEX 均为 **sRGB 输入色值**。以下名称是文档映射约定，不是强制新增类、接口或配置资产的清单。颜色分为环境、物件身份、词牌类别和已有功能提示四组。

### 2.1 暖砂环境 `warm_atrium`

| 名称 | HEX | 使用范围 |
|---|---|---|
| `Env.Background` | `#F3EFE6` | 游戏相机背景与场景外留白 |
| `Env.Ground` | `#E7D8C5` | 主要地面、固定基座 |
| `Env.Structure` | `#BFB3D6` | 已有固定建筑与外围结构；不用于 WALL 规则物件 |
| `Env.StructureShade` | `#958BAA` | 已有结构暗面或凹槽的可选配色 |
| `Env.Accent` | `#D7A6AF` | 仅供已有非交互装饰少量使用 |

本轮只有这一套主题，不按关卡或阶段随机换色。环境保持低饱和度，尽量让词牌正文与交互物件从背景中分离。结构暗面色不是全局阴影颜色，也不要求新建阴影着色器。不存在装饰、独立暗面或结构材质槽时，不为用齐色板新增模型或拆分几何。

固定玻璃保留现有材质与透明行为，不强行套用不透明地形色。若它与暖砂环境不协调，记录实景问题后再单独调色，不通过改变透明度或遮挡逻辑解决。

### 2.2 稳定的物件身份色

| 名称 | 物件 | 初始 HEX | 方向 |
|---|---|---|---|
| `Object.ROBOT` | ROBOT | `#BA7463` | 陶土红 |
| `Object.ROCK` | ROCK | `#7B8998` | 蓝灰 |
| `Object.CLOUD` | CLOUD | `#B7D2D8` | 浅雾蓝 |
| `Object.SPRING` | SPRING | `#9E8DB7` | 灰紫 |
| `Object.FLAG` | FLAG | `#C28FA2` | 柔和玫瑰 |
| `Object.WALL` | WALL | `#9D9486` | 暖灰褐 |

颜色跟随实际当前名词身份，不根据实体 ID、初始身份或当前控制者猜测。拆 STOP、添加 PUSH、取得或失去 YOU 时，主体身份色保持不变；ROCK 变为 FLAG 后使用 FLAG 色，撤销后恢复 ROCK 色。

这些颜色不表示“能推动”“能穿过”“有 WIN”或“已经获胜”。旗帜即使没有 WIN 也保留旗帜身份色，机器人失去 YOU 后也保留机器人身份色。同一种物件在不同关卡与阶段使用同一映射。

六种颜色是实装起点，不宣称已在灯光、遮挡、色觉差异或低分辨率下全部可辨。尤其检查浅云与地面、弹簧与淡紫结构、旗帜与已有粉色装饰的邻接关系；不能只比较色板上的孤立色块。

### 2.3 词牌类别与正文

| 名称 | HEX | 对应词汇／用途 |
|---|---|---|
| `Ink` | `#293246` | 全部词牌正文，已有必要轮廓或图标 |
| `Word.Noun` | 复用对应 `Object.*` 身份色 | ROBOT、ROCK、CLOUD、SPRING、FLAG、WALL；色值见 2.2 |
| `Word.Operator` | `#F6EEDD` | IS、AND |
| `Word.Property` | `#ECC66B` | YOU、PUSH、STOP、HOVER、FLY、WIN、BOUNCY |
| `Word.Unknown` | `#D4D7DD` | 未映射词的调试回退，不表示它是有效词汇 |

`Word.Operator` 取代旧文档的 `Word.Copula` 名称，以完整涵盖 IS 与 AND；只是文档约定更新，不要求迁移现有 API。类别底色应用于现有词块可读区域或现有主体，不强制新建标签面板或类别图标。

名词词牌与同名物件共用身份材质：写着 ROCK 的词牌与 ROCK 物件均使用蓝灰，其他五种名词同理。并行新增的 LAVA 词牌也复用其物件材质（包括熔岩材质回退），沿用该功能的实际配色。物件变形后采用新身份色，词牌仍按自身文字对应身份着色。YOU 与 WIN 词牌都使用属性金黄，不因字面特殊而改成控制蓝或目标金。`ROBOT IS FLAG` 使用 ROBOT 陶土红—连接词米白—FLAG 柔和玫瑰色序，不按句中位置猜类别。

成句与未成句词牌均保留正常正文、类别色和对比度；拆规则不变灰、不标红、不隐藏。沿用现有文本内容、位置与字号，不为适配配色缩字、换行或缩略词汇。

### 2.4 已有功能提示的颜色

| 名称 | HEX | 仅用于已有对应表现 |
|---|---|---|
| `Func.YOU` | `#237A95` | 已有控制提示 |
| `Func.WIN` | `#A36D18` | 已有目标属性提示，不代表完成状态 |
| `Func.Focus` | `#46658C` | 已有检视或选择提示 |
| `Func.Warning` | `#B7534B` | 已有真实动作拒绝或冲突提示，不评价解题方向 |

功能色不覆盖整块物件身份色，也不代替词牌类别色。仅有配置字段不代表已有可见标记；实装时核对实际呈现入口，缺少标记则记录为后续能力，不为用齐功能色新增圆环、图标、规则连线或提示系统。

本节不要求统一 HUD 或编辑器界面。顶点箭头的可用／受阻状态、文字与色散效果沿用现状，只检查改色后的场景是否使它们难以辨认。颜色不能成为判断控制、胜利或阻挡的唯一证据。

## 3. 应用规则

### 3.1 先改颜色，保留当前呈现结构

后续配色实装以游戏场景为对象，先记录原画面，再应用环境色、拆分混用的物件身份色及词牌类别色。复用现有材质与配置路径；同一旧材质目前承担多个身份时，映射需要能分别赋色，但不强制建立新的配置框架。

不改模型尺寸、网格、字体技术、相机取景或输入，不新建动画，不扩大到灯光和后处理重做。不用隐藏、透明化或移动物件掩盖颜色辨认问题。材质色改动需保留现有剖切与玻璃着色行为，不用通用替换材质使这些能力失效。

沿用工程当前色彩空间和渲染管线，避免重复色彩转换。运行配置应是后续实装的单一颜色来源；下方种子只是文档参考，不另建一套覆盖 Inspector 的运行时配置。

### 3.2 文字对比度与实际画面分开验收

以 sRGB 分量除以 255 得到 c；c ≤ 0.04045 时线性分量为 c / 12.92，否则为 ((c + 0.055) / 1.055)^2.4。相对亮度 L = 0.2126R + 0.7152G + 0.0722B；对比度为 (较亮 L + 0.05) / (较暗 L + 0.05)。

| 正文／底色 | 输入色值对比度 | 内部目标 |
|---|---|---|
| Ink / Word.Noun.ROBOT | 3.52:1 | 低于 4.5:1，待阅读优化 |
| Ink / Word.Noun.ROCK | 3.58:1 | 低于 4.5:1，待阅读优化 |
| Ink / Word.Noun.CLOUD | 8.07:1 | ≥ 4.5:1，通过 |
| Ink / Word.Noun.SPRING | 4.24:1 | 低于 4.5:1，待阅读优化 |
| Ink / Word.Noun.FLAG | 4.73:1 | ≥ 4.5:1，通过 |
| Ink / Word.Noun.WALL | 4.28:1 | 低于 4.5:1，待阅读优化 |
| Ink / Word.Operator | 11.10:1 | ≥ 4.5:1，通过 |
| Ink / Word.Property | 7.84:1 | ≥ 4.5:1，通过 |

2026-09-27 修订：名词改为物件身份色后，部分深墨正文组合未达 4.5:1；本次优先满足身份同色，不擅自改变物件色或文字方案，记录为后续阅读优化项。

以上已按输入色值核算，**不等于渲染后截图测量或玩家阅读验收通过**。灯光、阴影、材质、后处理和实际字高仍可能影响阅读。4.5:1 是本项目内部目标，不是无障碍合规认证。

本版不另定字高阈值，不以旧版 14 px / 20 px 替换玩法文档中的阅读目标。字号、缩放或遮挡导致的阅读问题如实记录，留待对应专项决定；不能因色值通过而声称整关可读。

## 4. 关卡验收与交付

### 4.1 使用真实关卡

本次核对时，运行目录 `Assets/_RulePyramid/Content/Levels/catalog.json` 与 `Assets/_RulePyramid/Config/LevelCatalog.asset` 已接入以下两组阶段：

| 运行关卡 | 当前地图文件（位于 Content/LevelDrafts） | 验收身份 |
|---|---|---|
| L01 | L1P1.json、L1P2.json、L1P3.json | 已接入运行的三阶段地图 |
| L02 | L2P1.json、L2P2.json、L2P3.json | 已接入运行的三阶段地图 |

目录名 LevelDrafts 不代表这些地图仍仅是草稿。配色实装前再次核对实际运行目录，并在证据中写明地图文件、阶段及“运行地图／未接入草稿／历史关卡”。接入运行不等于已经完成设计盲测或美术验收。

优先检查这六张地图。其他未接入地图可补充 CLOUD、WALL、AND、长词或特殊规则案例，但须标明身份，不把它们称为当前正式运行关卡；不为了配色验收改目录、加关卡或制作独立样板。
