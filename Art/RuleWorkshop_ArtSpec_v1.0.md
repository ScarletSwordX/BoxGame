# Rule Workshop｜规则工坊美术与视觉反馈规范

> **版本：VA-v1.0 · 日期：2026-09-27**  
> **定位：低饱和几何箱庭 + 功能性色彩的规则积木。**  
> 适用：现有 Unity 2022 推箱子／规则词块原型；旧文档中项目也称 Rule Pyramid。  
> 用途：交给 Codex 实际改造表现层、生成配置与资产、接入既有关卡编辑器并进行验收。  
> 本文件是新的美术实施规范，不是已经完成或通过 Unity 验证的工程。

## 0. 给 Codex 的执行边界

### 0.1 本次任务

把现有可玩原型从程序白盒改造成统一的纯色几何风格。**先保证文字、格子、属性和动作结果清楚，再改善构图与氛围。**不要只换几个材质，也不要借美术改造重写整个游戏。

执行前读取 `AGENTS.md`、README、当前有效玩法规格、`ProjectSettings/ProjectVersion.txt`、`Packages/manifest.json` 和现有代码。确认渲染管线、文本组件、输入后端、坐标换算、相机槽、规则解析结果、撤销流程、Prefab 与编辑器入口。

优先级：**用户最新明确要求 > 当前有效玩法合同 > 本文件的表现规范 > 旧原型文档。**旧文档只用于理解已有架构，不能把已经更新的玩法恢复成旧版本。

### 0.2 不可改变的玩法边界

- 所有显式世界规则来自实际存在、可观察的空间词块，包括最初教学关；不得新增 `fixedRules`、隐藏控制句，或用只读规则板替代物理词块。全局隐式默认行为由现有玩法合同决定，不由本文件扩展。
- 词块不能因为当前未成句而隐藏、不可读或不再参与原有交互。名词、`IS` 和属性词均必须能被独立辨认。
- 保留名词到名词的变形，例如 `ROBOT IS FLAG`；美术表现不能把这种句子错误地画成非法规则。
- 胜利是**两个不同实体分别具有 YOU / WIN 并占据同一逻辑格**。不允许把自己同时有 YOU / WIN 画成已经获胜，也不允许用邻接、动画碰撞或目标吸附补通关。
- 保留现有 12 关目标、第二关起有意义交互、至少 4 关真正多解等设计约束。本次不重排关卡、不改坐标、不加“必须推动过词块”的隐藏门槛。
- 维持模拟核心与 Unity 表现分离。配色、灯光、相机观察、动画、主题切换不得成为规则判定或解题条件。

### 0.3 范围与未知项的处理

现有工程版本与管线优先；**不升级 Unity，不自动迁移到 URP，不为美术新增付费插件或大型框架。**具体类名、脚本路径、实体词汇尚未通过本次任务读取仓库核实，本文对应名称均是职责建议，而非声称工程已有这些类型。

已有组件能承担职责就扩展它，不要为了逐项匹配文件名建立空类。例举的 `PUSH / STOP / HOVER / FLY / JUMP` 只在当前词汇表确实存在时接入；**视觉映射表不是新增玩法的授权。**不存在的词不生成正式资产，也不补规则逻辑。

本轮按桌面横屏验证，基准分辨率为 1920×1080 与 1280×720；这是验收条件，不是确定发行平台或最低硬件。

## 1. 艺术方向与取舍

### 1.1 一句话定义

**像一座温暖、安静的积木建筑；其中的规则词块像清晰、可操作的信息卡片。**

从 Monument Valley 的参考方向提取简洁几何、空间层次与受控色域；从 Mini Metro 的参考方向提取抽象、克制的信息表达。本项目不复刻两款游戏的地图、模型、角色或官方配色。[R1][R2]

### 1.2 三条视觉原则

1. **环境退后，词牌清晰，当前控制对象容易定位。**最高优先级是可读性，而不是让整个画面都鲜艳。
2. **颜色管类别，形状和文字管精确含义。**玩家不应仅凭“这个东西是黄色”判断它是否能通关。
3. **外观忠于当前规则，不忠于物体的刻板身份。**ROBOT 不一定受控，FLAG 不一定有 WIN，WIN 不等于可穿过。

### 1.3 必须避免

写实贴图、随机噪声、金属反射、大面积霓虹、全场粗黑描边、持续闪烁、过强泛光、景深、运动模糊、随意换色的功能标识。不要用装饰裂纹伪装危险、用假台阶伪装可行走路径，或让纯装饰物看起来像可推词块。

### 1.4 画面面积的建议比例

环境底色约 70%，空间结构与物体约 20%，功能强调约 10%。**这是构图检查的起点，不是需要代码精确统计的硬规则。**词块密集的谜题可以超过 10%；不能为了比例降低信息可读性。

## 2. 色彩体系：主题层与语义层彻底分开

所有 HEX 均为本项目新制定的 **sRGB 输入色值**，不是参考游戏的官方色板。禁止把色值散落在各个脚本中。集中保存在少量配置资产里，由表现层读取。

### 2.1 默认环境主题：暖砂庭院 `warm_atrium`

| Token | HEX | 使用范围 |
|---|---|---|
| `Env.Background` | `#F3EFE6` | 相机纯色背景、场景之外的留白 |
| `Env.Ground` | `#E7D8C5` | 固定基座、主要地面 |
| `Env.Structure` | `#BFB3D6` | 主要建筑、外围结构的低饱和淡紫 |
| `Env.StructureShade` | `#958BAA` | 需要手工区分的侧面、结构凹槽；不得作为第二层全局压暗 |
| `Env.Accent` | `#D7A6AF` | 少量非交互建筑点缀；不能装饰成机关 |

第一版只把这套主题做完整。背景使用纯色，不制作天空盒或复杂渐变背景。可行走地面应保留稳定的格子边界与顶面。

`StructureShade` 是可选的结构配色 Token，**不是 Unity 内置“阴影颜色”参数**。P0 优先用统一灯光与环境补光建立明暗，不要求自定义阴影着色器。

### 2.2 固定语义色：跨关卡、跨主题不变

| Token | HEX | 含义与限制 |
|---|---|---|
| `Ink` | `#293246` | 词牌正文、图标、必要轮廓；不用纯黑 |
| `Word.Noun` | `#79BCB3` | 名词词牌面板，青绿 |
| `Word.Copula` | `#F6EEDD` | `IS` 词牌面板，暖米白 |
| `Word.Property` | `#ECC66B` | 属性词牌面板，低刺激金黄 |
| `Word.Unknown` | `#D4D7DD` | 未映射类别的调试回退，不能伪装成有效新词 |
| `Func.YOU` | `#237A95` | 当前受控实体的双环／控制符号 |
| `Func.WIN` | `#A36D18` | 当前有 WIN 的实体的金色菱形／目标边界 |
| `Func.Focus` | `#46658C` | 检视或编辑选择框，不代表可控制 |
| `Func.Warning` | `#B7534B` | 已有系统报告的非法动作／冲突提示，不代表“解题方向错误” |
| `UI.Panel` | `#FBF7F0` | 必要的 HUD 背板、词牌放大检视背板 |
| `UI.SecondaryText` | `#596075` | 次要 UI 文本；不用于降低未激活词牌的可读性 |

**全体属性词的词牌底色相同。**`YOU` 词牌仍使用 `Word.Property`，不会整块改成蓝色；`WIN` 词牌也不会拥有一套独立卡片风格。功能色主要用于世界实体的当前属性标记，词牌本身以实际字面与类别为准。

P0 不给每个属性单独发明一种颜色。除 YOU / WIN 外，优先用深墨色的不同符号区分其他属性，以免出现“彩虹积木”。

### 2.3 后续可用环境主题：仅预留，不并行制作

| 主题 ID | 背景 | 地面 | 结构 | 结构暗面 | 点缀 |
|---|---|---|---|---|---|
| `mist_gallery` 雾蓝回廊 | `#EDF1F0` | `#D7E1DF` | `#AABBCD` | `#7E91A6` | `#D8B9AB` |
| `rose_court` 玫瑰庭院 | `#F3EBE7` | `#E5CECA` | `#C3B4D2` | `#93869E` | `#B6C6B8` |

换主题只能更改 `Env.*`，不能重定义词牌类别色、YOU / WIN 标识或已有颜色实体身份。暂不制作黑金夜景，避免同一版本同时维护浅色与深色两套可读性规则。

主题由表现配置指定，不自动根据当前生效规则或答案变色。若关卡复用、扩展同一片箱庭，优先保持旧区域外观连续，不把同一位置随机重新着色。

### 2.4 对比度与色彩管理

词牌正文统一用 `Ink`。按标准 sRGB 相对亮度公式计算，当前输入色板的文字对比度约为：名词 **5.89:1**，IS **11.10:1**，属性 **7.84:1**，UI 背板 **12.00:1**。

上述是**色值计算结果，不是渲染后截图测量**。本项目把常规文字至少 4.5:1 作为内部验收参考；借用 WCAG 的文字对比度与“不仅依靠颜色”原则，不因此宣称游戏已获得无障碍合规认证。[R3][R4]

执行要求：

- 词牌面板与正文尽量采用不受光照压暗的显示方式；正文不可用白字配浅黄或浅青底。
- 功能环和小图标必须有形状区别，必要时增加米白衬底与 `Ink` 细边。某个功能色在一种地面上清楚，不代表在所有结构颜色上都清楚。
- 检查工程当前 Linear / Gamma 设置，沿用既有设置；不要为本轮美术未经验证地更改项目级色彩空间。sRGB 与线性转换只在正确的输入／渲染边界发生，禁止材质颜色重复调用 `.linear` 或反向转换。[R5]
- 后处理、抗锯齿和灯光都可能改变实际阅读效果。必须在 Game View 与构建后的真实分辨率下检查，不能仅看 Inspector 色块。

## 3. 几何、格子与材质

### 3.1 统一尺度

用 `c` 表示现有逻辑中的一格边长。**不修改实际网格步长。**下列尺寸均相对于 `c`；局部原点示意采用格子中心，实际工程通过已有 `GridToWorld`／视觉偏移适配，不硬改 Core 坐标。

| 对象 | 建议视觉尺寸 | 备注 |
|---|---|---|
| 固定地面／基座 | X/Z 为 `0.99c`，高度沿用原网格 | 细缝用于识别格子，不是可通行缝隙 |
| 普通整格实体块 | `0.94c × 0.94c × 0.94c` | 与邻格有清楚分界 |
| 词块外壳 | `0.94c × 0.94c × 0.94c` | 不因单词长度改变物理占格 |
| 倒角 | `0.02c–0.03c` | 一段简洁倒角即可，不做圆润玩具球 |
| 词牌可读面板 | 宽约 `0.84c`，高约 `0.36c` | 实际受最长词与屏幕字号约束 |
| 玩家替代造型 | 宽约 `0.55c`，高约 `0.80c` | 仅在已有角色需要替换时使用；保留占格语义 |
| 目标空心框 | 外轮廓不超过 `0.88c` | 留出能看见进入对象的中部空间 |

将变形、轻微挤压等美术动画放在 `VisualRoot` 子节点上。逻辑根、选取代理、网格坐标与已有碰撞配置不能跟随“弹性动画”改变。

### 3.2 建模语言

使用方柱、平台、简洁拱形轮廓、少量切角等几何形体。P0 只需要共享的倒角立方体、简单实体外形、词牌面板、状态符号和空心框；不要为每个词单独建模。

所有可行走顶面维持水平与稳定边界。装饰不能跨入可交互网格、不能挡字，也不能看起来提供实际不存在的支撑。不要因为想让建筑更好看而移动现有关卡的墙、词块或实体。

### 3.3 材质语言

主体采用不透明、纯色、低光泽材质。P0 起始值为 Metallic = 0，Smoothness 约 0.1；材质实际参数名称以当前管线为准。无漫反射纹理、无随机污渍、无噪声法线。

“纯色”指材质没有复杂纹理，不等于每个面都必须同样亮。保留柔和明暗，用于识别高度与接触关系。局部图标、字形、必要的阴影遮罩不算写实纹理。

## 4. 词牌：类别不变，状态另画

### 4.1 统一结构

一个词块由以下视觉职责组成，允许合并 Mesh，不要求每项单独一个 GameObject：

```text
WordRoot                  绑定真实 EntityId / TokenId 与逻辑格
└─ VisualRoot             播放表现动画，不参与规则计算
   ├─ Body                米白／中性色倒角积木外壳
   ├─ LabelAnchor         固定绑定本词块的空间位置
   │  └─ Label            类别色面板 + 深墨色文字 + 小类别符号
   ├─ MembershipMark      当前是否参与活动规则的独立标记
   └─ FocusBracket        仅检视／编辑选择时显示
```

身体是“占据空间的积木”，标签是“可读的词”。不得用只有屏幕 UI、没有世界词块的标签替代它。

### 4.2 类别编码

| 类别 | 面板 | 冗余识别 | 例子 |
|---|---|---|---|
| 名词 | 青绿 | 左上小方形标记 | ROBOT、FLAG，或工程已有其他名词 |
| 系词 | 米白 | 左上短横标记，始终保留清楚边框 | IS |
| 属性 | 金黄 | 左上小菱形标记 | YOU、WIN，或工程已有其他属性 |

类别符号位置固定，不能替代正文。字体使用工程已有的清晰无衬线字体与文本组件；有 TextMeshPro 时优先复用现有字体资产。英文规则词使用大写、较粗字重、不换行、不缩略。正文优先于角标，空间不足时先去掉非必要角标。

`ROBOT IS FLAG` 的面板序列是 **青绿—米白—青绿**，不是“右边必须金黄”。类别以词汇定义为准，不按句中的位置猜测。

### 4.3 空间标签与四视角

默认方案是**绑定词块顶部锚点的单张小标签，标签朝向相机，词块实体不随相机转动**。标签不能自由漂移；以短支点或紧贴顶部的方式让归属明确。标签的尺寸与位置可以为避免穿插调节，但不得移动到另一格或重排词序。

普通状态下按真实空间遮挡，不使用全场 `ZTest Always` 穿透文字。高层物体遮住低层标签时，允许通过已有相机旋转或局部检视解决；不能让多个不同高度的单词在屏幕上冒充一条真实规则。

规则读取方向属于世界坐标与解析器。旋转镜头只改变观察，不按屏幕“从左到右”重新解释句子。需要查看来源时，使用锚定真实词块位置的短方向箭头／连线，而不是重新排列的字幕句子。

### 4.4 最小可读尺寸

在 1280×720 下，默认构图的词牌大写字母可见高度目标至少 **14 px**；1920×1080 下目标至少 **20 px**。这是实际屏幕像素，不是 TMP Inspector 的 `fontSize` 数字。

按关卡中最长的实际词验证。禁止无下限缩字以塞入面板；先增大相机视野内的物体尺度、优化 UI 占位或使用现有缩放功能。原型尚无检视功能且仍不达标时，可补一个**只放大当前选中真实词块**的检视显示，并明确锚点／选中框；它不能成为唯一能看到规则的地方。

本轮不做字体下载系统、多语言重构或大规模文本技术迁移。

## 5. 规则状态：不靠整块变色表达

### 5.1 状态表现

| 模拟器提供的状态 | 视觉表现 | 禁止做法 |
|---|---|---|
| 不属于当前活动规则 | 正常类别色、正常正文；无实线成员标记 | 变灰到难读、隐藏、加错误红叉 |
| 属于至少一条当前活动规则 | 类别色不变；标签底部出现 `Ink` 实线成员标记 | 全部改成“正确绿色” |
| 刚形成／刚拆散规则 | 成员标记一次淡入／淡出 | 给整个场景闪白、长期呼吸发光 |
| 解析器实际报告冲突／拒绝 | 对相关对象附加小 `!` 与简短原因 | 表现层自行推断规则冲突 |
| 正在检视某条规则来源 | 高亮该规则实际使用的词块；短线显示世界读取方向 | 展示解法、把未组成的潜在规则当作生效 |

这里的“活动规则”定义为解析／规则解析结果报告的当前规则；**没有匹配实体不等于句子无效**。例如场景里已经没有 ROBOT，仍存在的 `ROBOT IS FLAG` 不能仅因此被美术层取消成员标记。

### 5.2 多规则共享词与更新顺序

一个词可能属于多条规则。成员标记取“参与活动规则数量 > 0”；拆掉其中一条但仍参与另一条时，不能熄灭全部状态。检视来源时按具体规则显示，默认不画满屏连线。

由现有解析结果提供成员 EntityId、规则身份与当前有效属性。表现层不扫描 TMP 文本重新解析，也不根据颜色、场景对象名字或字符串排列推测玩法。

若当前接口缺少来源信息，增加最小只读适配输出，不能建立第二套规则引擎。仅有句子汇总文本而没有来源 ID 时，不编造精确成员高亮；在实施记录中报告这一接入缺口。

规则变化、实体变形、YOU / WIN 标记要对应同一份已提交状态或同一段有序表现事件。**静止可交互帧不能出现“文字已经拆开但旧属性还亮着”的状态。**若动画仍在表现旧位置，应沿用现有输入锁／事件队列，在结算点同步，不改变模拟事务顺序。

### 5.3 不给谜题贴“正确／错误”标签

拆规则是正常玩法，不是失败。无有效控制对象时，按模拟器提供的状态显示现有恢复提示，保留撤销／重开；不能自动重建 YOU 句子，也不能把最后一个受控外观保留下来伪装可操作。

## 6. 世界实体：身份、属性、交互分三层

### 6.1 身份层

基础轮廓或小图案用于表达“这是什么”，不表达“它现在有什么属性”。已有美术能满足辨认就沿用；需要占位造型时采用简洁几何。

例如 ROBOT 可用双眼头部轮廓，FLAG 用旗形，WALL 用砖缝符号；**只有工程实际包含相应对象时才制作**。不因为画了旗子就默认它是目标，也不因为画了机器人就默认它受玩家控制。

普通实体以低饱和中性色、环境结构色为主。不要用饱和青绿实体与青绿名词面板做唯一对应，优先用同一对象图案联系词与物。

若现有规则直接把 RED / BLUE 当身份，必须保留可辨认的红／蓝色，并附 `R / B` 或不同图案；不可随主题交换。可使用低饱和红 `#CB7E80`、蓝 `#7E9FBF`，但先确认这不会与当前游戏语义冲突。

### 6.2 当前属性层

| 属性／状态 | 标识 | 说明 |
|---|---|---|
| YOU | `Func.YOU` 双圆环／双弧控制标，必要时加小 `YOU` 标签 | 标在当前实际受控实体上，不绑定某个固定 Prefab |
| WIN | `Func.WIN` 菱形标与目标边界，保留实体身份图案 | 表示该实体当前有 WIN，不表示已经完成 |
| PUSH（若存在） | 深墨色短推向箭头 | 表示当前属性，不承诺这一步空间上一定推得动 |
| STOP／现有等效阻挡属性 | 深墨色阻挡横杠与实体表面 | 按实际阻挡查询显示，不能只看对象类型 |
| HOVER（若存在） | 一对水平短线 | 不使用上下漂浮动画伪装逻辑运动 |
| FLY（若存在） | 向上箭头 | 真实高度变化仍由模拟器驱动 |
| JUMP／弹跳面（若存在） | 简洁弹簧／上弹符号，置于实际作用面 | 不暗示所有角色都获得自由跳跃 |
| 检视／编辑选择 | `Func.Focus` 四角括号 | 与 YOU 的圆环不同，不混用 |

YOU / WIN 可同时展示。其他多个属性使用固定位置的小符号；空间不足时保留 YOU / WIN，并在选中检视中列出其余真实属性。不要让多个整块色覆盖彼此。

### 6.3 可进入与不可进入

“目标”与“阻挡”是不同维度。对当前可以同格进入的目标，采用开放边界或空心框，并让中心空出来；不要使用封闭实心立方体让玩家误以为只能碰外壳。

若某实体有 WIN 但当前仍阻挡进入，应同时显示实体阻挡外观与 WIN 标记。**不得为了符合空心目标美术而暗中移除 STOP、修改 Collider 或让 WIN 自动取消阻挡。**无 WIN 但可进入的对象也不能显示已激活的目标标志。

以现有模拟器针对实际操作的阻挡／支撑结果为准。不建立“所有非 STOP 对象都没有支撑”的新推论，不把视觉空心结构当作新的物理规则。

### 6.4 变形与控制转移

`ROBOT IS FLAG` 生效时，表现层读取转换后的实体类型／替换映射，更新身份外形，再从实际属性结果刷新 YOU / WIN 等标记。不得把旧机器人身上的控制圈无条件留给新旗子，也不得假设新旗子自动有 WIN。

P0 用一次短促缩放／淡化切换表现身份改变，逻辑位置不变。源目标多个实体、一对多或多对一等行为一律服从已有逻辑，不在表现层补齐。撤销必须恢复变形前身份、属性与标识。

## 7. 场景、相机与遮挡

### 7.1 构图基线

沿用项目的正交四视角方案；现有相机已稳定时不为美术另造控制器。尚未配置的视觉起点为俯角约 **35.264°**、四个 yaw **45° / 135° / 225° / 315°**。这些是项目构图参数，不是参考作品内部参数。[S1]

相机焦点围绕关卡有效包围盒，取景需覆盖实际玩法区及所有规则来源词块，而非只追着角色。通过现有 `GridToWorld` 和相机 API 验证实际方向，不能凭角度数字直接更改既有输入映射。

目标是玩法主体占可用区域约 65%–80%，其余保留呼吸空间；以词牌可读性优先。较大关卡不靠无限缩小词牌硬塞进屏幕，使用已有观察／缩放能力，并保持全局定位。

切换视角不能推进回合、重算规则或触发重力。若已有相机动画期间的输入约束，原样保留。

### 7.2 格子与高度

通过平台边缘、顶面与侧面明暗、细缝表达格子。默认不覆盖高对比棋盘线。不同高度必须能看出支撑关系；悬空对象不能画出一块不存在的支撑底座。

需要落点／支撑提示时只显示当前真实状态，不显示预测最优解。不要在所有格子上画可达箭头；这会把美术任务扩大为新的路径提示系统。

### 7.3 遮挡处理的优先顺序

先处理标签锚点、视角与不必要装饰；再使用已有遮挡辅助。只有实际玩法对象仍无法定位时，才接入局部淡出或检视轮廓。

P0 不制作全屏透视描边。可先给被遮挡的当前受控实体一个小型定位符号；该符号只表示位置，不冒充可见实体轮廓，也不能泄露无来源信息。

非交互装饰可以淡出。对参与玩法的地形／实体使用淡出时，必须保留格子边界或清晰轮廓，并维持原有选取与阻挡；不能让障碍“看起来已经消失”。相关实现无法可靠落地时作为 P1，记录仍存在的遮挡场景。

不可达但提供规则的词块必须仍是实际词块，并在可用观察方式下能辨认；不能藏到墙后，靠 HUD 汇总替代它。

## 8. 灯光、阴影与后处理

### 8.1 P0 起始设置

以下是**需要在工程里调校的起点，不是跨管线保证一致的配方**。

| 项目 | 起点 |
|---|---|
| 主光 | 一个固定世界方向的 Directional Light |
| 主光方向 | 可从 Euler `(50, -30, 0)` 起步，以现有场景轴验证 |
| 主光颜色 | 近白、轻暖；避免明显黄色光覆盖青绿词牌 |
| 主光强度 | 约 0.9 起步，按工程现有曝光／色彩空间调整 |
| 阴影 | 轻柔，强度约 0.25–0.35 起步；不能淹没文字与台阶 |
| 环境补光 | 轻微灰紫，保证背光面仍可辨；不设成黑色环境 |
| 背景 | `Env.Background` 纯色 |
| 文字与标签 | 不投射阴影；优先使用不受场景光照压暗的显示 |
| 后处理 | P0 默认不新增效果；保留已有必要效果时说明其影响 |

世界光方向在四个镜头槽之间保持一致，不为每个槽临时转太阳。若背面太暗，调整补光与阴影，不把功能色随镜头替换。

灯光应在基准场景集中配置；不要给每个词块挂点光源。避免烘焙出移动词块离开后仍残留的固定物体阴影。

### 8.2 管线适配

**已有 URP：**沿用锁定包版本和当前 Renderer，主体优先使用兼容的 Lit / Simple Lit，标签使用适合现有文本系统的材质。先把无 AO 的基础画面做好，再考虑小半径、低强度 SSAO。

URP 的 SSAO 是 **Renderer Feature，不是 Global Volume 中的 AO Override**。其深度／法线来源与 Shader Pass 必须匹配；自定义 Shader 若缺少对应支持，不能以“勾选了 SSAO”当作效果已正确。引用文档为 URP 14，工程版本不同时检查对应版本而非直接复制参数。[R6]

**已有 Built-in：**保留 Built-in，使用已有 Standard／Unlit／文本材质，先靠软阴影、材质明暗和简单的接触提示实现风格。不为了 AO 引入整套新管线。

**其他现有管线：**保留原配置，做最小适配；没有验证过的效果明确标注。不要让渲染管线名称成为编译时硬依赖，除非项目已稳定引用对应程序集。

### 8.3 AO 与接触提示的限度

AO 的目的只是让积木的接触与层叠更清楚，不是把边角涂黑。P1 可从较小半径、较低强度起步，并记录开启前后的画面与性能。场景已有明显接触阴影时不要再叠加一圈同样强的假阴影。

使用简化接触阴影时，必须依据真实支撑面确定位置；不允许永远在物体脚下画一块贴地黑斑，让悬空物看起来已经落地。

### 8.4 后处理禁区

P0 不新增 Bloom、景深、运动模糊、色差、胶片颗粒或暗角；不靠 LUT 挽救错误色板。当前项目已有 Tonemapping 时记录设置并检查颜色，不把 ACES 当作必然更好看的默认答案。Unity 提供不同 Tonemapping 模式；选择属于本项目调校，而非本风格必须使用某一模式。[R7]

所有新增灯光／Volume／Renderer 调整应限制在目标游戏或验证场景。修改共享 Renderer Asset 前检查其他场景引用，必要时复制专用配置；不得破坏用户其他场景。

## 9. 动画与即时反馈

### 9.1 基本原则

动画表现已发生的逻辑变化，不通过动画位置、触发器或播放结束事件补做规则判定。优先复用既有移动／事件播放系统；有玩法意义的跳跃阶段、输入窗口与事务顺序原样保留。

| 事件 | P0 视觉反馈 | 建议时长／幅度 |
|---|---|---|
| 一格移动／推动 | 平滑移到模拟器给出的格位；被推物与玩家反馈协调 | 原系统允许时约 0.10–0.16 秒 |
| 动作被拒绝 | 受控实体的 VisualRoot 小幅抵住后回正；必要时显示原因 | 位移不超过 `0.025c`，约 0.08 秒 |
| 规则形成 | 相关词块成员线一次出现 | 约 0.12 秒，不持续闪烁 |
| 规则拆散 | 只撤掉已不再成立的成员标记 | 约 0.12 秒，词牌正文不变暗 |
| 名词变形 | 身份造型短促收缩后换形；更新实际属性标识 | 约 0.16–0.22 秒 |
| 落地 | 轻微压缩并回正；不抖动相机 | VisualRoot 缩放变化不超过 3% |
| 真正获胜 | 发生胜利的格位短暂强调，随后显示完成 UI | 约 0.35 秒，不强制自动下一关 |
| Undo / Restart | 取消旧动画，重建对应状态与标记 | P0 可立即同步；不保留过期特效 |

以上仅是表现起点。已有正确且更简洁的动画可以保留，不为了凑时长改变动作节奏。禁止通过“变形动画暂时变成另一实体”影响碰撞或规则。

### 9.2 安静的静止画面

静止状态没有持续跳动、转圈和整块闪烁。HOVER 不做上下摆动来假装悬停，WIN 不做强呼吸灯，词牌不因空闲自动漂浮。

提供一个表现配置开关 `ReducedMotion`：开启后去除非必要挤压、抖动与装饰性过渡，状态本身立即或短淡入显示；保留理解移动所需的最小反馈。不得改变逻辑速度、输入窗口或回合数。

## 10. HUD 与关卡编辑器

### 10.1 游戏 HUD

沿用现有 UI 技术，先统一排版与颜色，不为本轮任务迁移整套 UI 框架。

- 左上角：关卡编号／名称；其他信息按需显示。
- 边缘操作区：已有的旋转、撤销、重开等操作；不能遮住场景规则来源。
- 临时提示：只显示实际交互原因或用户主动请求的信息，出现后不挤动整个布局。

面板使用 `UI.Panel`，正文 `Ink`，次要文案 `UI.SecondaryText`。主要按钮可使用 `Func.Focus` 配浅色文字，不把 YOU 蓝或 WIN 金用作任意按钮装饰。

1080p 下常规 UI 文本起点约 22 px，720p 下至少约 16 px；实际字体与缩放以清楚为准。按钮有边框／形状反馈，不能只靠颜色表示选中。编辑选中、悬停、可控制是三个不同状态。

不新增长期占据画面的只读规则板。允许检视时放大某个真实词块、显示该实体已有属性来源；必须保留明确空间关联，不能把 HUD 数据当作规则来源。

### 10.2 既有关卡编辑器接入

保留现有 `IMGUI EditorWindow + SceneView`、图层绘制、保存／读取、试玩与撤销架构。表现配置不能写进纯逻辑模拟状态。[S1]

最小接入内容：

1. 实体／词牌笔刷预览复用游戏中的类别色与图案，不另做一套含义相反的编辑器配色。
2. 当前 Y 层／已存在的层选择工具保持清楚；编辑选择用四角括号，不用 YOU 控制圈。
3. 在已有设置区域提供主题资产、视觉尺寸与字体的引用／预览入口。
4. 试玩与正式游戏复用同一词牌、实体与属性表现，不允许编辑器里看起来有效、游戏里标记失真。

编辑模式中的规则状态必须注明来自当前草稿解析预览，还是试玩中的运行状态。不要把编辑草稿自动结算为新关卡，更不要为取得美术预览偷偷推进模拟。

主题默认存在单独表现配置中。P0 可用“关卡 ID → 主题 ID”的侧车配置，不修改旧关卡 JSON 的 gameplay schema；项目已有表现元数据机制则直接沿用。文件保存后不得破坏旧关卡读取与回放。

## 11. 实现结构与数据合同

### 11.1 配置职责

少量 ScriptableObject 足够；以下是建议职责，不是强制拆类清单。

| 职责 | 建议名称 | 保存什么 | 不保存什么 |
|---|---|---|---|
| 固定语义色、字体、符号 | `VisualStyleConfig` | 功能 Token、文本样式、符号引用、尺寸与动画参数 | 当前回合、规则事实、运行实体列表 |
| 环境主题 | `EnvironmentTheme` | `Env.*`、相关共享材质、灯光预设引用 | YOU / WIN 定义、实体碰撞 |
| 逻辑到视觉的映射 | 复用现有 Presenter／最小适配器 | 对象类型、词类别、规则成员、有效属性的读取映射 | 第二套解析器或胜利计算 |
| 标签朝向 | 复用相机相关组件 | 当前视角下的显示旋转 | 世界坐标与规则读取方向 |
| 编辑器生成／检查入口 | 复用现有工具菜单 | 创建共享资产、生成样板场景、检查缺失引用 | 不可撤销地覆写用户资产 |

主题切换与视觉样式数据不进入游戏状态哈希、动作回放、存档胜负或规则求解输入。不要给 Core 引入 UnityEngine、Material、Color 或 TMP 类型。

### 11.2 表现层至少需要读到的信息

```text
一个可对应到同一结算版本的状态／事件来源
实体：稳定身份或明确替换映射、类型、逻辑格、真实有效属性
词块：实体身份、实际 Token、词汇类别
规则：当前规则身份、真实参与词块 ID、解析器已知状态
交互：当前受控对象、已有动作拒绝／完成／变形等事件
观察：现有相机槽与可用检视对象，不写回模拟
```

这些是信息需求，不规定现有代码必须改成上述 DTO。已有查询、快照或事件列表能满足时直接复用。只缺一项来源信息，就补那一项最小只读输出；不要顺带重构核心。

### 11.3 资源与性能

P0 采用少量共享材质、共享 Mesh 和共享字体资产。**禁止在每帧或每次换关时无控制地创建材质、字体、图标和临时 Mesh。**状态优先通过小标记的显隐、共享材质引用与既有动画系统表达。

不要把 `renderer.material` 当作随处可调用的颜色接口，也不要把 `MaterialPropertyBlock` 当作无条件更高效的方案。在 Unity 2022.3 的 SRP Batcher 条件下，使用 MPB 的对象不兼容该批处理路径；实际取舍需用 Frame Debugger／Profiler 验证。[R8]

P0 不引入自定义全屏描边、每对象独立灯、复杂 GPU Instancing 系统或通用美术框架。不要为了“合批”改动确定性的对象身份、更新顺序或可选取范围。

运行要求：静止时不反复刷新全文本、不重新解析规则、不产生来自美术层的持续每帧 GC。只有状态、主题、镜头或显示设置变化时更新对应内容；必要的朝向／移动动画除外。

性能目标是在记录清楚的开发机与 1080p 场景中争取 60 FPS；这不是硬件承诺。对比改造前后的 CPU/GPU 帧时间、GC、材质实例与 Draw Calls；未测量不能报告“性能优化完成”。

### 11.4 文件组织建议

按当前工程的既有结构安放，不强制移动旧目录。无既有约定时可采用：

```text
docs/
  ART_SPEC.md                       本规范
  ART_IMPLEMENTATION_STATUS.md      阶段记录与真实验证结果
  ArtReview/                        对比截图与测量记录
Assets/<现有项目根>/Art/
  Config/                           VisualStyleConfig / EnvironmentTheme
  Materials/                        共享环境、词牌、功能标记材质
  Meshes/                           共享几何
  Prefabs/                          词块与实体视觉组件
  Fonts/                            仅引用项目已有／已确认可用的字体
Assets/<现有项目根>/Scenes/
  ArtValidation.unity               独立样板，不占用正式关卡编号
```

不要伪造现有目录名。生成器应可重复运行：更新受本工具管理的资产、复用稳定引用、正确清理临时资源；不删除手工制作资产或重建仓库。

## 12. P0 最小资产清单与样板场景

### 12.1 必交付资产

| 资产 | 数量／范围 | 完成标准 |
|---|---|---|
| 默认环境主题 | 1 套 | 统一背景、地面、结构和少量点缀 |
| 固定语义色配置 | 1 份 | 所有词牌与实体状态共用，不硬编码分散色值 |
| 可复用几何 | 小集合 | 倒角块、标签面板、空心框、必要符号 |
| 词块视觉 | 一个通用结构或现有结构扩展 | 名词／IS／属性，所有现有词可读 |
| 世界实体视觉 | 现有对象范围 | 身份可辨，属性标识动态更新 |
| YOU / WIN / Focus 标记 | 各一种清楚且不同的形状 | 可同时显示，灰度下可分辨 |
| 最小事件反馈 | 移动、拒绝、规则成员变化、变形、胜利、撤销恢复 | 不产生新的规则与判定 |
| 编辑器预览接入 | 复用现有工具 | 与运行时共用映射 |
| 样板场景与报告 | 各 1 份 | 可复现，记录实际通过／失败／未验证 |

### 12.2 `ArtValidation` 样板内容

样板不算第 13 个正式关卡，不进入关卡选择列表，也不能成为隐藏玩法测试替身。复用真实规则与实体创建路径；样板布局只需覆盖以下观察对象：

- 普通地面、较高台阶、整格实体与可进入的空心目标。
- 名词、IS、属性词各至少一块；已有词表中的最长词。
- 一条真实成立的规则，以及一组真实未成句的词块。
- 当前 YOU 与 WIN 的真实属性标识。
- 已有词汇允许时的一条真实名词变形，并能撤销恢复。

纯粹展示全部色板／符号的测试架可以独立存在，但必须注明“视觉样本，非可玩规则状态”，不能用其截图冒充规则绑定已通过。

样板需在四个相机槽检查。正式关卡中仍要验证规则拆分、交叉共享词、变形、阻挡与撤销；样板好看不代表关卡可读。

## 13. Codex 开发顺序与完成定义

### 阶段 A：工程检查与视觉基线

检查并记录版本、管线、现有模块与词表。保存未美化的代表性关卡截图和可运行的已有测试结果。确定需要修改的最小文件集合，不立即大规模替换 Prefab。

**完成定义：**能说明当前工程实际情况；旧玩法是否通过有记录；没有擅自升级依赖。

### 阶段 B：先完成一张可读的静态样板

创建语义色／默认主题，替换基础几何与词牌显示，调好统一灯光和取景。此阶段先不叠加粒子与 AO。

**完成定义：**四槽画面中词牌可读，类别一致，实体与地形能分辨；有实际 Game View 截图，而不只是生成了 C#。

### 阶段 C：接入真实规则状态与事件

接入规则成员、YOU / WIN、实际阻挡外观、变形和撤销。沿用模拟器输出，不重写解析与通关流程。

**完成定义：**形成／拆散规则、名词变形、控制转移、同格获胜与撤销对应的视觉和逻辑一致；不靠固定示例动画伪装。

### 阶段 D：推广到正式关卡与编辑器

将同一配置推广到现有关卡和编辑器，检查不同高度、最长词、遮挡、共享词及不同视角。保留原关卡数量、布局、可达性和多解要求。

**完成定义：**第 14 节 P0 验收已逐项记录，相关现有回放／测试通过，未通过与未验证项如实列出。

### P1：P0 稳定后才做

轻量 SSAO、细化接触提示、局部遮挡淡出、更多环境主题、缩略图以及额外动画润色。它们不能成为 P0 可读性的前置条件。

### 本轮明确不做

新机制、新词法、关卡重设计、全新相机系统、大规模 UI 重写、写实资产制作、复杂 Shader 框架、运行时美术编辑器、联网、角色骨骼动画与完整音频设计。

## 14. 验收清单

### 14.1 视觉与可读性

- [ ] 默认主题统一；没有未经配置的随机高饱和环境颜色。
- [ ] 名词／IS／属性在每关使用相同类别规则；变形句显示为名词—IS—名词。
- [ ] 当前生效与未生效词牌都能读；拆规则不被表现成“犯错”。
- [ ] 720p 与 1080p 的最长词不截断、不换行、不压到规定目标以下。
- [ ] 四槽旋转后标签不反字、不镜像、不漂到邻格；规则箭头仍绑定世界方向。
- [ ] YOU 圆环、WIN 菱形、Focus 四角框在灰度截图中仍能区别。
- [ ] 功能标记在地面、结构顶面与较暗区域都能看清；必要时有中性衬底／细边。
- [ ] 目标的可进入／阻挡状态没有被美术误导；空心目标中心能看见进入对象。
- [ ] 没有装饰性假通路、假支撑，或掩盖关键词的装饰。
- [ ] UI 未挡住实际规则来源；不可达词块仍可观察。

### 14.2 玩法与状态回归

- [ ] 改造前后的同一世界指令回放产生相同逻辑结果；有状态哈希时进行对比。
- [ ] 相机旋转、主题切换、ReducedMotion 不改变回合、规则、重力与胜负。
- [ ] `ROBOT IS FLAG` 等已有变形使用真实结果；Undo 恢复原外观及属性。
- [ ] 一个词仍参与其他规则时，拆掉其中一条不会错误熄灭成员标记。
- [ ] 无匹配实体的成立句不会被表现层自行判为无效。
- [ ] YOU 被移除／转移时标识同步，无“看起来可控制但实际不受控”的静止帧。
- [ ] 邻接 WIN、碰到外壳、单个实体自带 YOU+WIN 均不触发假完成演出。
- [ ] 有 WIN 但仍阻挡的实体没有因换外观变得可穿过。
- [ ] 快速连续 Undo、Restart、换关不会留下旧规则线、状态圈、目标光或旧实体。
- [ ] 无新增隐藏规则、固定控制句、通关门槛，也无关卡坐标与解法修改。

若某个测试情形在当前有效玩法合同下本就不支持，记录“不适用”及原因，不为了通过美术验收补做该机制。

### 14.3 工程与性能

- [ ] 当前编辑器编译无新增错误；运行场景无 Missing Shader／粉材质／缺字。
- [ ] Core 没有新增 Unity／美术类型依赖；现有关卡数据仍能读取与保存。
- [ ] 现有 EditMode／PlayMode 测试按可用条件运行，结果有日志。
- [ ] 记录开发机、分辨率、管线和图形设置，保存美化前后性能数据。
- [ ] 静止画面无美术层持续每帧 GC；无每帧创建材质或重新设置全文本。
- [ ] 反复换关与重开后，材质／临时对象数量不持续增长；生成器可重复运行。
- [ ] 编辑器预览与运行时词牌映射一致，试玩不会污染源关卡。
- [ ] 构建验证有明确结果；无法构建时写“未验证”，不写“应该没问题”。

### 14.4 证据与交付报告

`ART_IMPLEMENTATION_STATUS.md` 至少记录：实际修改文件、生成资产、管线与版本、实际执行的测试及结果、截图路径、性能记录、剩余问题和回退办法。

至少提供：改造前后同机位对比；样板四槽截图；720p 最长词截图；灰度辨识截图；真实规则形成／拆散的前后状态；变形与 Undo 的前后状态。高风险正式关卡另附截图。

**“配置文件已写出”“Unity 编译通过”“规则绑定通过”“Game View 阅读通过”“构建通过”是不同结论，必须分开记录。**缺少 Unity 运行环境时，可以完成代码与资产生成逻辑，但必须明确哪些场景、材质与交互尚未实际验证。
