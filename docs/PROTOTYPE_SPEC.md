## 术语与词牌分类（2026-09-27）

| 标准名称 | 含义 | 示例 |
|---|---|---|
| 物体 | 地图中实际存在的一个对象实例，具有类型、位置与当前属性 | 地图中的一台机器人、一块岩石 |
| 物体类型 | 物体所属的种类，由规则中的名词指代；代码沿用 subject 字段 | ROBOT、ROCK、LAVA |
| 词牌 | 地图中承载一个规则词语的可移动文字块；与物体实例分开 | 写着 ROBOT 或 DEFEAT 的文字块 |
| 名词词牌 | 指代一类物体，不等于该类物体本身 | ROBOT、ROCK、CLOUD、SPRING、FLAG、WALL、LAVA |
| 属性词牌 | 在有效规则中赋予物体行为或性质，不是物体类型 | YOU、PUSH、STOP、HOVER、FLY、WIN、BOUNCY、HOT、MELT、DEFEAT |
| 运算符词牌 | 组织名词与属性的规则关系 | IS、AND |
| 规则表达式（简称规则或句子） | 按合法方向连续排列的词牌组成的完整表达式；有效时参与全局规则计算 | LAVA IS DEFEAT、ROBOT IS YOU、ROCK IS FLAG |

- DEFEAT 单独称为“属性”或“属性词牌”；LAVA IS DEFEAT 是“属性规则”，表示 LAVA 类型的物体具有 DEFEAT 属性。不把单个 DEFEAT 称为完整声明或物体。
- ROBOT 名词词牌与 ROBOT 物体是两种不同实体：前者参与组句，后者接受规则赋予的属性。同理，放置 DEFEAT 词牌本身不会产生危险，必须组成有效规则。
- 规则表达式可以是“名词 IS 属性”，也可以是“名词 IS 名词”的变形规则；AND 连接多个名词或属性时，仍遵循现有解析合同。这里统一术语，不增加新语法。
- 编辑器物体笔刷与物体详情只选择物体类型；词牌笔刷、词牌详情及句子编辑统一使用独立的“词牌类别”和“内容”下拉栏：类别选择名词、属性或运算符；内容列表只包含所选类别的词语，不能从名词内容列表选到属性或运算符。需要跨类别替换时先切换类别，内容默认选择该类第一项。显示分类不写入 token，JSON 仍保存 ROBOT、DEFEAT 等原始词语。

## 0. L03 新增机制合同与实现边界

### 0.1 LAVA、HOT 与 MELT

- LAVA 是 Object 物种，对应可操作的 LAVA 名词牌；其危险性质由 LAVA IS HOT 等世界句子提供，不因模型是岩浆而隐藏赋 HOT。
- HOT 的对象所在格被另一个具有 MELT 的对象进入时，销毁 MELT 进入者。MELT 不会自行销毁，HOT 不会无条件消灭所有物件；被销毁的对象可以是 YOU，也可以是其它具有 MELT 的对象。
- HOT/MELT 是相互作用的一对属性，不解释成自动给所有 YOU 添加 MELT，也不解释成对象拥有其中一个就自动获得另一个。
- 销毁应纳入当前命令事务及撤销记录；不能只隐藏模型仍保留碰撞或受控 ID。

### 0.2 顶部反弹优先于进入岩浆

用户已明确：BOUNCY 只包含从上方落到顶面的接触。必须先判断这一接触，再决定是否进入危险格；不先进入 HOT 格并销毁，再把对象抬回上方。

| 场景 | 新合同结果 |
|---|---|
| MELT 对象侧面进入只有 HOT 的岩浆 | 销毁进入者 |
| MELT 对象从上方落入只有 HOT 的岩浆 | 没有反弹保护，实际进入后销毁 |
| MELT 对象从上方落到 HOT + BOUNCY 的岩浆顶面 | 有效顶面接触优先反弹；此次不结算 HOT 销毁 |
| MELT 对象侧面进入 HOT + BOUNCY 岩浆 | 侧面不触发 BOUNCY；进入后仍受 HOT 销毁 |
| 不具 MELT 的对象进入 HOT 格 | HOT/MELT 配对条件不成立，不因这对属性销毁 |

“BOUNCY 覆盖 HOT”指有效顶部反弹接触的结算优先级，不删除 HOT 规则或给来者永久免疫；之后其它实际进入仍重新判断 HOT/MELT。普通站立或侧面接触不能伪造成一次下落。

沿用既有向上三格、顶棚逐格阻挡与顶点方向选择，用户未改变这些参数。为落实 LAVA IS HOT 与 LAVA IS BOUNCY 的预期用途，顶面接触必须在进入岩浆格前被识别；不能直接沿用旧“无 STOP 则跳过顶面接触”而让角色穿入销毁。BOUNCY 顶面接触与水平实体阻挡如何分离，需实现时显式建模；不偷偷增加 LAVA IS STOP，把本应能进入的危险格变成永远进不去的墙。

### 0.3 多个 YOU 与存活判定

- 允许同类或不同物种的多个实例同时 YOU；ROBOT AND ROCK IS YOU 可以使两类已有对象同时受控。不能继续将多个 YOU 作为 MultipleYOU 错误回滚。
- 有一个或多个存活的有效 YOU，控制仍可继续；部分对象被消灭不等于整关失控。无存活 YOU，或规则变化使全部对象失去 YOU，才进入 NoControl。
- 保留全局“没有可控制的对象了，按 Z 撤销。”提示；撤销应恢复被销毁对象、规则、位置及整条命令状态。
- 按最新胜利合同，任一存活 YOU 自身具有 WIN 或与 WIN 实例合法同格即可获胜，HOT 与 WIN 同格按第 0.4 节先销毁再判断胜利。
- 用户已确认多对象方向输入：被墙或其它合法阻挡挡住的 YOU 原地停下，其它可以行动的 YOU 继续移动；不能因为一个对象受阻而回滚所有对象。此合同已接入核心移动事务。
- 同格争用、共用推链、混合运动与表现关注采用第 0.4 节的确定性策略，不依赖实体列表顺序。

### 0.4 本轮实现采用的确定性结算约定

以下为落实新合同的实现选择，不标记成额外用户确认：

- 本命令开始时取得全部 YOU 及其顶点状态；同一方向输入按前排到后排预检，位置相同时用稳定 ID 排序。被挡对象停下，其它对象继续；一条推链中的对象在同一人工阶段至多被平移一次。所有人工位移统一提交后再重算句子，新获得 YOU 的对象从下一条命令起接受输入。
- HOT/MELT 在实际位移进入后、获胜判断前结算；先销毁进入者，再由存活 YOU 判断 WIN。只有规则变化而没有进入动作，不会自动融化原地对象；HOT 对象走入静止 MELT 对象，也不倒置为静止者主动进入。
- 真实下降到非实体 BOUNCY 物件的顶面同样可以反弹；这不改变其水平实体性。向上三格仍逐格检查阻挡和其它实际入格的 HOT/MELT。
- 地面 YOU 与顶点 YOU 可以同时收到方向输入，分别按地面移动/推链和顶点侧移处理；有顶点时空格沿用 WAIT 释放下降，地面对象不因此跳跃。顶点对象侧移受阻时保留原顶点状态，其它 YOU 可继续移动；没有任何对象能完成方向动作时沿用拒绝输入。
- 表现关注对象优先选顶点 YOU，否则选稳定 ID；关注对象只用于镜头剖切及提示，不决定谁接受输入。不同区域的多个 YOU 都可以触发区域提示。
- YOU 与 HOVER/FLY 的直接控制组合仍不在当前支持范围；多个 YOU 并不自动放开这一限制。schemaVersion 仍为 9，旧 SingleYouTransfer_NoControlUndo 作为兼容名称接受，新草稿可使用 MultiYouIndependentBlocking_NoControlUndo，二者均执行最新多 YOU 规则。

### 0.6 DEFEAT 入格销毁（2026-09-27）

- 新增属性词牌 DEFEAT，通过真实世界句子（例如 LAVA IS DEFEAT）赋予物体；不隐含 STOP、HOT 或其它属性。
- 具有 YOU 的对象实际进入另一个具有 DEFEAT 的对象所在格时，销毁 YOU 进入者，无需 MELT。相邻、站在上方、被 STOP 阻挡或把 PUSH 危险源推到下一格均不算入格；非 YOU 对象不会因 DEFEAT 销毁。
- 按入格后完成规则解析和变形的属性判断，销毁先于 WIN。仅规则变化或危险源进入静止 YOU 所在格不算该 YOU 主动入格；离开后再次进入则重新判断。
- 水平移动、跳跃、下落及其它实际入格位移都结算。BOUNCY 顶面反弹没有进入危险源所在格，不触发 DEFEAT；侧面实际进入仍触发。
- DEFEAT 与 HOT/MELT 同批判断；同一对象同时满足两者只销毁一次，记录 Defeated。销毁清除对象及其运动状态，纳入整条命令撤销与重开；多 YOU 中剩余对象继续受控，最后一个销毁后进入 NoControl。
- schemaVersion 保持 9；编辑器词牌笔刷、词表校验、规则显示与运行时模型移除支持 DEFEAT，不因此改动现有关卡布局。

## 1. 本轮不能退让的约定

### 1.1 所有显式规则必须来自世界里的文字块

`ROBOT IS YOU`、`FLAG IS WIN`、`ROCK IS PUSH`、`CLOUD IS HOVER` 等句子都必须由同一世界网格中的独立 Text 组成。名词、IS、AND、属性，各是一块。语句来自这些块当前的 token 和位置，不来自关卡编号、预设属性、关卡说明、HUD 或只读配置。

**删除 `fixedRules` 字段及运行时读取路径。**也不允许改名为 `baseRules / ruleOverrides / precomputedRules / activeRules` 绕过。v0.9 遇到旧版数据应报告需要迁移，不静默载入另一关，也不偷偷补一个默认 ROBOT IS YOU。

世界默认重力、YOU 的默认实体性、文字的默认实体与可推性、固定 Terrain 的碰撞、输入协议和获胜判定，仍是已经约定的基础机制，不需要为了这些元规则新增句子。不得借此给某个物种默认 HOVER、BOUNCY、WIN 或 YOU。

**世界外观本身没有天生属性：**SPRING 模型不自动弹、CLOUD 模型不自动浮、FLAG 模型不自动胜利。活跃规则缺失时，外形可以保留，但必须正确表现当前性质。

### 1.2 看得到不等于现在推得到

部分句子可以在地形隔开的区域，供玩家看清原因但暂时无法接近。它们仍需独立占格、存在于 `entities`、由同一 Parser 解析；拆改这些词时，规则必须真的变化。

本包进一步统一：**所有 Text 的 `anchored=false`。**主操作区的名词、IS、属性都可推，不普遍锁成只能替换末尾词的槽。不能因为 ID 以 `src_` 开头、放在某个区或属于教学基础句，就在 MovePlanner 中拒绝推动。

灰盒使用有实际碰撞格的透明固定隔墙，把部分完整句子和操作区隔开；所有词下方都有真实支撑。透明只改变 Terrain 的表现，不改变碰撞。未来美术可重做地形布置，但改动后要重新测试可达性，不能只移模型不改逻辑。

### 1.3 第一、第二关也不豁免

L01 开场就看得到 ROBOT、IS、YOU 三块，操作区另有 FLAG、IS 和可推入的 WIN。L02 开场就看得到控制和胜利句子，必须在操作区把 PUSH 写入 ROCK 的句子，再搬岩块搭阶。**第一关不是无词牌的移动房间；第二关不是只有石头和规则 HUD。**

十二关都至少有一块在参考解中被实际操作的世界文字；所有十二关都要求通过地图结构保证至少一次有效改造。后五关依旧保留“只搬物品、不改字”的合法分支，这并不豁免世界规则必须可见。

不新增“已碰过规则块才开门”的门槛；互动是关卡设计约束，不是通关条件。

### 1.4 范围与版本边界

总数仍为 12 关；L08—L12 共 5 关多策略，18 条参考解。第一关起需要有效互动，没有额外第 13 关。部分关卡可能有更多合法解，不能为了保住参考解而用关卡脚本封死。

本轮不恢复自由定向跳、拉箱、两格身体或边缘支撑，不取消 ROBOT IS FLAG；不扩大 v0.8 的单 YOU、单目标变形边界。

## 2. 保留的世界与动作合同

### 2.1 世界与物品

世界使用 `(x,y,z)` 三维整数格，Y 向上；每个实例占一格。Terrain 是固定结构；Object 的名词为 `ROBOT / ROCK / CLOUD / SPRING / FLAG`；Text 是词牌。写着 ROCK 的词牌不是 ROCK 实例，不响应 `ROCK IS FLY`。

所有 Object 与 Text 默认下落，包括空心目标和可动文字。没有新的 FALL 词。HOVER 表示保持当前高度，FLY 表示向上运动，优先级为 `FLY > HOVER > 默认 Down`。所有显式规则仅由空间词牌产生；全部词牌可动，不能使用 anchored 提供隐藏免重力或不可操作性。固定 Terrain 是地形，不是规则列表。

本轮 12 关都有实际的底板，不借助不可见边界地板完成解法。生产核心继续区分横向／顶部边界和底部虚空；Python 参考模型只覆盖有实际底板的布局，不验证坠入虚空的死亡／移除。

### 2.2 属性与实体性

| 属性 | 定义 |
|---|---|
| YOU | 接收当前玩家输入，隐含实体性；不是永远绑定 ROBOT，也不隐含 PUSH |
| PUSH | 可手动推动的实体，可承托；不能通过方向移动自动登上，不免重力 |
| STOP | 阻挡直接穿入的实体，可承托；不能通过方向移动自动登上，不是冻结，不否定 PUSH 或 FLY |
| HOVER | 不主动升降，失去支撑也保留高度；不自动实体化 |
| FLY | 自动逐格上升直到被阻挡；需要实体表面才能承运玩家 |
| BOUNCY | 实际下落到其实体顶面的对象，从接触格向上弹三格；不自带 STOP |
| WIN | 与另一个具有 YOU 的对象同格时胜利；不覆盖碰撞规则 |

```text
Object.EffectiveSolid = 有 YOU 或 PUSH 或 STOP
Object.CanManualDisplace = 有 PUSH 且当前不是 YOU
Text.EffectiveSolid = true
Text.CanManualDisplace = true  // v0.9 的 Text 一律 anchored=false；位移仍须通过推链与碰撞预检
```

`PUSH + STOP` 仍可推；没有 PUSH / STOP / YOU 的普通物品是非实体。BLOCK 已从词库删除，内部仍有统一的 EffectiveSolid，不在各物品脚本里各写一份。

两个动态对象只有在**双方都实体化**时才互相排斥、承托；至少一方非实体时允许同格，方向对称。Terrain 阻挡并承托所有动态对象，包括空心目标。支撑只看正下方，没有边缘、角点或同层互托。

WIN 不隐含非实体：`ROCK IS WIN AND PUSH` 仍不能被直接进入。L08、L12 的变形解法会移走原句中的 PUSH 或 STOP、拼出 ROCK IS FLAG；新身份只受 FLAG 规则影响。L09 的纯属性路径仍是赋 WIN 后转移 YOU。

### 2.3 输入与意图

| 阶段／输入 | 行为 |
|---|---|
| 普通方向 | 前格可进入则平走；有可推体则预检并推动整条连续推链；不可推或推链堵塞则失败，不翻越 |
| Space | 原地跳一格；没有水平分量，不缓存成定向跳 |
| 弹跳顶点的新方向输入 | 侧移一格，再恢复下降；不推、不爬、不补跳 |
| 弹跳顶点 Space | 原位恢复下降 |
| Q/E | 切换四个斜俯视角槽；不推进模拟 |
| Z/R | 撤销整个上一条命令／重开 |

游戏输入不再读取 Shift；按下或松开 Shift 不改变方向命令及按住方向的连发。文字与物品使用同一套推法，新录制只记录方向，不产生 P 前缀。编辑模式的 Shift 拖动复制等快捷键不受影响。

普通方向移动与推动都不会产生 `p → p+d+Up` 的登攀。头顶是否净空、物体是否只有一格高、当前 YOU 的名词均不改变这个限制；失败不消耗回合、不写入撤销历史。没有自由定向跳、拉箱或自动登攀。

水平推链统一移动所有成员与操作者，再重算规则。不能逐个移动链成员，让中途断句产生实际不存在的短暂属性。移动支撑物时不自动水平搬运其上整摞物体。

### 2.4 原地跳、顶压、弹跳和上浮

顶起只处理正上方一个可手动移动对象；不连顶整塔。落地压低也要求被操作体可手动移动，且其下方可进入；每条指令最多对该下落者执行一次下压，静止站立不重复。BOUNCY 优先，不同时下压弹台。文字被顶起后仍会按默认重力回落。

BOUNCY 必须有一次真实的下降位移后接触上表面。走上、爬上、侧撞都不触发。弹台身体在 Y=1 时，玩家接触格为 Y=2，正常顶点为 Y=5，而不是从起跳前的位置加三。沿上升路径逐格检查顶棚，截断后不穿透。

受控体在弹跳顶点获得一次新输入机会；非受控体的顶点暂停到下一条有效世界命令再恢复下降，避免同一回合无限弹跳。只有物品实际被移动或规则改变才计入互动审核，单纯站上固定弹簧弹跳不算主动改造。

FLY 平台与正站在它上面的当前 YOU 成组逐格上升；双方目标格都预检，头顶堵住则整组停下。它只承运直接站在顶面的受控实例，不搬运整摞普通物品或文字。离开后平台仍会继续上升到受阻。

本轮利用移动规则的方法是**弹台／石台／云平台改变玩家路线**。不新增受控体直接获得 HOVER／FLY 后的自由飞行输入。当前 YOU 具有这两种模式时应显式诊断并回滚不支持的改写，而不是让操作失常；这项范围限制必须在编辑器规则预览中可见。

## 3. YOU、WIN 与名词变形：保留的完整合同

### 3.1 同格胜利（2026-09-27：允许自身 YOU+WIN）

```text
存在实例 a、b（允许 a == b）：
  a 有 YOU
  b 有 WIN
  a.cell == b.cell
  且本次原子变化后的状态合法
```

同一个存活实例同时有 YOU 与 WIN 时可以自身配对获胜。不加入邻接、模型接触、投影重叠、接近距离或教学完成计数等兜底。

每次合法原子位移和随后的规则更新完成后，检查胜利；首次满足就记录 `youId / winId / cell / cause` 并停止后续自动运动。只因规则改变而使同一个实例具有 YOU 与 WIN，或使已经同格的两个实例成为 YOU 与 WIN，也会立即胜利。一次推链中尚未整体提交的临时位置不检查。

### 3.2 控制权转移与身份变形是独立操作

不要再写：

```text
GetEntity("player") 就是当前受控对象。
ROBOT Prefab 永远接收输入。
目标永远叫 goal 或者永远是 FLAG。
```

应从当前规则查询唯一受控实例与全部 WIN 实例。数据中的 `robot_01` 只是初始机器人的稳定 ID；即使控制权交给 `goal` 这个旗标实例，两个 ID 都不重命名。

失去 YOU 的对象只失去该默认来源：若没有显式 PUSH / STOP，它会变成非实体；若仍有显式 STOP，它仍然阻挡。取得 YOU 的对象获得默认实体性，但不会凭空得到 PUSH、HOVER 或其他能力。

### 3.3 一次推动完成安全换控

L09 的换控台采用相邻两行（L12 对应的目标主体为 SPRING）：

```text
初态：             将 IS 往下一行推一格后：
ROBOT  IS  YOU      ROBOT  [ ] YOU
FLAG   [ ] YOU      FLAG   IS  YOU
```

“下一行”是世界 +Z，同一 Y。移动的是一个实体词牌 IS。整条位移完成后扫描规则，旧 YOU 消失、新 YOU 成立，只有一个控制对象。先在另一处拼出 `ROBOT IS WIN`，旧身体失去 YOU 后就成为可进入的空心机器人目标。

这是第 9 关的纯换控用法，不执行名词变形。它不是两条程序脚本 `DisableRobot(); EnableFlag();`；来源仍是实际文字布局。第 12 关则先将控制权给 SPRING，随后另拼 ROBOT IS FLAG，实际改变原身体的身份。两类操作都不凭空改位置、身体格数或镜头槽位。

### 3.4 零个或多个 YOU

稳定初态必须恰有一个 YOU，且未获胜。

游玩中拆掉 YOU 可以进入 **NoControl**：完成本条指令剩余环境结算后，保留残局、提示撤销或重开；不偷选机器人继续操作，不丢失撤销历史。环境自动位移若在同条事务中重新拼回 YOU，则按最终状态继续。

本版未实现多个 YOU 同步输入。新规则让多个实例同时 YOU 时，返回明确 `MultipleYOU`，整条命令回滚，不随机挑第一个。编辑器应提前标出所有受影响实例。这是公开的原型范围限制，不是关卡里的隐藏规则。

输入、自动载人、落地处理、顶点状态、摄像机关注与 HUD 都要在规则变化后重新确定当前受控 ID，不能继续引用回合开始时的旧对象。动作阶段绑定实例，不绑定某一个名词或模型。

### 3.5 IS 的两种类型：赋性质与变身份

此前已经确认允许 `ROBOT IS FLAG`。因此，名词变形现在是 **P0 正式机制**，不再用“给原身体 WIN”或“换控”代替。操作输入不新增按键，依然通过推、顶、压、下落等方式调整文字。

| 句子 | 实际含义 | 是否改变 subject | 拆掉句子后的结果 |
|---|---|---|---|
| `ROCK IS WIN` | 当前所有 ROCK 获得 WIN | 否 | 无其他来源时失去 WIN |
| `ROCK IS FLAG` | 当前所有 ROCK 实例就地变成 FLAG | 是 | 已完成的变形保留，不自动变回 ROCK |
| `ROBOT IS FLAG` | 当前所有机器人实例就地变成旗标 | 是 | 原机器人 ID 仍存在，但当前 subject 是 FLAG |
| `ROCK IS CLOUD` | 岩块变成云，并按现有 CLOUD 规则重新计算性质 | 是 | 是否悬停取决于 `CLOUD IS HOVER`，不是云的隐藏天性 |

名词变形作用于整关所有匹配 **当前 subject** 的 Object。无需场内预先存在目标类型实例；不会吸收现有旗帜，也不会移动到它的坐标。`ROCK IS FLAG` 不把写着 ROCK 的 Text 变成 FLAG 文字，也不改 Terrain。所有物种仍是一格，模型外观不扩大逻辑体积。

这是原型自己的明确语义，不声称完整复刻其他游戏的变形细则。

### 3.6 变的是身份，不是实例；性质不跨物种继承

变形批次保留 `id / cell / 当前运动阶段`，只改 `subject`，然后重新计算属性、实体性、重力、控制权和目标身份。不能把原属性位直接复制给新类型。

例如：

```text
ROBOT IS YOU
ROCK IS PUSH
FLAG IS WIN
ROCK IS FLAG  ← 玩家刚刚拼成
```

岩块成为旗帜；原来的 `ROCK IS PUSH` 即使还存在，也不再作用于它。若 FLAG 没有 PUSH/STOP/YOU，原岩块会成为可进入的空心旗标，由 FLAG 的 WIN 规则提供目标性质。这里不是 WIN 自动删除 PUSH，而是对象已不再是 ROCK。

反之，若同时存在 `FLAG IS STOP`，变出来的旗帜仍然阻挡，不能通过胜利判定强行穿入。若存在 `FLAG IS HOVER`，它立即悬停；若目标类型无运动例外，恢复世界默认下落。

`initialSubject` 可以用于作者显示和复盘，但不能作为 PropertyResolver 的查询依据。稳定 ID 中的 `rock`、`robot_01` 只是名字，不随着变形重命名，也不能用它们继续选择旧模型、旧碰撞或旧操控对象。

### 3.7 变形后 YOU 不自动跟随；支持真正改造原身体

只存在 `ROBOT IS YOU` 时，拼出 `ROBOT IS FLAG` 会让原身体不再满足 ROBOT 的 YOU 规则。若没有其他受控对象，进入可撤销的 NoControl；不能偷偷给新旗帜补 YOU，或回退到一个叫 player 的实例。

如果新类别确有 `FLAG IS YOU`，变形后的旗帜会受控；但这条规则作用于全部 FLAG。存在多面旗帜时会触及本版保留的单 YOU 限制，返回 MultipleYOU 并回滚，不能随意只选“刚变出的那一面”。本版允许名词变形，不等于顺带承诺多 YOU 同步移动。

第 12 关用一个不需要多 YOU 的流程展示用户提出的真实变形：

```text
步骤 1：移动 IS，把 ROBOT IS YOU 换成 SPRING IS YOU。
        原机器人失去控制；唯一弹簧成为受控对象。
步骤 2：操控弹簧拼出 ROBOT IS FLAG。
        原机器人实际变为旗帜，按 FLAG IS WIN 成为目标。
步骤 3：操控弹簧进入该旗帜所在格。
        YOU=spring 与 WIN=robot_01 是两个不同实例，合法同格获胜。
```

与之对照，第 9 关仍用 `ROBOT IS WIN` 和换控旗帜，原机器人的身份不变。两关有意区分“同一种东西变了性质”和“它已经成了另一种东西”。

### 3.8 持续生效的句子与已完成的变形分开

本版采用**状态改变型变形**：句子有效时转换匹配实例，移除句子只停止之后的转换，不撤销已经发生的身份变化。

- 想恢复此前局面，使用整步 Undo。
- 想在游戏世界中反向变形，可以另拼 `FLAG IS ROCK`；它同样作用于全部 FLAG，不只作用于曾经是 ROCK 的个体。
- 将句子推开再推回，可以让之后出现的新源实例发生变形；不会无条件复制已有对象。
- `ROCK IS ROCK` 是无操作句，不消耗变形次数，也不产生“免疫变形”的隐藏保护。它与 `ROCK IS FLAG` 并存时不阻止变成 FLAG。

这项默认值会增加不可逆选择，但不取消无限撤销。提示应区分“停止变形规则”和“撤销刚才的变形”，不要宣称拆句即可还原。

### 3.9 同步批次与链式转换：每实例每指令至多一次

为防止 `ROCK IS CLOUD` 与 `CLOUD IS ROCK` 在同一回合无限互变，本版明确采用：

> **每条被接受的世界指令中，每个实例最多发生一次非平凡的身份转换。**

每次进入规则结算点，先从同一份变形前状态捕获所有待变形实例，再统一提交。不能在遍历第一个岩块后就让它继续匹配下一条规则，而其他岩块还没处理。

```text
ROCK IS CLOUD
CLOUD IS FLAG

某个 ROCK 在一次有效指令中变为 CLOUD。
它在同条指令的后续下落、词牌移动或 WIN 检查中，不会再变为 FLAG。
下一条有效指令才可能把它变为 FLAG。
初态本来就是 CLOUD 的另一个实例，则可在第一条指令中变为 FLAG。
```

两向转换会随着有效指令交替，不随动画帧、镜头旋转或真实时间自动变化。失败输入、只按修饰键、不合法的 WAIT 不推进变形。受控弹跳顶点的一次侧移或释放属于新的有效指令，重新给予一次变形机会。

词牌在自动下落中拼出新句子时，未在本条指令变过形的源实例仍应立即响应；不能只在手动推词的那一刻扫描。批次中的控制权、碰撞和 WIN 都在全部身份替换后检查，不检查半批次中间态。

`transformedIdsThisCommand` 属于事务上下文，不存进作者关卡文件；若有子步调试快照，必须一起保存它。完整回合前快照不需要保存上一回合的临时标记，下一指令开始清空。自动结算的循环判重需要包含该集合，不能仅看坐标。

### 3.10 当前支持范围与冲突

| 情况 | 本版处理 |
|---|---|
| `ROBOT IS FLAG` 等任意已登记名词对 | 支持，统一规则，不硬编码几个特例 |
| `ROCK AND CLOUD IS FLAG` | 支持，多个源类别映射到同一个目标 |
| 重复的 `ROCK IS FLAG` | 去重，只变一次，不复制实例 |
| 同时 `ROCK IS CLOUD` 与 `ROCK IS FLAG` | MultipleTransformTargets；明确回滚，不按扫描顺序挑一个 |
| `ROCK IS FLAG AND CLOUD` | 暂不支持一变多；诊断，不复制、不仅执行前半句 |
| `ROCK IS FLAG AND WIN` 或 `ROCK IS WIN AND FLAG` | 暂不支持混合右侧；分别写 `ROCK IS FLAG` 与 `FLAG IS WIN` |
| 文字本体变形／固定 Terrain 变形 | 不支持；Text 与 Terrain 不属于这些名词的实例集合 |
| 两个同格非实体因变形同时实体化 | RuleConflict，整条回滚，不自动挤出、吞并或穿透 |
| 变形后多 YOU，或 YOU 直接 HOVER/FLY | 延续公开范围限制，明确诊断并回滚，不凭模型补另一套输入 |
| 变形后零 YOU | 允许 NoControl 残局，完成当前环境结算后可撤销／重开 |

这些组合限制应在编辑器预览与拒绝提示中可见。不要通过无声忽略句子来伪装兼容，更不要把已经获准的全部名词变形功能一并退回“以后再做”。

### 3.11 WIN 的时机与变形批次

每个原子操作的顺序统一为：

```text
旧状态预检 → 整组位移 → 重读规则 → 同步身份变形
→ 按新身份派生性质 → 校验最终状态 → 检查同格 WIN（允许自身）
→ 尚未获胜才继续重力、上浮或弹跳的后续原子步骤
```

例如，非实体 ROCK 与机器人已同格，本次合法变化让 ROCK 变为 FLAG，且 FLAG 有 WIN，则可以立即获胜。反过来，如果 ROCK 原有 WIN 但本次变为不带 WIN 的 CLOUD，不能在变形前的瞬间抢先记胜。

同一个实例变为 FLAG 后若具有 YOU+WIN，也可自身配对获胜。名词变形不改胜利公式，不重新引入接近、邻接或身份名称等兜底。

### 3.12 加载、撤销与保存

生产 `WorldFactory` 必须在读规则后检查初态：恰有一个 YOU、没有初始胜利、没有待自动位移，且没有会把现有实例立即改变的非平凡变形。世界中可以存在完整变形句而暂时没有源实例；初态就有源实例则要求作者明确重做初态或将句子留到游玩中再拼成，不能在玩家第一步偷偷变形。

配套 Python `Model` 是底层测试模型，局部单测可以构造含待变形的原始状态测试算子；正式十二关由 `main()` 额外检查无待变形。不得把这个测试便利当成生产加载合同。

Undo 恢复每个实例的当前 `subject`、ID、位置、运动阶段、控制权和胜利记录；恢复后只重建派生索引，**不再次执行变形**。否则撤销回 ROCK 后马上又变 FLAG，玩家将无法真正撤销。

作者 JSON 仍保存初始 subject。试玩停止必须丢弃运行中的变形残局，不能把作者的岩块默认保存成旗帜。存续运行快照和回放状态摘要则必须包含当前 subject，否则同位置、不同物种会被错误认为同一搜索状态。

## 4. 规则来源与表现的闭合链路

### 4.1 唯一的运行时来源

```text
WorldState 中所有存活 Text 的 token / cell
    → 同高度 +X / −Z 语法扫描
    → PropertyRules 与 TransformationRules + SourceTextIds
    → 当前身份对应的性质 / 控制权 / 重力
    → 动作、下落、变形、胜利
    → 表现与派生的规则摘要
```

不能倒过来从 HUD 文本或作者的 `sourceGroups` 创建规则。Parser 不过滤主操作区／隔离区，不过滤词牌可达性，不由相机可见性决定是否生效。玩家没看着的一句规则依然有效；前提是它的词块确实存在于世界。

每个生效的“主体—属性”和“主体—变形目标”必须保留至少一组 `SourceTextIds`；每组 ID 都能追溯到同一高度、连续合法方向上的真实词牌。重复句子可有多组来源。只删一组但另一组仍在时，性质不会消失，这是重复规则的正常结果，不是隐藏兜底。

### 4.2 空间句子不能只是一块装饰牌

ROBOT、IS、YOU 必须分别生成三个词牌视图；不是把整行字符串印在一块背景面上，再让 fixedRules 驱动逻辑。用镶边或浅色连线帮助看出句子可以，但不能让连线本身提供规则。

临时灰盒每格对应一块实体词牌，顶面或朝镜头的字面显示 token；字面可随镜头调整可读朝向，但规则读取方向固定为世界 +X / −Z。不能因换镜头而倒读、折句或改变词牌占格。

### 4.3 隔离规则区的实际制作方案

所有新增基础句子放在主区负 Z 侧的独立空间里，句子沿 +X 排列。相邻句子至少留两格空位，行与行留一格，避免意外串句。完整地板承托词牌；一格厚的透明 Terrain 隔墙位于主区外侧一行，并覆盖可操作高度，防止主区通路因扩地图而被绕过。

这是一种保守的灰盒布局，不是要求最终美术都做成玻璃柜。**最终可改成可见的高台、悬崖对岸或墙内凹槽，但都必须是真实地形和词块，且重新验收通路。**不可把源词移出镜头、塞进不可见父物体或改成屏幕角落的列表。

透明隔墙要有边框、反光或触碰反馈，让玩家看得出边界。不要使用完全不可见的“空气墙”。隔墙的透明材质属于关卡必要表现，不能用完全不透明的默认灰材质遮住源词后仍声称完成。

把玩家在编辑器中放到源词旁边，应当能用同一套方向输入推动它；拆开 YOU 会真的失控，撤销会恢复。这是检查“不可达”没有偷换成“逻辑只读”的验收。

### 4.4 四视角下的可读性不是附加项

首次进入每关，镜头必须同时交代角色、核心操作词与基础句子所在空间。布局不足以保证真人可读：实际 Game View 需要人工检查文字大小、遮挡、玻璃反射和缩放。

`presentation.minimumReadableWordPixels=28` 是首版验收目标，不是已经测出的事实。不能为纳入所有物体而无限缩小文字；可以允许不推进世界的观察缩放／聚焦。聚焦应移动观察镜头并高亮真实词牌，而不是弹出一份自带规则的替代板。

同一条规则至少在一个相机槽可无遮挡阅读；首次需要理解它时应位于初始可读范围或有明确的世界指示。Q/E 切镜头不消耗回合。遮挡采用围绕当前 YOU 的屏幕圆形局部剖切，只剔除玩家前方的遮挡表面，圆外保持原有地形；不得整物体淡化、删除逻辑阻挡或隐藏被提示的词。

当前规则摘要只允许是 Parser 输出的派生 UI。点击一条摘要定位到真实 SourceTextIds。关闭 HUD 后，玩家仍能在世界里找到每条规则；本版不提供“只读规则板”这种关卡对象。

### 4.5 建立从文字到物体的因果反馈

拼成句子时，依次高亮参与的词牌、受影响的同类物品，再播放属性或身份变化。修改名词、IS 与属性都走同一机制，不按关卡编号特判。

PUSH／STOP 改变碰撞与推动性质，物体保持原有模型、尺寸和不透明外观，不再通过虚像或淡化表达属性缺失；HOVER 仅使物体保持高度，FLY 才上升；BOUNCY 只表现弹性，不把模型换成弹簧；名词变形才替换物品身份模型。模型、token、规则和碰撞必须来自同一状态。

L01 旗标初态没有 WIN：保持可识别的旗帜轮廓，但不亮起胜利标识。补上 WIN 才发光。岩块、机器人、墙等物体失去 STOP/PUSH/YOU 后仍保留原有外观；补上属性时只改变相应玩法性质，不以缩放或透明度表达碰撞。名词变形仍可改变模型身份。此表现约定按 2026-09-27 用户修订生效。

## 5. 十二关与多解的设计约束

有效互动是成功移动非受控 Object 或 Text，或者由这些动作导致规则变化。走空格、已有弹台上的弹跳、切镜头、推失败均不算。原地跳真实顶起文字则算。

L01—L12 均由地形和规则保证至少一次有效互动；游戏胜利仍只检查不同 YOU/WIN 合法同格。`designContract`、回放和互动审核不得进入 WinResolver。

L08—L12 维持五个多策略关：改变通路、改变目标实例、换控、移动目标、选择弹跳或上浮、变形原身体。不是把同一种解法的绕左／绕右算两种。每条参考解从同一份初始 JSON 独立运行，不能复用另一解法的残局。

主区词牌全面解锁后，可能出现“搬文字搭台阶”等额外解法；合法的新解不自动算漏洞。不允许通过拒绝特定名词推动、只接收预设操作序列、隐藏重复规则来维护所谓标准答案。

本次穷尽的是**不允许有效互动的子图**，不是包含任意推字的全部世界状态。它证明当前模型内无法纯走／爬／跳通关，不证明每个谜题必须使用指定关键词，也不证明没有更多解法。

## 6. 程序、数据与编辑器

### 6.1 不更换框架，删除第二条规则来源

仍采用纯 C# Core、Unity Runtime、Editor、Tests 分层。保留实际 Unity 2022 工程的版本、管线、输入后端和资产；不要重建仓库。Scene 与 Transform 不是逻辑真相，角色、规则、重力和碰撞由整数模型计算。

本轮优先修改 `LevelDefinition / RuleParser / WorldFactory / WorldView / LevelEditor`，不是只给 HUD 增加世界文字的装饰模型。

| 模块 | 本版合同 |
|---|---|
| LevelDefinition | 不再含 fixedRules；显式规则只有 entities 中的 Text |
| RuleParser | 扫描全部空间词；不注入任何物种规则；性质与变形均输出来源 ID |
| PropertyResolver | 当前 subject 匹配派生规则；只保留已约定的默认行为 |
| WorldFactory | 不再默认创建 ROBOT IS YOU / FLAG IS WIN；初态无 YOU 必须报错 |
| WorldView | 遍历实际 Text 生成每个词牌；不能只显示 Object 或只显示主区 |
| RuleSummary | 只读派生结果和来源定位；不能创建规则 |
| TransformationResolver | 同步、每指令每实例至多一次、保留 ID／位置、重算新身份属性 |
| GameSession | 一次命令及全部连锁统一撤销；控制权与变形一并恢复 |
| Editor | 画词牌或成句工具落地为独立 Text；删除旧“固定规则列表”编辑面板 |

### 6.2 语法与结算时序

```ebnf
Sentence = PropertySentence | TransformSentence ;
SubjectList = Subject, { AND, Subject } ;
PropertySentence = SubjectList, IS, Property, { AND, Property } ;
TransformSentence = SubjectList, IS, Subject ;
Subject = ROBOT | ROCK | CLOUD | SPRING | FLAG ;
Property = YOU | PUSH | STOP | HOVER | FLY | BOUNCY | WIN ;
```

同高度、世界 +X 或 −Z 连续读取；不读 Y、反向、斜线、拐弯、跨层或屏幕投影。AND 保留有效前缀。多句属性取并集，不取最后一句。右侧多名词／名词属性混合、多个变形目标、多个 YOU 等仍显式诊断。

每条有效命令：旧状态预检 → 手动平移、推链或独立跳跃原子提交 → 全量读词／批量变形／新属性／状态校验／WIN → 当前受控体下降 → 环境上浮和下落 → 稳定或顶点决策 → 提交一次历史。每次文字重力位移后也重新读词。

环境 Up 按 Y 降序、ID 稳定排序，每轮每体一格；Down 按 Y 升序、ID 排序逐格下降到接触或模式改变。核心不得因容器遍历顺序改变结果。规则导致两个实体非法同格时整条回滚；不穿透、不随机挤出。循环／子步上限触发应作为明确模拟错误，不当成玩家失败。

框架生产实现仍需要处理底部虚空、对象移除和失败；本包的有限参考模型仅验证有实际底板的十二关，不代替这些单元测试。禁止把参考模型把边界视作墙的测试便利带入正式虚空语义。

快照包含 ID、当前 subject、token、位置、存在性、运动阶段、待恢复下降、终局和胜利配对；属性与来源是派生数据，恢复后重建，但不重放变形。相机状态不作为物理回合继续推进的依据。

### 6.3 v0.9 JSON 合同

```text
schemaVersion: 9
mechanicsVersion: RW-v0.9
id / title / bounds / terrain / entities / options / camera
presentation / designNotes / designContract / referenceSolutions
```

**不存在 fixedRules。**数据加载入口应拒绝旧规则数组，包括空数组，不把忽略未知字段当成已经删除旧规则系统的证明。

- `bounds.min/max`、`terrain.min/max` 都是包含端点的整数坐标。
- `entities` 保存稳定 ID、`kind=Object|Text`、subject／token、cell、`anchored=false`。
- Object 用 subject，Text 用 token。不要用 `w_win` 或 `robot_01` 这样的 ID 猜内容或控制权。
- `terrain.appearance=Stone|TransparentGlass` 仅用于表现；碰撞由同一 terrain 范围决定。没有一个隐藏的图层自动免碰撞。
- `presentation.sourceGroups[].textIds` 只帮作者聚焦，没有 tokens，也不参与 Parser；删除它不改变规则。表现应遍历实际 Text，而不是把这些分组当唯一生成清单。
- `presentation.mainAreaBounds` 只是构图与审查辅助，不是第二个玩法边界。完整 `bounds` 包含全部源词。
- `designContract.requireActiveInteraction=true` 对十二关一致；L01/L02 的参考解还要求真实 Text 位移。
- `referenceSolutions[]` 包含命令、事件要求和结果，仅供验证，不能成为通关脚本。

本包 options：

```text
actionMode = MoveAutoPush
winMode = YouAndWinSameCell（旧 DistinctEntitiesSameCell 标签兼容读取）
gravityMode = WorldDownExceptHoverOrFly
collisionMode = SolidPairsTerrainUniversal
solidityMode = YouPushStopOrText
supportMode = StrictBelow
controlMode = SingleYouTransfer_NoControlUndo
bounceRiseCells = 3
transformationMode = PermanentSingleTarget_SimultaneousOncePerEntityPerCommand
ruleSourceMode = WorldTextOnly
textMobilityMode = AllWordsMovable_GeometryAccess
```

磁盘定义、作者草稿、试玩状态必须深拷贝隔离。保存输出的是作者初态，不是试玩结束后的词块排列或变形后物种。未知版本直接报错；本包已经给出新布局，不应运行时把旧 fixedRules 随便扔到某个坐标当作迁移完成。

### 6.4 编辑器必须跟着改

沿用 IMGUI 窗口、按 Y 层 XZ 画布、独立三维预览、四视角、作者撤销重做和隔离试玩。作者“放置一句话”工具可接收 token 序列，但必须创建逐块 Text，并逐格校验支撑、方向、空位；保存后不残留规则字符串作为第二来源。

| 工具 | 验收结果 |
|---|---|
| 全词牌计数 | 当前 LevelDefinition、WorldState、实际 TextView 数相符，包含隔离区 |
| 规则来源检查 | 每条属性／变形规则能选中其源词；不允许无来源事实 |
| 输入预览 | 同一方向按前格占用显示移动或推链，失败不会翻越；不可达不是不可推属性 |
| 支撑检查 | 源词和可动词都有合法初态支撑，不靠 anchored／隐藏 Hover |
| 可见性检查 | 可聚焦全部源词并逐相机检查；不能靠规则 HUD 代替世界可读性 |
| 缺失视图检查 | 模型中 Text 存在而视图缺失、字面为空或 token 不一致时报告错误 |
| 删除词实验 | 在试玩副本移走 IS，规则立刻消失；Undo 恢复，不影响作者草稿 |
| 来源区实验 | 把测试出生点放到隔离区，能推动源词并真正改变规则 |
| 多解回放 | A/B/C 各自新建会话；对照 YOU/WIN、弹跳、上浮、换控和变形 |
| 内容审核 | 十二关都有世界文字和实际词互动样例；全部十二关进行无互动搜索 |

当前版本每关都无 anchored=true；编辑器导入遇到它必须报告与合同不符，不把它悄悄改成 false 后仍沿用旧解法验证。
