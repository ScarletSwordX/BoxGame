### 0.2 本版为实现采用的明确约定

以下是把讨论落到工程所需的设计选择，并非用户逐字指定的所有细节：

| 项目 | 采用值 / 范围 |
|---|---|
| 零重力词工作名 | `HOVER`；不主动上升，不锁死对象；可集中改名，不能混出两个等价词 |
| 有效重力优先级 | 固定约束先于运动；动态对象 `FLY > HOVER > 默认 Down` |
| 原地跳高度 | 一格；可以顶起正上方一个可移动实体阻挡体，不连顶整塔 |
| 下压 | YOU 实际落地时，条件允许可将一个可移动支撑体压低一格；一条命令最多一次 |
| 句法 | 同 Y、沿世界 +X / +Z 的直线，支持左右两侧 AND；六关只重点教属性侧 AND |
| 默认支撑 | StrictBelow，只看直接下方有效实体承托，不启用边缘支撑 |
| P0 控制数量 | 恰好一个 YOU；六关固定控制句，暂不制作换体、多 YOU 或悬空受控体的输入玩法 |
| P0 边界 | 闭合灰盒，底部有真实地基；侧面和顶部的不可越界限制必须可见，不以隐藏掉落死亡制造谜题 |
| 自动时序 | 离散指令驱动，明确的主动作段＋环境结算段，见第 7 节；不是连续刚体模拟 |

**历史 32 小时是此前提供的人工投入预算，不是本次重新承诺的完成工期。**本版比最初两属性原型复杂；第 15 节给出实现检查点与砍表现的顺序，不保证在固定时间内完成全部系统。

### 0.3 必须停止沿用的旧设计

- 不再把“每格至多一个实体”作为数据不变量；玩家与空心目标同格是正常状态。

## 1. 游戏要验证什么

### 1.1 一句话定义

**玩家是一个默认受重力的实体方块，通过移动规则文字、制造和解除重力例外，在立体阶梯中攀登，最终填入一个可进入的目标空间。**

金字塔是空间主题，不要求第一版完成四个侧面和内部迷宫。先做可读的局部残缺阶梯；模型、美术和音效可用临时资源。

### 1.2 核心循环

观察高度和规则 → 找到可操作文字与接触位置 → 提交一条离散动作 → 看见规则与结构变化 → 使用新路线或高度 → 进入目标。尝试失败可以整步撤销。

本版的核心教学不是“先拼出基本物理让角色正常工作”，而是：**东西本来会掉；文字使世界出现例外；拆掉例外，正常行为立即回来。**

文字仍是实体材料，能推、顶、压、承托，但不承诺六关都以“拆句子当台阶”为唯一主题。在默认重力下，强行沿用该旧命题会引入没有依据的悬浮。L02 验证落字成句，L03/L06 验证解除例外，L04/L05 验证规则如何提供高度。

### 1.3 原型成功标准

运行入口 → 完成六关中的一个完整切片 → 观察一次真实规则变化 → 利用高度变化 → 同格获胜 → 撤销获胜或重开 → 在编辑器修改关卡、保存并隔离试玩。完整内容目标再扩展到六关。

没有时间限制、步数上限、追赶敌人、连续坍塌计时。撤销不是无死锁证明；六条参考路径也不是唯一解、最短解或谜题质量证明。

## 3. 程序框架选择

### 3.1 总体方案

沿用上传底稿最重要的分离：**纯 C# 确定性模拟核心＋轻量会话层＋Unity 表现适配＋共用数据的关卡编辑器。**不用为这个原型引入完整 MVVM、依赖注入容器、ECS、响应式框架或通用事件总线。

| 项目 | 本版选择 |
|---|---|
| 引擎 / 管线 | 检查并保留现有 Unity 2022 与渲染管线；新空工程可用最简单 3D 配置；不升级包来规避适配问题 |
| Core | System 下的普通 C# 类、结构体、枚举与集合；不引用 UnityEngine / UnityEditor |
| 依赖隔离 | Core / Runtime / Editor / Tests 的 `.asmdef`；Core `noEngineReferences: true` |
| 组装 | GameBootstrap 显式创建模拟器、会话、序列化器、关卡来源与 Presenter |
| 时间 | 一条离散命令产生一条事务；Update 只采集输入/播放表现，不模拟重力 |
| 序列化 | JSON DTO＋Runtime 中的 JsonUtility 适配器；嵌套对象/列表，不序列化 Dictionary 或 Unity 引用 |
| 表现配置 | 少量 ScriptableObject 保存材质、Prefab、镜头与 TextAsset 清单；不存运行中的可变世界 |
| 游戏 UI | 简单 IMGUI 或已有 UI；文字可先用 TextMesh / 工程已有文本方案 |
| 作者工具 | IMGUI EditorWindow＋按 Y 切片的绘图交互与三维观察；SceneView 与窗口共用编辑会话 |
| 测试 | Core 为主的 EditMode 测试；Runtime 场景/输入另做 PlayMode 与人工验收 |

旧 Input Manager / 新 Input System 按工程实际启用后端实现一个适配器。不要为了节省输入适配去更改整个项目设置。不要将镜头槽或键名直接写进 Core 的空间判断。

## 4. 世界、实体、默认属性与碰撞

### 4.1 网格与单一状态源

`GridCell(x,y,z)` 为实体身体占据的一格，Y 向上，四向为 ±X / ±Z。站在 Y=0 地基上，身体在 Y=1。Core 使用自己的整数值类型，不用 Vector3Int。表现只做 `origin + cellSize × cell` 映射。

本版关卡边界采用包含端点的 `bounds.min / bounds.max`；允许负 X/Z，例如 L05 的 Z=-1 规则台。不会因为坐标为负就认为越界。六关底部都有实际静态地基；边界外操作拒绝，并在画面呈现边框/截面边界，不把未建模的隐形墙当线索。

地形可用多个轴对齐整格盒压缩存储，展开后取并集。地形盒重复覆盖不是实体冲突。颜色与文字是具有稳定 ID 的实体；格子查询必须返回实体集合，而不是只有一个 Entity。

```text
entitiesById: EntityId → EntityState
occupantsByCell: GridCell → 集合<EntityId>
terrain: 静态整格占位集合
```

索引是派生缓存，不能与实体坐标形成两份权威数据。编辑器与游戏必须采用同一套合法同格判断。

### 4.2 类型合同

| 对象 | 实体性 | 默认运动 | 可由玩家直接操作 |
|---|---|---|---|
| 静态中性地形 | 固有阻挡、承托 | 固定 | 不可推、顶、压，不受颜色规则影响 |
| 可动文字 | 固有实体、承托 | 世界默认 Down | 可水平链推、单体顶起、满足条件时落地压低 |
| 锁定文字 | 固有实体、承托 | 明确固定 | 不可移动；必须显示铆钉/支架/固定标记 |
| YOU 颜色对象 | 默认实体 | 世界默认 Down，规则可推导例外；首批不开放该输入变体 | 接收角色动作 |
| 非 YOU 颜色对象 | 由显式 BLOCK 决定 | 世界默认 Down，可被 HOVER / FLY 覆盖 | 不能普通水平推；有实体表面时可被顶/压 |
| 无 BLOCK 的 WIN 目标 | 空心、可被 YOU 进入 | 默认 Down，悬空必须有 HOVER / FLY 或实体支撑 | 不作为玩家的顶、压、弹跳接触面 |
| 固定规则碑文面板 | 不占玩法网格，不可踩踏 | 不参与运动 | 只读、可见的显式规则来源，不是隐藏组件 |

颜色实体首版不允许作者随便勾选 anchored 来偷免重力；需要固定建筑请用 Terrain。`anchored=true` 当前只用于 Text。字面上写 RED 的词块不是红色实例，不继承 RED 的属性。

### 4.3 默认来源与文字来源分离

对颜色实体：

```text
ExplicitProperties(e) = 全部有效显式规则对 e.color 的属性并集
EffectiveBlock(e)    = ExplicitProperties 包含 BLOCK 或 YOU
```

YOU 默认实体性来自“当前被控制”，不是来自 RED 色相。它不应被永久写回 EntityDefinition，也不需要伪造一条 `RED IS BLOCK` 字符串注入解析器。

未固定动态对象的常态重力：

```text
FLY 存在   → Up
否则 HOVER → Hover
否则       → Down（世界默认）
```

固定约束在上式之前处理。默认 Down 不是名为 FALL 的显式属性，更不是每回合先执行一次 Down 后再执行 FLY。FLY 与 HOVER 同时存在选 Up，编辑器提示被覆盖来源；六关不把该冲突当谜题。

来源查询示例：

```text
RED：控制 = RED IS YOU；实体 = 玩家默认；重力 = 世界默认 Down。
BLUE：实体 = BLUE IS BLOCK；重力 = BLUE IS HOVER → Hover。
```

主画面只显示真正存在的显式规则。默认说明可放在帮助与选中面板，不制造可被拆开的假文字。

### 4.4 支撑和可进入目标

至少分开三个查询：`CanShareCell`、`BlocksEntry`、`CanSupport`。不能仅凭“某格里有对象”判断玩家不能进入，也不能让空心目标承担玩家支撑。

| 交互 | 结果 |
|---|---|
| YOU ↔ 无 BLOCK 的颜色对象 | 双向允许同格；谁移动都一样；无互相支撑、顶压或弹跳 |
| YOU ↔ 有效 BLOCK 的颜色对象 / Text / Terrain | 实体接触；不能直接穿入；WIN 不改变此结果 |
| 两个空心颜色对象 | 允许同格；并不因此自动获胜 |
| 空心颜色对象向 Terrain / Text / 非 YOU 的 BLOCK 运动 | 受其阻挡，向下落时可以被其实体上表面支撑 |
| 两个实体阻挡体 | 不允许同格；原子组可以使用彼此同时让出的旧格 |
| Terrain 与任何动态实体 | 不允许同格 |

对“一个非玩家实体体积主动占入空心对象已有位置”这种六关没有使用的相向争用，P0 不发明挤开、吞掉或压碎规则。显式位移不能提交非法组合；自动重力若遇到**没有可承托实体面、又不能合法提交的动态争用**，返回不支持的接触诊断并回滚事务，不能把空心目标当成隐形支架。将来扩展这种交互时另订规则并补测试。

这是一项公开的 P0 支持范围限制，不是以拒绝复杂碰撞掩盖六关中的正常动作。六关的 YOU↔空心目标双向重叠、目标落到普通地基、文字落到普通地基必须完整可用。

### 4.5 StrictBelow

只允许直接下方的有效实体表面提供承托；没有边角接触、同层互托或对角支撑。YOU 默认实体后也可以为普通实体提供接触表面；不再沿用原 v0.1 “角色不承托，石头压到角色就死亡”的特殊合同。

悬停但有 BLOCK 的对象仍能承托；没有 BLOCK 的 HOVER 轮廓不能承托。承托与是否受重力分开。

## 5. 输入、原地跳跃、冲击与弹跳

### 5.1 唯一输入协议

| 状态 | 输入 | 逻辑指令 / 含义 |
|---|---|---|
| Grounded | 方向 | Move(worldDirection)，水平一格；遇可动 Text 则尝试链推 |
| Grounded | Space | JumpInPlace，原地上升一格，必要时单体顶起，随后下降；不允许横移 |
| BounceApex | 新的方向输入 | 在当前高度横移一格，随后强制下降；不是第二次跳跃 |
| BounceApex | Space | ResumeBounceDescent，原位恢复下降 |
| 可观察状态 | Q/E | 切相机槽，不推进模拟、不消耗顶点选择 |
| 试玩 | Z / R | 整步 Undo / Restart |
| 已获胜 | 下一关按钮 | 明确确认后切关；保留 Undo/Restart/观察 |

Core 的命令只有世界四向 Move、JumpInPlace、ResumeBounceDescent。回放采用 E/W/N/S/J/WAIT；WAIT 只在顶点有效，不额外提供 Grounded 任意等待键。按键与状态适配后才向 Core 提交命令。

同帧 Grounded 的 Space＋方向只发原地跳；该方向不缓存为顶点侧移。到顶点需要新的按下输入，不能长按自动消耗侧移。顶点的方向＋Space 只尝试该方向；受阻则拒绝，不暗中改成原位下降。

未输入、旋转、读提示、非法移动都不推进其他物体。一次正常起跳再原地落回仍是合法指令，即使角色最终坐标相同；它可以推进已暂停的非玩家运动。

### 5.2 行走与推字

目标格可进入则水平移动一格，再由下降阶段处理失去支撑。没有自动登阶或对实体方块的自动跳跃。

若目标是可动 Text，向前收集连续文字链；任一被固定、终点越界、终点存在不可进入对象则整条拒绝。预检所有目的格，原子提交全部文字和 YOU，不能先移动一半。颜色方块不混进水平推字链，也不新增 PUSH 属性。

被推出台面的文字会在本命令中参与默认重力。没有“必须一直在 Fixed 上方”限制，也没有离开台面自动悬停。

顶点侧移仅为移动到可进入格，不允许在空中推字、爬上目标或额外顶起。

### 5.3 原地跳跃与顶起

从 Grounded 出发；若正上方可进入，YOU 上移一格；若正上方是一个可移动实体阻挡体，且该对象再上方可进入，则 YOU 和被顶体各上移一格，组成一个原子组。

只能顶一个。第二个阻挡体、固定文字、Terrain 或顶部边界挡住时拒绝。不顶空心目标；向上经过其格子只可能触发正常同格获胜。

普通跳跃没有输入决策顶点。完成主动作段的下降后才交还操作，除非落到 JUMP 产生真正的 BounceApex，或途中已经获胜。

**顶字后是否留下来由重力决定。**默认文字会落回；有 HOVER 的颜色块被顶高后则可以保持新高度。不要为让旧教学继续成立而给被顶物添加隐藏一回合悬停。

### 5.4 下落与一次落地压低

下落由实际逐格 -Y 位移记录，不是通过动画速度判断。已下降后接触可移动实体支撑体，若该支撑体下方可以进入、此次未触发 JUMP、当前指令尚未消费 YOU 的下压额度，则支撑体与 YOU 原子下移一格。

持续站立不反复压低；一次命令最多一次压力事件。压低后的物体仍会按其重力模式继续结算，不能把“冲击一格”误当成“以后最多再落一格”。

在当前默认重力＋StrictBelow 下，普通静止文字之所以站稳，通常就是因为下方已被承托，因此常常不能再被压下。该动作的可见用途更适合无下方支撑的 HOVER 实体等状态。**六关不必硬教压字；保留明确实现和局部测试即可。**

### 5.5 JUMP 的唯一含义

当一个实际下降过的实体接触某个 BLOCK＋JUMP 的上表面，触发的是**下落者**向上移动三格，不是弹跳台自己移动。

```text
弹跳台身体格 Y=1
下落者接触格 Y=2
上升路径 Y=3 → Y=4 → Y=5
正常顶点 Y=5
```

从更高处落下不增加弹力。每个上升格都检查碰撞、规则和 WIN；顶棚提前截断，不穿透，不顺带顶起头顶物体。实际升高为零不建立假顶点，也不回退执行下压。

水平侧撞、静止站立、等高走上弹台、从下方顶碰均不触发。走上台后原地跳再落下可以触发，这是 L06 的明确教学。

JUMP 先于普通落地压力，消费此次接触。若上升中已进入 WIN，立即记录终局并停止，不能继续凑满三格动画。

### 5.6 顶点与非玩家弹跳

YOU 新到顶点时，暂停并允许一次侧移或原位下降。侧移被挡则保留原顶点；成功后这次机会被消费，必须完成下降或进入另一台产生的新顶点。

被弹起的非 YOU 实体也记录顶点，但没有横移输入；在下一条**有效世界指令**中原位恢复下降。新产生的顶点不能在同一条命令里立即又恢复，否则会形成自动无限弹跳。

恢复下降是已开始弹跳的强制运动段，不能因常态 HOVER/FLY 把它留在半空或凭空再给侧移。完成此次接触段后再采用常态重力。首批不赋予 YOU HOVER/FLY；这类受控体输入合同属于扩展，不是暗中给它自由飞行。

## 6. 规则语法、解析与同格胜利

### 6.1 合法词库与句法

```ebnf
Sentence = Subject, { AND, Subject }, IS, Property, { AND, Property } ;
Subject  = RED | BLUE | PINK ;
Property = YOU | BLOCK | HOVER | FLY | WIN | JUMP ;
```

只扫描同 Y、沿世界 +X / +Z 的连续直线；不读 -X/-Z/Y、对角、拐弯或投影视角拼句。切镜头不改变有效句子。各句对同色实例取属性并集，重复句不重复执行位移。

解析最长有效前缀。例如 `BLUE IS BLOCK [空格] FLY` 中 BLOCK 仍有效；填入 AND 后才增加 FLY。`BLUE IS BLOCK AND` 的有效前缀依旧是 BLUE IS BLOCK，悬空 AND 可提示但不能让前缀凭空失效。

不要用字符串包含检查假装解析；也不用通用语言引擎。颜色—AND 列表、IS、属性—AND 列表的线性扫描足够。来源中保留每条实际句子的文字 ID / 轴 / 格子，固定碑文保留自己的 sourceId。

### 6.2 固定碑文和属性来源

固定规则采用与移动词同一语法，只读展示在独立的规则板，不占玩家网格。规则的存在必须可见并能追溯，不让 MonoBehaviour 悄悄给某个蓝实例 FLY。

六关只保留必要的显式 `RED IS YOU`；不自动生成 RED IS BLOCK、RED IS FALL 或 ALL IS FALL。其他如 BLUE IS BLOCK、PINK IS WIN 可以按题面设为明确可见的固定句。

文字石位置变化——无论来自水平推、顶起、落地压低、重力还是弹跳——都使规则失效/重建；不能只监听玩家主动推字。派生属性、重力模式和缓存应可从当前位置完整重算。

### 6.3 真正的暂态规则

移动文字可以在下降途中短暂成句，也可以下一格又断句。每次合法原子变化后都解析，并根据第 7 节的固定调度执行后续动作，不人为延长这条规则。

主动作、环境上浮、文字下落之间存在确定的调度顺序，并非现实物理的同时发生。依赖暂态规则的谜题必须记录具体微步和作用对象，不能宣称“所有其他物体都在瞬间完成稳定化”。**本版六关不依赖暂态悬空成句：L02 的 WIN 最终落稳在句子里。**

### 6.4 唯一胜利谓词

```text
存在 a,b：
  a.id != b.id
  a 的有效显式属性含 YOU
  b 的有效显式属性含 WIN
  a.cell.x == b.cell.x
  a.cell.y == b.cell.y
  a.cell.z == b.cell.z
```

不比较模型包围盒、Collider 接触、距离容差、面邻接、同平面距离或屏幕投影。一个实体自己同时有 YOU+WIN 不能与自己配对胜利。`goal` 只是示例里的 ID，不是 Core 的目标特判。

### 6.5 检查时机

每个合法原子位移组及由其产生的规则重算后：**先确认新状态合法，再检查 WIN**。规则刚激活时，若最终位置已合法同格，也立即胜利，不要求再移动一次。

推字的原子组包括玩家走入文字旧格；不能在只移动文字、还没移动玩家的中间状态判胜。载人、顶起、压低同理。非法实体化不得先获胜再掩盖冲突。

命中后保存 `Won{youId,winId,cell,cause}`，停止剩余自动运动。弹跳、下落、上浮或载人经过目标格均有效，不等整回合落稳。表现只播放到该合法终局微步。

六关初态不得已获胜；L02 初态暂时没有有效 WIN 是有意教学，不能被加载器自动补上。

## 7. 确定性结算、世界重力与事务

### 7.1 不用物理引擎决定规则结果

刚体、碰撞回调、FixedUpdate、动画时长都不决定格子位置、是否落地、句子成立或通关。逻辑先产生有序结果，表现再播放。

一次命令的输入前状态是撤销边界；里面可以发生多次落字、规则重算和弹跳，但最后只有一条 Undo 记录。以下调度是本项目的离散设计选择，不声称模拟真实连续力学。

### 7.2 整条命令

```text
S0：合法可操作状态（Grounded 或 BounceApex）
  1. 检查版本、终态、输入阶段；在候选副本上规划动作。
  2. 原子组不合法 → Rejected；原世界、其他顶点、历史全部不变。
  3. 确认动作被接受，记录本命令开始前已有的非玩家顶点待恢复。
  4. 应用玩家水平/推字/起跳/顶起/顶点侧移原子组。
  5. 重算规则与默认来源 → 校验 → WIN；命中立即终止。
  6. 完成玩家主动作段的必要下降/接触/三格弹跳。
     普通跳没有可操控顶点；新 BounceApex 暂停。
  7. 执行环境结算段，直到稳定、待决策顶点或合法胜利。
  8. 成功提交候选世界、S0 历史与事件轨迹。
```

副本内部的每次 commit 都是合法原子变化检查点，不是对外提交一半世界。后续遇到规则冲突/不支持交互/循环时回滚本命令，丢弃其临时 Won/移动/动画事件，给出诊断。已经命中合法 Won 时则正常终止，不再模拟它之后本来可能发生的事件。

### 7.3 逐格动作与环境调度

主动作段优先完成玩家的有限下落/弹跳轨迹，逐格解析和判胜。环境对象不会在普通跳的半途中由于帧率抢先更新。被顶起的普通词会在随后的环境结算中恢复下落，而不是被永久挂住。

环境反复执行固定顺序：

1. **Up 阶段**：按 Y 降序、同高按稳定 ID，检查当前仍为 Up、非 anchored、非暂停顶点、非强制下降的实体；每个实体每轮最多上移一格。符合载人条件时形成整组。
2. **Down 阶段**：按 Y 升序、同高按稳定 ID，检查当前默认 Down 或需要恢复强制下降的实体；沿列逐格下降，每格 commit、解析、校验、WIN，直到承托、模式不再需要下降或生成新顶点。后一个对象不读取一份已经过期的属性。
3. 还有变化则再次从 Up 阶段开始；无变化且 YOU 位于 Grounded/BounceApex 则结束。

每段必须重新读取当前对象、属性与占位，不能因为它在本轮列表中就继续用旧模式运动。不要遍历 Dictionary 时直接凭偶然顺序处理整个世界。

这是顺序微步模型，而非所有物体同一时刻同步一步。更换为并行重力会改变暂态规则与接触时机，属于规则版本变化，不能只当性能优化。首批地图避免多个动态群同时相向争用；复杂冲突不在有限参考模型的验证范围内。

### 7.4 普通重力和支撑

无特殊属性的颜色、空心目标和可动文字都执行 Down；不能按种类漏掉 Text。锁定文字/地形固定，HOVER 不自动移动，FLY 常态向上。

接触需要记录这段下降是否真的出现 -Y 位移。没有新下降的稳定对象，不生成新的落地冲击。被 JUMP 弹起后恢复的强制下降忽略常态模式直到该有限接触段结束；新顶点只等待下一条有效命令。

玩家静止站在下降支撑上时，应在同一事务里随空出的空间下落到新承托位置；是否产生落地接触按真实位移与接触变化记录，不能用渲染器的插值计算。六关不使用下降中的载人弹跳平台；扩展时需补充相对接触判定，不能凭旧示例宣称支持。

### 7.5 FLY 承运

BLOCK＋FLY 平台可携带直接位于其上方、确实站稳、非 BounceApex/强制下降中的 YOU。平台、乘客的全部目的格先检查再原子上移一格；乘客头顶被挡则整组停止，不挤压、不穿顶、不把乘客留在原位。

P0 不携带箱塔和普通文字，不把同色平台当联动刚体。其他位于上方的实体按普通碰撞使该平台受阻；两个同色平台各自结算，L05 有前后两台不同的停止条件。

玩家离开后，平台仍具有 FLY；它可以继续上升到自身受阻。原型不能靠“玩家下车后停止脚本”偷偷把 FLY 关闭。

### 7.6 防循环与支持范围

默认重力下文字会移动并改变规则，同时存在 Up/Down，不能再用 v0.1 的“只下降所以必定终止”论证。需要重复状态检测和防御微步上限。

循环签名至少包含：规范化实体位置、锁定状态、活动运动阶段、待恢复下降/顶点、此次下压消费记录以及必要的调度位置；不包含不断增加的日志编号、相机或动画时间。只有位置相同还不足以判断相同状态。

建议小图硬上限以可配置的 4096 个原子变化起步，并提供关卡 ID、指令、规则、最近轨迹；这不是玩家可利用的规则或步数限制。超过上限/重复循环回滚本命令并标为模拟诊断，不能冻结编辑器。

当前只支持一个可操控实体。若规则变化产生零个或多个 YOU、不可解释的实体化同格，P0 以明确 Unsupported/RuleConflict 拒绝整条变化。六关用固定控制句规避这些情况，不做“暂时不能操作也必须等到自己恢复”的高级规则系统。

### 7.7 初始状态

先结构校验，再在临时世界解析全部显式规则、玩家默认实体和世界重力，然后试结算初态。不能先掉落再识别 HOVER，也不能无声沿用旧版文字悬浮。

六关要求：试结算不改变初态、YOU 稳定且初始未获胜。若作者布局会自动落下，编辑器显示结果并阻止按“已稳定六关模板”试玩；可提供“预览稳定化 → 作者明确应用到草稿”的编辑操作，再保存。不要静默改写源文件或等玩家第一次输入才突然坍塌。

## 8. 会话、撤销、重开与事件

### 8.1 完整逻辑快照

保存全部动态实体与稳定 ID、坐标、存活/锁定状态、YOU 运动阶段、非玩家顶点与待下降、起跳/接触信息、终态/胜利记录、回合计数及会影响未来动作的状态。静态关卡可共享只读引用，动态列表和字典必须深拷贝或真正不可变。

有效属性和重力可以从恢复后世界重算；不要把缓存当另一份持久真相。默认 BLOCK 不能粘在失去 YOU 的对象上。恢复后重建占位索引。

一次 Undo 恢复**获胜/移动命令开始之前**，不是退回某个最后微步；因此能同时撤销落字成句、平台移动、塔冠下降和获胜。

### 8.2 会话合同

- Rejected 不计步，不增加历史，不恢复其他实体顶点。
- 接受的原地跳即使回到原坐标也计为一条可撤销命令。
- Won 后暂停世界输入，允许观察、Undo、Restart 和明确 Next。
- Restart 恢复已校验初态，清空游玩历史；首版不撤销 Restart。
- 相机槽属于表现状态，Undo 不强制旋回旧镜头。
- 编辑 Undo/Redo 和试玩 Undo 是两个历史栈。

### 8.3 事件轨迹

建议采用普通不可变事件列表：

```text
Walk / TextPushed / HeadBump / JumpRise
GravityFall / LandingContact / LandingPress
RuleActivated / RuleDeactivated / EffectiveGravityChanged
BounceStarted / BounceStep / BounceApexReached / BounceBlocked
ApexSteer / ApexReleased / FlyOrRide / RideStopped
Won / CommandRejected / SimulationDiagnostic
```

Rule 事件带来源，移动事件带实体 ID、旧/新整数格、原子组 ID 与原因。动画、提示和编辑器回放消费这些事件，不反过来修改世界。

Undo/Restart 可以打断动画；取消旧队列后对齐新快照。用 Presenter 世代号或统一动画任务取消防止旧回调写回 Transform。不以动画完成通知作为逻辑完成依据。

## 9. 核心类型与职责

| 类型 | 职责与关键边界 |
|---|---|
| GridCell / GridBounds | 整数坐标与包含式边界，不依赖 Transform |
| LevelDefinition / EntityDefinition | 版本化初始数据；不含运行缓存、Prefab、独立 PlayerSpawn/Goal 判定 |
| WorldState / OccupancyIndex | 唯一活动状态与多实体格查询 |
| RuleParser / RuleSet / RuleSource | 网格词与固定句解析，保留有效前缀、来源、读取方向 |
| PropertyResolver | 显式属性、YOU 默认实体、世界重力模式的统一推导 |
| CollisionPolicy | 同格、进入、承托三类查询；YOU↔空心双向交互 |
| AtomicMovePlanner | 行走、文字链、顶起、压低、载人的目的格预检 |
| MotionState / LandingContactResolver | 主动跳、真实下降、冲击消费与接触记录 |
| BounceResolver | 三格上升、碰顶、顶点、恢复下降 |
| VerticalResolver | 固定顺序 Up/Down 调度与终止检测，不调用 Physics |
| WinEvaluator | 不同 YOU/WIN 同格，合法 commit 后唯一判胜源 |
| SimulationEngine | 组织完整指令事务和事件，错误时不修改输入状态 |
| GameSession | 当前状态、初始快照、Undo、Restart、终态输入边界 |
| LevelValidator / InitialStateBuilder | 格式、规则、属性组合、支撑、稳定出生等诊断，不宣称证明可解 |
| LevelEditSession | 作者草稿、编辑操作、脏标记、Undo/Redo；不借用玩家推动来画图 |
| UnityLevelSerializer / LevelSource | JSON 边界与运行关卡来源，IO 失败不覆盖有效文档 |
| GamePresenter / WorldView | 模型、文字、目标轮廓、动画；不是规则数据源 |
| CameraSlotsController / InputAdapter | 四槽观察与键到世界方向的映射 |
| TutorialTracker | 观察事件、显示提示，不参与输赢或暗改物理 |
| LevelEditorWindow / SceneGridPainter / PreviewHost | Unity 作者工具及隔离预览，调用同一 Core |

主要契约可采用：

```text
ValidateStructure(level) → ValidationReport
BuildInitialState(level) → Stable / NeedsStabilization / Invalid
ParseRules(world) → RuleSet with sources
ResolveProperties(entity, ruleSet) → EffectiveTraits with origins
TryStep(sourceState, command) → Accepted / Rejected / Unsupported / SimulationError
    + resultingState + orderedEvents + diagnostics
GameSession.TryExecute / Undo / Restart
LevelEditSession.Apply / Undo / Redo
```

命名可按现有工程调整；职责不能向 View 漏出。游戏 Runtime 不应识别某个实体 ID 叫 `player` 或 `goal` 才工作，这两个名字只是附带测试数据的约定。

## 10. 关卡 JSON：唯一持久化数据源

### 10.1 三层对象隔离

```text
磁盘 LevelDefinition
    ↓ 深拷贝
作者 LevelEditSession.Draft
    ↓ 深拷贝＋校验
试玩 GameSession.WorldState
```

试玩的颜色位置、落字结果、顶点和玩家/目标重叠不能写回出生数据。Unity Scene 只保存 Bootstrap、镜头与表现依赖，不再保存另一份手摆关卡真相。

### 10.2 schemaVersion = 5

| 字段 | 定义 |
|---|---|
| schemaVersion | 必须为 5 |
| mechanicsVersion | 必须为 `RP-v0.5`；数据格式版本与玩法语义分别检查 |
| id / title | 稳定关卡 ID 与显示名 |
| bounds | `{ min:{x,y,z}, max:{x,y,z} }`，端点包含 |
| terrain | `[{min:{x,y,z},max:{x,y,z}}, ...]`；轴对齐整格盒取并集 |
| entities | 实体列表；每项含 id、kind、color、token、cell、anchored |
| entities.kind | `Color` 或 `Text` |
| entities.color / token | Color 用 RED/BLUE/PINK，token 空；Text 用合法词，color 空 |
| entities.cell | 身体整数格 `{x,y,z}` |
| entities.anchored | P0 Color 必须 false；Text 可 true，必须有固定视觉 |
| fixedRules | `[{id, tokens:[...]}]`；只读可见碑文，不能被当隐藏组件 |
| options | 当前固定的模式断言，见下表；不是同时支持旧玩法的开关 |
| camera | 初始槽、俯角、四 yaw 与输入映射模式；可另预留焦点/正交尺度配置 |
| tutorial | objective 与三级 hints；不作为胜利条件 |
| referenceSolution | 世界命令数组与预期终态；作者改变地图后须重新验证，不能自动标通过 |

所有 DTO 用普通可序列化字段和对象/列表。文件中不使用 Dictionary、JaggedArray、Unity 对象引用或运行快照。terrain 用显式 BoxData 对象，不能把紧凑六数数组的草稿格式误当成 JsonUtility 已实现支持的最终存档。

本包 `levels/L01.json` 至 `L06.json` 就采用此格式。Python 检查器读取同一批文件，只在内存转换为便于检查的元组，没有另一份独立的地图源。

### 10.3 模式断言

```json
{
  "supportMode": "StrictBelow",
  "jumpMode": "LandingBounce3",
  "bounceRiseCells": 3,
  "decisionMode": "GroundedOrBounceApex",
  "ruleAxes": ["PositiveX", "PositiveZ"],
  "winMode": "DistinctEntitiesSameCell",
  "winCheckMode": "AfterAtomicLogicChange",
  "actionMode": "FourWayMoveInPlaceJumpApexSteer",
  "gravityMode": "WorldDownExceptHoverOrFly",
  "playerBlockMode": "ImplicitFromYou"
}
```

只有这一套受支持值。发现旧 FallRequired / FaceAdjacent / DirectionalJump 等定义应拒绝或进入明确迁移诊断，不提供隐藏兼容模式。

### 10.4 保存与加载

ID 必须唯一稳定；移动不重分配，复制才分配新 ID。保存采用确定顺序，例如 terrain 按范围、实体按 ID，便于 Git diff。字段缺失、未知 token、损坏 JSON、未知版本都需要可读错误，不默默补成“能运行”的默认关。

允许结构合法但尚不可玩的草稿保存；试玩必须通过更严格校验。IO 失败保留草稿和旧文件；先写同目录临时文件再提交替换，捕获权限/路径异常，不宣称所有文件系统操作天然原子。

Runtime 通过 LevelCatalog 中的 TextAsset 引用读关卡，不直接访问 `Assets/...` 或 AssetDatabase。附带 `catalog.json` 是作者数据目录清单；初始化菜单应据此创建 Unity 关卡引用配置，不能要求发布版读取 Editor 工程路径。

### 10.5 旧数据迁移

| 旧字段 / 概念 | 新处理 |
|---|---|
| Explorer / playerSpawn | 改为 Color 实体，由有效 YOU 识别；位置保存在 entity.cell |
| Goal 坐标 | 改为 Color 实体与可见 WIN 规则，不再单独判胜 |
| RED IS BLOCK 基础碑文 | 六关删除；默认来源是 YOU 身份，不是替换成隐藏碑文 |
| RED IS FALL / BLUE IS FALL | FALL 已移除；不能保留无效果语句冒充兼容 |
| 普通无 FALL 的悬空物 | 需要实际支撑或明确 HOVER；旧高度不能静默保留 |
| PUSH / Pull / 自动攀爬 / JE 等 | 不映射为新动作；旧回放失效 |
| 动态文字无重力 | 全部迁移为 Down，锁定必须是可见的 anchored |
| 同格实体唯一索引 | 替换为多 ID 索引与成对交互 |
| 旧六关参考路径 | 重新运行新模型和 C#，不是改一个版本号即可通过 |

不要直接对整个用户资产目录执行破坏性迁移。可以保留旧文件到 archive，把新关写入明确新目录；实施状态列出哪些旧脚本/资源不再参与运行。

## 11. 关卡编辑器设计与预留

### 11.1 技术与交互分开

采用 **IMGUI EditorWindow 的工具界面＋类 Tilemap 的按 Y 层绘制交互**。这不是二选一：IMGUI 决定窗口如何实现，切片网格决定作者如何画关卡。

沿用后续关卡稿的 SceneView 三维观察/绘图方向；二维 XZ 切片是稳定的精确编辑入口。SceneView、窗口、预览都调用同一 LevelEditSession，不能各留一套独立布局。

若工程已有基于 PreviewRenderUtility 的隔离预览可以复用；否则 PreviewHost 管理专用预览资源与临时对象，不为了本原型同时维护两套昂贵渲染实现。核心要求是清楚的切片绘制、四镜头观察与**不污染作者现有场景**。SceneView 的点击也必须落到当前 Y 平面，而不是误写被遮挡的上层物体。

### 11.2 窗口布局

```text
New | Open | Save | Save As | Edit Undo/Redo | Validate | Playtest / Stop
关卡 ID / 标题 / 边界 / 当前 Y / 画笔 / 固定规则

左：XZ 切片＋上下层淡显      右：三维观察、四槽、选中轮廓
底：同格实体列表 / 属性来源 / 规则 / 支撑与重力诊断 / 回放事件
```

Terrain、Color、Text、FixedRulePanel 是不同作者操作。玩家由 Color＋YOU 识别；不再有独立 Spawn/Goal 画笔偷偷创建非规则对象。可以提供“创建玩家/空心目标”快捷模板，但它们必须产生正常颜色实体和可见规则数据。

### 11.3 P0 作者操作

新建、打开、保存/另存、切 Y、单格放置/擦除、选中与移动实体、修改词/颜色/锁定、编辑固定句、修改边界、四镜头预览、校验、隔离试玩、读取参考命令、编辑 Undo/Redo。

同格选择必须列出所有 ID，不能因为玩家遮住空心目标就无法选择目标。地形擦除与实体擦除分层；Resize 不可静默裁掉越界对象。一次拖刷作为一个编辑历史步骤。

画笔不受玩家移动规则限制：即使当前没有 BLUE IS BLOCK，作者也能搬动蓝实例。暂时不完整的草稿可以显示，不能要求先成为合法 GameSession 才能看见布局。

### 11.4 必须提供的诊断

| 面板 | 最低行为 |
|---|---|
| 属性来源 | 区分显式 BLOCK、YOU 默认实体、世界 Down、HOVER、FLY、anchored；不展示假的 FALL 句 |
| 规则 | 列出有效句、读取轴、前缀/未连接词、固定/可动来源；点击定位 |
| 重力/支撑 | 哪些物体无支撑会落下，悬停来源是什么，文字落到哪一层；基于 Core 预演 |
| 目标 | 只高亮 WIN 自身格；可进入性、下方承托、同高入口；删除六个邻格获胜预览 |
| 顶起/下压 | 预览真实结果；明确“该字会落回”“下方实体阻挡不能压”，不虚构持久悬停 |
| 弹跳 | 接触格、三格逐格路径、碰顶位置、顶点一次侧移出口 |
| FLY | 平台与乘客整组净空、停止高度，AND 所在句子的支撑是否稳定 |
| 回放 | 世界命令、阶段、规则变化、终局原因；至少可看事件列表和逐指令结果 |

局部候选入口不等于完整路径可达，编辑器不得仅因目标旁有空格就显示“已验证可解”。六关中的先天无 WIN（L02）要作为明确作者意图提示，而不是自动修复。

### 11.5 编辑与试玩隔离

编辑草稿 → 完整校验 → 深拷贝创建 GameSession → 锁定作者绘制 → 使用同一个 SimulationEngine 试玩 → Stop 丢弃会话 → 返回未被改变的草稿。

可以在编辑器工具内模拟，无须每次切 Unity Play Mode，但不能把它当作实际 Runtime 场景验收。没有按 Save，停止试玩绝不写回文件；通关状态不能被误保存为下一次出生点。

### 11.6 草稿保护

脏标记根据保存修订点或内容比较；撤销回保存状态可以清除脏标记。New/Open/Close 遇到脏文档提供 Save / Discard / Cancel。

脚本重载时可用 SessionState 暂存草稿 JSON、源路径、当前层；它只保护编辑器会话，不代替磁盘存档。重载后可丢弃试玩动画和编辑历史，但要恢复草稿并说明历史重置。临时预览对象、相机、材质与渲染资源必须正确清理。

### 11.7 校验分级

**结构错误：**未知版本/模式/词、无效边界、重复 ID、缺少必填字段、实体在 Terrain 内、非法 kind/color/token、Color 偷设 anchored、损坏固定句。阻止作为正式关卡导出/试玩。

**试玩前错误：**初态无或多 YOU、玩家不稳定、自动结算会改变六关初态、初始已获胜、非法实体组合、首批目标有 BLOCK、初始自动循环、参考命令含旧定向跳。结构合法的未完成草稿仍可保存。

**设计警告：**某词顶起后必落回、目标暂未激活、HOVER 被 FLY 覆盖、句子部分无效、过多遮挡、超大地图、关键参考解过期、可能存在不使用机制的路线。普通校验不证明唯一解或无死锁。

### 11.8 运行时编辑器预留

LevelDefinition、LevelEditSession、编辑命令、Validator、规则预览和 GameSession 放在不依赖 UnityEditor 的层。未来只替换 UI、文件浏览器和 PreviewHost；不预做云端关卡库、账号、多人协作或一套通用编辑器引擎。

## 12. 四视角、目标表现与玩家引导

### 12.1 四槽镜头

四个正交斜视角，相差 90°，建议起始 yaw 45/135/225/315°、俯角约 35.264°。这些是本项目的构图起点，不是对参考游戏内部镜头参数的断言。每关可设置焦点和正交尺度；切镜头不改变规则/回合/顶点。

| 槽位 | W | D | S | A |
|---|---|---|---|---|
| 0 | +Z | +X | -Z | -X |
| 1 | +X | -Z | -X | +Z |
| 2 | -Z | -X | +Z | +X |
| 3 | -X | +Z | +X | -Z |

Unity 相机绕轴的实际正负、LookAt 和按键映射要在真实场景逐槽验收；世界回放不依赖上述键名。方向提示画在脚下网格四边，避免让玩家以为能走任意屏幕八方向。相机过渡期间暂不收世界移动，新槽生效后再映射。

### 12.2 目标与属性表现

无 BLOCK 颜色对象呈空心轮廓；有 WIN 时点亮内部和边框，让实心玩家“填入”目标。未激活轮廓可以进入但不播放完成效果。碰到外壳、停在邻格不显示完成，不自动吸附补一步。

有 BLOCK 的非玩家物体显示实体表面；HOVER 表示原位悬停、FLY 表示上浮，两者有不同的方向符号。JUMP 上表面有清晰弹跳标志，不把它画成主动跳起的角色。

文字标签可以朝相机，但句子来源连线固定于世界网格。用 R/B/P 及纹理/形状辅助颜色识别。Collider 可用于鼠标选取，不能作为独立碰撞或胜利源。

### 12.3 最小 HUD 与教学

显示关卡名、当前阶段、基础输入、显式规则、最近拒绝原因、Undo/Restart、终局；调试展开实体位置和属性来源。默认行为只在第一次说明和检视面板提示，不用冗余碑文占满场景。

每关三级提示：先指出对象/关系，再解释规则，最后给明确操作。依据事件或玩家主动查看推进，不靠计时催促。提示和教学事件不能成为隐藏胜利条件；正确替代解也应获胜。

## 13. 六关灰盒：新规则下的教学链

以下为**新机制下的六个可复建灰盒初稿**。坐标来自配套 `levels/*.json`；每关一条参考路径已经在有限 Python 设计模型回放，结果文件与脚本见配套包。不是 Unity 实机地图，也未证明最短解、唯一解或必须按全部预设教学步骤通过。

主题顺序：**进入目标 → 落字成句 → 解除悬停 → 三格弹跳 → AND＋载人上浮 → 两次弹跳＋让目标下降。**不再要求前两关教完所有基本接触动作。

本节坐标与地形盒均含端点；地形盒写作 `min → max`。Terrain 盒重叠取并集；未列出位置为空。锁定文字必须显示固定安装，不允许把这些挂在场边的只读构件伪装成免重力可动词。E/W/N/S 是世界 +X/-X/+Z/-Z，J 是原地跳，不是键名。

### 13.1 L01｜填入那个位置

**教学目标：**首先建立“填入空心轮廓”而不是碰到外壳的完成语言。中墙迫使同高绕行，四视角有助观察但不是通关条件。

**关键检查：**站在 `(3,1,1)` 与目标面邻接仍 Running；进入 `(4,1,1)` 才 Won。没有跳跃教学、没有一格高出口，也不检查是否按过相机键。

**引导重点：**第一提示指向目标内部；撞墙再提示观察另一面。不要用目标旁的脚印或平台外壳播放完成特效。

**防误设计：**不要补一条自动吸附或邻接胜利来掩盖输入映射问题。替代绕行路线可以接受。

**数据文件：**`levels/L01.json`。**边界：**`(0,0,0) → (5,6,3)`。

**固定可见句：**`RED IS YOU`；`PINK IS WIN`。

**静态地形盒：**

```text
(0,0,0) → (5,0,3)
(2,1,0) → (2,3,1)
```

| ID | 类型 / 颜色或词 | 身体格 | 固定 |
|---|---|---|---|
| `player` | 颜色 RED | `(0,1,1)` | 否 |
| `goal` | 颜色 PINK | `(4,1,1)` | 否 |

**参考指令：**`E N E E S E`。

| 步骤 | 世界指令 | YOU 结果格 | 结果阶段 |
|---:|---|---|---|
| 1 | `E` | `(1,1,1)` | Grounded |
| 2 | `N` | `(1,1,2)` | Grounded |
| 3 | `E` | `(2,1,2)` | Grounded |
| 4 | `E` | `(3,1,2)` | Grounded |
| 5 | `S` | `(3,1,1)` | Grounded |
| 6 | `E` | `(4,1,1)` | Won |

**三级提示文本：**

1. 进入发光轮廓。
2. 中墙后面留有同高通道。
3. 绕到目标同高处，再走进目标格。



### 13.2 L02｜让文字落进句子

**教学目标：**文字也受默认重力。把上层 WIN 推出台沿，它在本命令中落入下层的 `PINK IS [ ]`，使目标激活。

**关键因果：**WIN 从 `(4,2,2)` 推至 `(4,2,3)`，继而掉到有地基支撑的 `(4,1,3)`；此时句子持续成立，不依赖暂态悬空或隐藏锁字。玩家随后可以从上层踩到这个文字顶部，再向旁边走下到目标高度。

**引导重点：**同时高亮落字列与下层空槽，让玩家理解是世界中的高度变化，而不是屏幕投影拼字。只有落稳的规则点亮目标；PINK 初态无 WIN，可以进入但不能获胜。

**防误设计：**不要在 `(4,1,3)` 补实心 Terrain，否则 WIN 无法落入该格；它的支撑是 `(4,0,3)`。不要把本关改回“顶起 WIN 后停空中”。本关没有使用原地跳跃，允许玩家先学较简单的规则改写。

**数据文件：**`levels/L02.json`。**边界：**`(0,0,0) → (7,6,4)`。

**固定可见句：**`RED IS YOU`。

**静态地形盒：**

```text
(0,0,0) → (7,0,4)
(4,1,1) → (4,1,2)
```

| ID | 类型 / 颜色或词 | 身体格 | 固定 |
|---|---|---|---|
| `player` | 颜色 RED | `(4,2,1)` | 否 |
| `goal` | 颜色 PINK | `(6,1,3)` | 否 |
| `t_pink` | 文字 PINK | `(2,1,3)` | 是 |
| `t_is` | 文字 IS | `(3,1,3)` | 是 |
| `t_win` | 文字 WIN | `(4,2,2)` | 否 |

**参考指令：**`N N E E`。

| 步骤 | 世界指令 | YOU 结果格 | 结果阶段 |
|---:|---|---|---|
| 1 | `N` | `(4,2,2)` | Grounded |
| 2 | `N` | `(4,2,3)` | Grounded |
| 3 | `E` | `(5,1,3)` | Grounded |
| 4 | `E` | `(6,1,3)` | Won |

**三级提示文本：**

6. 编辑器改一个支撑/词位置、保存、关闭重开、试玩、Undo、Stop；文件与草稿都保持作者版，不被残局污染。
7. 尝试不稳定初态、旧 FALL 词和错误版本，得到明确错误，不加载隐藏默认关卡。
8. 具备构建环境时，确认独立程序能加载六关、输入方向正确、无 Editor-only 依赖；否则如实记录未构建原因。

## 16. Codex 工程实施约束与交付

### 16.1 先审查而不是全盘重建

识别现有的 Explorer/Goal、PUSH/PULL、FALL 标签、无重力文字、单格 Entity 字典、自动登阶、旧胜利条件及玩家特殊 Rigidbody；列出需要替换的来源。

只保留一条活动逻辑入口。不能在新版 Core 外仍由旧 PlayerController 在 Update 施加重力，也不能让旧 GoalTrigger 碰到玩家就获胜。Scene/Prefab 中的旧脚本引用要一并检查，不能只改 C# 文件。

保留用户原素材、场景、包与工程约定。需要迁移时给出明确路径和状态，不无提示删除或覆盖非生成资源。

### 16.2 初始化入口

提供 `Tools/RulePyramid/Create or Repair Prototype`，以编辑器 API 创建/修复本原型管理的场景、基础材质、表现配置与 TextAsset 关卡清单，重复执行应安全。

不要手写猜测 GUID 的 Unity YAML，也不要清空 Build Settings；需要加入场景采用增量操作。未经 Unity 实际创建/验证，不得宣称场景“打开即玩”。没有现有可执行 Unity 环境时，先交付可导入代码与唯一初始化步骤，并注明未验证项。

### 16.3 代码纪律

- 模拟位置和属性不从对象名称、Transform、Collider 或画面颜色反向猜测。
- 一次原子组先预检再提交，不能把规则扫描塞进每个 BlockView 的 Update。
- 同一关卡可以同时拥有编辑草稿、试玩与测试会话；不使用全局可变世界单例。
- 属性来源集中：显式规则、YOU 默认实体、世界 Down、固定约束；不散落 PlayerController 特判。
- 命令、快照、事件为纯数据；不要为实现撤销反向播放物理动画。
- IO、JSON、模拟拒绝、不支持范围、内部错误分别报告；禁止空 catch 和假成功。
- 小地图优先整关扫描与完整快照；不为尚不存在的大型世界先上性能架构。

## 17. 后续扩展：现在预留什么

| 后续方向 | 当前预留 | 当前不做 |
|---|---|---|
| 边缘支撑 | `ISupportPolicy`，明确当前 StrictBelow；新策略需要新 mechanicsVersion 与独立测试关 | 不给六关偷偷启用边角承托，不声称已复刻其他游戏 |

| 更多文字 | Parser / PropertyResolver / RuleSource 集中 | 不预做通用 DSL、TEXT、NOT、递归或对象变形 |
| 完整金字塔 | 关卡数据独立于场景、镜头按关配置 | 不做四面连续大地图、流式世界和寻路系统 |
| 运行时编辑器 | 草稿、编辑命令、校验和试玩核心无 UnityEditor 依赖 | 不做云同步、账号和关卡市场 |

核心原则仍是：**预留可替换的边界，不提前实现所有可能性。**
