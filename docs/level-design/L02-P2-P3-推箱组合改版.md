## 1. 定位与目的

| 阶段 | 学习目的 | 加入的经典空间问题 | 可观察成功行为 |
|---|---|---|---|
| P1 | 复核已理解真实下落触发 BOUNCY、顶点侧移与世界成句 | 不改图 | 玩家能解释弹性来自句子，并使用弹跳 |
| P2 | 先保留仍有用途的能力，再把它转给目标位置的另一物种 | 先取后拆、临时让位、绕到另一推动侧 | 取回 ROCK 词牌后替换 SPRING 主语，让唯一 BOUNCY 作用于 ROCK，以 ROBOT 获胜 |
| P3 | 同一种推动方法，换一个位于合适位置的执行者 | 预先摆词、推动侧不可达、换控接力 | ROBOT 准备词牌，合法交接 YOU，ROCK 从远端完成最后一推并借弹性获胜 |

前置知识沿用 L01 的推动词牌、拆句/组句、STOP/WIN 和 Z 撤销；弹跳由 P1 提供。ROCK IS PUSH 虽在当前地图存在，首版方案不依赖玩家掌握搬动普通箱子；普通 ROCK 的位置主要用于承载弹跳与控制交接。

预计难度由决策依赖增加：P2 两个相关决策（何时拆、怎样换入），P3 三个相关决策（准备什么、何时换控、从哪侧推）。不以增加行走步数、词牌数量或精确空中操作作为难度目标。体验时长作为盲测记录，不预设硬性指标。

### 2.2 P2 具体改动：先取回，再换入

采用“换主语”把弹性从 SPRING 转给 ROCK，保留当前高台上的 ROCK 词牌作为有用途的取物目标。与旧卡搬运 BOUNCY 的方法相比，这仍检验同一属性作用于不同物种，也能充分利用现有高台。

| 对象/空间 | 计划改动 | 用途与约束 |
|---|---|---|
| ROBOT / 两处弹跳点 / FLAG | 优先保留当前出生与物件坐标；出生周围工作区不得占住(8,3,4) | 保持旧弹跳点通往取词台，新 ROCK 弹跳点通往最终旗台 |
| SPRING IS BOUNCY | 保持初态完整，位于中层可读工作台；保留同一套3块词牌ID | 必须先用旧弹性拿到 ROCK，再拆旧句 |
| 高台 ROCK 词牌 | 保留高台取词关系；可局部调整其落词口位置 | 玩家通过旧 SPRING 到达高台，推词牌从投递口落至中层收件位；有独立安全回落路线 |
| 投递口 | 加/改一个有底部支撑的中层收件位，避开弹跳竖井和源词区 | ROCK 词牌与玩家都能返回工作区；不能落成无法回收的低层死角 |
| 旧 SPRING 主语 | 在句首旁设置1格暂存位与推动侧 | 先移走 SPRING 腾出句首，保留能回收的侧向空间；不要求来回多次搬运 |
| 换入路线 | 用一个短 Terrain 隔断组织共用通道和一条绕行路 | ROCK 词牌需在转向位停一次，人绕到另一侧后推进句首；暂存词牌不得堵死唯一推位 |
| ROCK IS PUSH 源句 | 首版保留，不新增 STOP/AND 句 | PUSH 已提供实体支撑；获得 BOUNCY 后可作为弹台。仍要检查玩家是否能移动 ROCK 绕解 |
| 唯一 BOUNCY | 继续只保留一块 | 禁止同时保留两条独立的有效弹性句而消解“先取后拆” |

关键状态链：

1. 旧 SPRING 有弹性；新 ROCK 没有弹性，目标台在 ROCK 路线末端。
2. 借旧 SPRING 登上取词台，把 ROCK 词牌送到中层，玩家安全返回。
3. 将旧句的 SPRING 主语暂存，旧弹性失效；这一步不能让取回的 ROCK 失去搬运通路。
4. 利用转向位与绕行路，从正确一侧推 ROCK 入句，形成 ROCK IS BOUNCY。
5. ROBOT 从中层落到普通 ROCK 顶部，弹上目标台获胜。

两个必须成立的因果：先拆旧句会失去高台取词手段；随手直推 ROCK 不能完成换入，至少需要一次改变推动侧。失败应在短距离内显露，允许通过Z恢复。

### 2.3 P3 具体改动：准备词牌，交给另一侧的 YOU

本版保留远端 ROCK 的高台初始站位，不再要求机器人先搬 ROCK 到远端；否则会同时引入普通物件搬运与复杂交接。经典推箱的预先摆位由 BOUNCY 词牌承担。

| 对象/空间 | 计划改动 | 用途与约束 |
|---|---|---|
| ROBOT | 优先保留中层出生(8,3,5)，朝向可操作词牌与交接台 | 初次行动仍发生在熟悉操作台 |
| ROCK | 保留远端高台(12,5,5)与单实例数量 | 获得 YOU 后从高台下降到机器人到不了的推动侧 |
| 两个 SPRING | 首版保留当前两处位置；初态均只有 STOP、没有 BOUNCY | 完成同一全图 SPRING IS BOUNCY 后两者同时变弹性；检查较近一只是否产生绕解 |
| SPRING IS BOUNCY | 初态改为待补句；把 BOUNCY 放在可由 ROBOT 准备的收件/暂存位 | 移除当前“开局已有弹性”的捷径，恢复换控后的实际任务 |
| 准备通道 | ROBOT 能把 BOUNCY 推到交接格；最后成句需要从相反一侧推动 | 对机器人而言“词能到、人到不了”；不能由推链从原侧直接拼好 |
| 远端推动侧 | 保留高差并局部补 Terrain 隔断/落脚台，使 ROCK 能从Y=5安全落到Y=3推动侧 | 隔离来自碰撞和高差，不能靠视觉遮挡、无 STOP 的 WALL 栏杆或隐藏限制 |
| ROBOT IS YOU | 把现有控制句移到中层可操作交接台，地面原位不再留另一条 ROBOT IS YOU；保留原实体ID | 修复当前控制句与实际操作区脱节的问题；其他地面源句继续保留 |
| 交接词牌 | 新增一块 ROCK、一块 YOU，与旧句共用一块可推 IS | 一次推 IS 同时拆旧句、成新句；全程至少一个 YOU，不经过必须继续操作的失控态 |
| FLAG | 保留当前最终目标，场内仅一只 FLAG | 最后由 ROCK 借弹性到达；不添加“换控次数”隐藏门槛 |

交接台局部逻辑示意（非全图坐标，X向右，Z向上，所有词牌同层）：

```text
Z+1    ROCK    空格    YOU
Z      ROBOT   IS      YOU
Z-1    空格    人      空格
```

向+Z推中间 IS 后，ROBOT IS YOU 失效，ROCK IS YOU 成立。有效句子仍按+X读取，换控不依赖反向读句。工序3须给该4×3左右局部区域留出进入、预摆和退路，不把示意直接复制到已有占格上。

关键状态链：

1. ROBOT 看见远端 ROCK、缺词的弹性句和没有弹性的两只 SPRING。
2. 在仍有 ROBOT 控制时把 BOUNCY 推到交接格，保留最终推位及新角色落脚点。
3. 到交接台，一次合法推动将 YOU 交给 ROCK。
4. ROCK 从远端高台下降到新的推动侧，完成最后一推，组成 SPRING IS BOUNCY。
5. ROCK 使用弹跳路线到 FLAG；ROBOT 留在原区域。

过早换控的失败须可理解：远端 ROCK 无法代替机器人把尚未送达的词牌送到交接格。第一版只安排这一个顺序约束，不额外叠加长距离多箱死锁。若 ROCK 能直接走向旧机器人区域完成全部准备，必须回修隔断与落脚关系。

### 2.4 继承和阶段初态

- 原组关系保留 P1→P2→P3，P1 本轮不改。先完成并审阅 P2 保存后的继承差异，再落实 P3 独有覆盖，避免按旧子图覆盖新父图。
- 所有差异按右上角编辑坐标比较；实体沿用ID、按字段覆盖。当前相同尺寸X、不同Z深度下，共用位置在P3原始Z通常比P2大3，不能直接复制原始坐标。最终以编辑器实际转换为准。
- P2 的工作台、转向位和安全回路作为共用骨架，允许向P3传播；P3 仅对接力通道、远端落脚、交接台和必要隔断登记局部覆盖。
- 明确覆盖 P3 的 ROBOT/ROCK/SPRING/FLAG 位置、初态 BOUNCY 布局和控制句位置；保持字段粒度，不整体冻结所有实体与地形。
- P3 不继承有效 ROCK IS BOUNCY；若父图新增/移动相关词牌，逐项转换或覆盖，并检查无意多余主语与额外成句。P2独有的可搬ROCK词牌在P3须明确删除覆盖或复用，不能遗留无用途的额外ROCK。
- 物件按阶段作者初态重布；P2怎么解不影响P3起点。旧 FLAG 只保留为各阶段唯一目标，位置按本阶段配置；不按ID禁止获胜。
- 源词、出生、目标、提示、参考解与配置分别核对；新增文案用简短英文，当前75°玩家视角不改。
- 保存继承中出现跳过、冲突、越界时逐条解决；不能将“保存成功”视为整组内容已传播。

## 5. 解题逻辑审查计划

以下均为未验证假设，不能把状态链称作已求解：

- P2：过早拆 SPRING 句是否仍能用普通跳跃、词牌支撑或现有ROCK取得高台词牌；旧SPRING是否可直接到FLAG；能否移动普通ROCK或借推链跳过转向；取词后是否有安全回程。
- P2：两块主语的暂存位是否真的可回收；所有换向都有玩家站位，不能出现“词能过去，人推不到”。
- P3：一直操纵 ROBOT 是否能完成弹性句或直接到FLAG；初始无弹性时是否仍能进入远端推位；普通跳跃、落台与词牌搭桥是否绕过隔断。
- P3：提前换控能否包办全部准备；合法交接是否一次结算完成；原源区是否残留ROBOT IS YOU造成多YOU；新ROCK主语是否意外成句。
- P3：两只SPRING同时获得BOUNCY后的所有入口/落点与捷径；任一较近弹台直接到FLAG是否绕过预期准备。
- 两阶段：全图规则、PUSH带来的推链、STOP改变后的通行与支撑、文字下落/卡角；无STOP的WALL物件不能当硬墙。
- 死锁分为局面内可恢复和需Z/R恢复，失败尽早可见；不得以有撤销为理由容忍无反馈的长程陷阱。
