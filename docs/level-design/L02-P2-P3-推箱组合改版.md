## 1. 定位与目的

| 阶段 | 学习目的 | 加入的经典空间问题 | 可观察成功行为 |
|---|---|---|---|
| P1 | 复核已理解真实下落触发 BOUNCY、顶点侧移与世界成句 | 不改图 | 玩家能解释弹性来自句子，并使用弹跳 |
| P2 | 先保留仍有用途的能力，再把它转给目标位置的另一物种 | 先取后拆、临时让位、绕到另一推动侧 | 取回 ROCK 词牌后替换 SPRING 主语，让唯一 BOUNCY 作用于 ROCK，以 ROBOT 获胜 |
| P3 | 同一种推动方法，换一个位于合适位置的执行者 | 预先摆词、推动侧不可达、换控接力 | ROBOT准备词牌，合法交接YOU，ROCK完成最后一推使五只SPRING同时生效，再沿新增弹跳路线获胜 |

前置知识沿用 L01 的推动词牌、拆句/组句、STOP/WIN 和 Z 撤销；弹跳由 P1 提供。ROCK IS PUSH 虽在当前地图存在，首版方案不依赖玩家掌握搬动普通箱子；普通 ROCK 的位置主要用于承载弹跳与控制交接。

预计难度由决策依赖增加：P2 两个相关决策（何时拆、怎样换入），P3 三个相关决策（准备什么、何时换控、从哪侧推）。不以增加行走步数、词牌数量或精确空中操作作为难度目标。体验时长作为盲测记录，不预设硬性指标。

### 2.2 P2 具体改动：先取回，再换入

采用“换主语”把弹性从 SPRING 转给 ROCK，保留当前高台上的 ROCK 词牌作为有用途的取物目标。与旧卡搬运 BOUNCY 的方法相比，这仍检验同一属性作用于不同物种，也能充分利用现有高台。

| 对象/空间 | 计划改动 | 用途与约束 |
|---|---|---|
| ROBOT / 两处弹跳点 / FLAG | 优先保留当前出生与物件坐标；出生周围工作区不得占住(8,3,4) | 保持旧弹跳点通往取词台，新 ROCK 弹跳点通往最终旗台 |
| SPRING IS BOUNCY | 保持初态完整，位于中层可读工作台；保留同一套3块词牌ID | 必须先用旧弹性拿到 ROCK，再拆旧句 |
| 高台 ROCK 词牌 | 保留高台取词关系；可局部调整其落词口位置 | 玩家通过旧 SPRING 到达高台，推词牌从投递口落至中层收件位；有独立安全回落路线 |
| 投递口 | 加/改一个有底部支撑的中层收件位，避开弹跳竖井和源词区 | ROCK 词牌与玩家都能返回工作区；不能落成无法回收的低层死角 |
| 旧 SPRING 主语 | 在句首旁设置1格暂存位与推动侧 | 先移走 SPRING 腾出句首，保留能回收的侧向空间；不要求来回多次搬运 |
| 换入路线 | 用一个短 Terrain 隔断组织共用通道和一条绕行路 | ROCK 词牌需在转向位停一次，人绕到另一侧后推进句首；暂存词牌不得堵死唯一推位 |
| ROCK IS PUSH 源句 | 首版保留，不新增 STOP/AND 句 | PUSH 已提供实体支撑；获得 BOUNCY 后可作为弹台。仍要检查玩家是否能移动 ROCK 绕解 |
| 唯一 BOUNCY | 继续只保留一块 | 禁止同时保留两条独立的有效弹性句而消解“先取后拆” |

关键状态链：

1. 旧 SPRING 有弹性；新 ROCK 没有弹性，目标台在 ROCK 路线末端。
2. 借旧 SPRING 登上取词台，把 ROCK 词牌送到中层，玩家安全返回。
3. 将旧句的 SPRING 主语暂存，旧弹性失效；这一步不能让取回的 ROCK 失去搬运通路。
4. 利用转向位与绕行路，从正确一侧推 ROCK 入句，形成 ROCK IS BOUNCY。
5. ROBOT 从中层落到普通 ROCK 顶部，弹上目标台获胜。

两个必须成立的因果：先拆旧句会失去高台取词手段；随手直推 ROCK 不能完成换入，至少需要一次改变推动侧。失败应在短距离内显露，允许通过Z恢复。

### 2.3 P3 具体改动：先完成接力，再启用现有弹跳路线

v0.1中“两只SPRING”的方案失效。本版保留用户新增的五弹簧、落脚台和旗台挡墙，主要重做中层词牌工作区。P3体验顺序改为“准备 → 换控 → 启用弹性 → 连续弹跳收尾”。

#### 保留清单

| 内容 | 本轮计划 |
|---|---|
| 地图与出生 | 保持15×6×14；优先保留ROBOT=(8,3,5)、ROCK=(12,5,5)、FLAG=(13,5,11) |
| 5只SPRING | 全部保留现有位置和现有ID，包含用户新加的三只一排；不移回旧二弹台版本 |
| 中间落脚台 | 保留原始(12…14,4,8)，对应角色站位Y=5；作为进入横排弹簧前的观察和准备位置 |
| 旗台挡墙 | 保留原始(12,5,10…12)，避免从西侧弹台直接向东进旗台；不拆墙缩短路线 |
| 全局规则 | SPRING IS STOP、FLAG IS WIN、ROCK IS PUSH继续成立；所有SPRING共用弹性状态，不给某只加隐藏例外 |

#### 新改动清单

| 内容 | 具体改动与目的 |
|---|---|
| 当前SPRING IS BOUNCY | 保留SPRING/IS的工作台关系，把BOUNCY从句尾(9,3,7)移出，改为需要先整理的可推词牌；初态五只SPRING均无弹性 |
| 暂存与转向 | 中层局部增加一个暂存位、一个转向格和一条回身路。ROBOT先把词牌推离直线目标方向，绕到另一侧，再送至接力位置；只做一次短换向，不加入多箱排序 |
| 最后一推 | 最终拼句的推动侧由远端ROCK进入；ROBOT可以完成前置摆位，但不能独自完成同等操作。首选复用ROCK高台的下降口，并局部增加有支撑的接力落脚面；实际坐标在原型中验证 |
| 控制交接台 | 将原ROBOT IS YOU三词保留ID移到中层可达区，移除原地面的同一有效句；配置相邻ROCK / YOU词位，一次推动共用IS完成控制转移 |
| 启动后的返程 | ROCK完成最后一推后必须能回到(11,1,6)的落入入口，再借它返回上层，继续使用用户新增落脚台与横排弹簧。不能为了最后推位把ROCK关在无出口的小室 |
| 目标前路线 | 保留原始X=13/14的进入空间，允许在三只一排中选可行入口；避免把这段做成连续精确空中操作考试 |

接力区的拓扑预算仍优先使用中层约5×7格工作区；原型需证明转向、双方推位与ROCK返程同时成立。投递口不能占据任一弹簧上升列，新增墙体不能堵住新落脚台。仅画一堵墙不等于ROBOT到不了另一侧：词牌作为可推实体与人具有相近通行需求，必须逐格检验玩家能否跟随词牌绕过隔离。若几何关系不成立，先回修局部接力区，而不是破坏用户新增五弹簧结构。

控制台仍采用下列局部关系，具体落位待原型：

```text
Z+1    ROCK    空格    YOU
Z      ROBOT   IS      YOU
Z-1    空格    人      空格
```

向+Z推中间IS，同一结算拆掉ROBOT IS YOU并组成ROCK IS YOU。整图仅一个ROCK，因此本段保持单对象控制。P2的可搬ROCK词牌若被继承，可复用于交接台；仅在需要时新增，不留下多余主语。

#### 新关键状态链

1. 初态五只SPRING无弹性。ROBOT能看见完整弹跳路线，但不能直接重放当前11步路线通关。
2. ROBOT在中层完成一次暂存/换向，把BOUNCY送到接力位置；交接台仍保持可达。
3. 推IS，把YOU交给高台上的ROCK；原机器人留在工作区。
4. ROCK从另一侧完成最后推词，组成SPRING IS BOUNCY，五只同时生效。
5. ROCK返回近端落入入口，利用(11,1,6)弹回高台，走到(12…14,5,8)的新落脚面。
6. 由落脚面进入Z=9的横排弹簧，在X=13或14一侧弹到旗台；原始X=12的挡墙继续影响落点选择，最后由ROCK接触FLAG。

三只横排弹簧承担容错落入区；(11,1,11)那只位于旗台西侧，受新挡墙限制，提供可观察的路线对照。暂不强求每只都成为必经步骤，更不要求“踩满五只”才能胜利；若盲测显示西侧弹簧只有误导作用，再单独评估其位置或存在必要性。

提前换控时，ROCK不应能包办尚未完成的ROBOT预摆；开启弹性后，ROCK必须有可达返程。上述两点与“ROBOT无法自己完成最后一推”是原型最优先的三项可行性检查，目前均未验证。
