# Rule Pyramid Prototype-v0.5 支持包

## 内容与使用

`RulePyramid_Prototype_Codex_v0.5.md` 是本版完整实施合同。将它复制为项目的 `docs/PROTOTYPE_SPEC.md`，替换旧 Prototype-v0.1 与 LD-v0.4 的活动入口，旧资料可归档。

`levels/L01.json` 至 `L06.json` 是新规则下的唯一关卡数据源，`catalog.json` 提供作者目录清单。复制到 Unity 内容目录后，由 Codex 实现的初始化菜单建立 TextAsset 关卡引用；发布版不应直接依赖 Assets 文件路径。

当前规则：YOU 默认实体；可动颜色、空心目标、文字默认 Down；只有 HOVER / FLY 改变常态重力；没有可拼 FALL。胜利是不同 YOU/WIN 同格，没有邻接兜底。地面只走四向或原地跳，JUMP 弹跳顶点才能侧移一次。

六关为：填入那个位置、让文字落进句子、撤掉例外桥才落下、落下去弹上来、让脚下成为电梯、借两次落差迎回塔冠。

## 运行设计检查

使用 Python 3.10 或更新的兼容 Python，标准库即可；不需要 Unity 或第三方包：

```sh
python reference_check.py --output validation_results.json
```

脚本读取包内同一份 JSON。它只在指定 `--output` 时写生成报告，不修改关卡源。请勿使用 `python -O`，因为检查依赖断言。

本包附有此次运行的 `validation_results.json`：六条参考路径和 24 项针对性检查通过。包括初态稳定、参考解最终获胜、获胜后撤销、反转实体列表后的相同获胜记录。

## 重要边界

这是实施规格和设计见证数据，不是 Unity 项目。没有交付或验证 Unity Scene、C# 游戏代码、编辑器、实际输入、镜头、动画和构建。Python 脚本不是完整游戏引擎、穷举求解器或 Unity 可用性的替代证明。

见证模型对 ID 使用 player/goal 作为样例约定。Unity Core 应从 YOU/WIN 属性识别对象，不能照抄 ID 特判。模型支持当前路径与有限检查使用的离散规则子集；完整 C# 必须补齐规格第 14.3 节的错误处理、边界交互、一般输入与编辑器测试。

对尚未定义的复杂动态实体争用，不生成挤压、吞掉等隐藏规则，也不能把空心目标当隐形承托。六关参考路径不使用该类情况。参考解不是最短解、唯一解，也未证明每一条合理替代路径都符合教学预期。

`HOVER` 是本版采用的零重力工作名。以后换名必须集中更新词库、数据、解析、提示与版本；不要同时保留两个同义词造成不必要选择。
