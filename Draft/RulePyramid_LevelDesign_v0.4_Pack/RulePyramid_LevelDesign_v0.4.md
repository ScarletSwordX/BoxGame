# 规则金字塔：同格目标、精简动作与六关教学设计

> **版本：LD-v0.4｜用途：交给 Codex 搭建/修改 Unity 2022 灰盒原型**  
> **完整替换 LD-v0.3，不是只改判定的补丁。**  
> 本版以用户确认的两个决定为基线：**同格重叠获胜＋可进入的空心目标；地面四向移动＋原地跳跃；被弹起后允许一次顶点侧移。**  
> 六关数据、参考路径和 Python 检查器均已同步。Python 设计模型通过，不代表 Unity 工程已实现或完成验收。

## 0. 版本边界与不可回退的决定

### 0.1 本轮确认

| 事项 | 本版采用 | 明确不采用 |
|---|---|---|
| 获胜关系 | 两个不同实体分别具有 YOU / WIN，且占据同一逻辑整数格 | 面邻接、距离阈值、对角邻接、屏幕投影重叠、碰一下目标外壳就获胜 |
| 首批目标 | 不带 BLOCK 的颜色实体，以可进入的空心轮廓表现；WIN 生效后点亮 | 给 WIN 默认附送 BLOCK，或让 WIN 暗中取消 BLOCK |
| 地面动作 | 四向移动、原地跳跃；推字由移动接触产生 | 地面定向跳跃、自动登阶、自动翻墙、跨格冲刺 |
| 弹跳后的动作 | BounceApex 时一次水平侧移，随后下落；也可原位恢复下降 | 普通跳跃中侧移、连续空中横移、二段跳 |
| 胜利检查时机 | 每次**合法原子逻辑变化**之后；首次满足就记录 Won，停止本次后续模拟 | 只在整回合落稳后检查、使用动画中的 Collider/包围盒判断 |

这是唯一默认玩法，不提供“同格或邻接都算”的兼容开关。旧输入和旧回放应显式失效，不能在新关卡中继续接收定向跳跃。

### 0.2 延续的机制

玩家为红色方块；规则词为 `RED / BLUE / PINK / IS / AND / YOU / BLOCK / FALL / FLY / WIN / JUMP`。地图使用整数三维网格，四槽正交观察；文字只在同 Y 的世界 +X/+Z 直线上形成句子。保留顶字、落地压字、三格落地弹跳、FLY 载人、整步撤销、固定碑文与可动文字、开发者关卡编辑器。

`JUMP` 仍作用于接触面：**带 BLOCK+JUMP 的方块被下落实体撞到上表面时，下落实体从接触格向上弹最多三格，接触面不自行移动。** 没有横撞触发、没有主动弹力升级。

六关不使用多 YOU、变色/变形、额外 PUSH/HOVER、边缘支撑或新的计时压力。边缘支撑只保留接口，不参与本版六关。

### 0.3 六关迁移摘要

| 关卡 | 本版处理 |
|---|---|
| L01 | 改名“填入那个位置”；右侧路径降为同高，目标 Y=1；取消登阶教学，最后必须再走进目标 |
| L02 | 删除 PINK 的固定 BLOCK；顶 WIN 后继续走进目标，未激活时走入粉色轮廓不获胜 |
| L03 | 右侧槽沿降低一格，压字后能平走出槽；蓝块下降后补平断口，终点保持在有支撑的 Y=2 |
| L04 | 保留弹跳路径；目标改为空心，多走一步进入，而不是停在旁边 |
| L05 | 登乘侧地面抬高一格、出生点同步抬高；平走登上后平台，不再定向跳登乘 |
| L06 | 第二台明确使用“走上去 → 原地跳落”；粉色塔冠保留 WIN、获得 FALL，但不带 BLOCK；最后进入塔冠 |

## 1. 输入与角色行动合同

### 1.1 动作表

| 当前阶段 | 输入 | 逻辑动作 |
|---|---|---|
| Grounded | WASD / 方向键 | 镜头映射为世界四向，水平移动一格；遇可动文字则尝试整链推字 |
| Grounded | Space | 原地向上移动一格；可把正上方一个可动阻挡体顶高一格，然后下落；X/Z 不变 |
| BounceApex | 一个方向 | 在当前高度横移一格，立即恢复下降；阻挡则拒绝，保留顶点 |
| BounceApex | Space / 回放 WAIT | 不再上升，原位恢复下降；可以再次落到弹跳台并进入下一次顶点 |
| 任意可观察状态 | Q / E | 四个镜头槽切换，不推进模拟 |
| 试玩 | Z / R | 整步撤销 / 重开；获胜状态也允许撤销或重开 |

**地面指站在合法支撑面上，不是限定某个 Y。** 可以站在固定平台、文字、带 BLOCK 的颜色块上操作。自动下落不是额外按键；静止站立不会反复压低脚下方块。

普通原地跳跃没有可操控顶点，其上升与下降在同一世界指令中结算。只有受到 JUMP 弹起才产生可停留观察的 BounceApex。不得为了“少一个键”暗加对普通障碍的一格自动登阶。

### 1.2 同时按键与回放

地面同帧出现 Space 和方向：**只发原地 Jump，丢弃该帧方向意图，不缓存为后续侧移。** 被弹起后的侧移需要顶点阶段的新输入；实现时对导致起跳的按键做释放/新按下门控，避免长按把动作串起来。单帧多个方向只选一个确定方向，不能合成对角移动。

顶点同帧出现方向与 Space：只处理该方向的一次侧移，不再加高、不额外执行第二条 WAIT。若方向被挡，整条动作拒绝，不暗中改成原位下降。具体按键优先级在输入适配层实现，Core 一次只接收一条离散指令。

Core 的行为集合只有 `Move(E/W/N/S)`、`JumpInPlace` 和 `ResumeBounceDescent`；同一个方向指令根据 Grounded/BounceApex 被解释为行走或侧移。旧 `JE/JW/JN/JS` 必须被拒绝，不修改世界、撤销栈或其他实体运动。回放文件导入时还要提前报告这些非法指令。

无输入、看提示、旋转镜头、被拒绝的动作，都不会恢复顶点下降。获胜后停止接收新世界动作，只允许观察、撤销、重开、下一关。

### 1.3 顶起、下压与弹跳

**主动顶起：** 原地跳跃的目标格有可移动阻挡体，且其上方空闲，则把该阻挡体与玩家作为一次原子组分别上移一格。只顶一个，不连顶箱塔。锁定文字、固定地形不能被顶。空心非 BLOCK 实体没有可被头顶的实体表面。

**普通落地压低：** 玩家实际下降后接触可移动阻挡体，若其下方空闲且该接触未触发 JUMP，则把它与玩家原子地下移一格。同一次已接受指令最多产生一次玩家下压；继续站立不再压。原地再跳一次，可再次形成冲击。文字默认没有自动重力，压低后会停在新高度。

**JUMP 优先：** 接触面有 BLOCK+JUMP，且这段下降至少有一次 -Y 位移，则由 JUMP 消费冲击，不再同时执行普通下压。横撞、从下方顶碰、等高平走上台、静止站立，都不触发。

三格的基准：台块在 `(2,1,0)`，下落者接触格是 `(2,2,0)`，上升依次经过 Y=3、4、5，正常顶点为 `(2,5,0)`。跌落起点更高不会增加弹力。上升逐格检查，碰顶提前停；被动弹跳不复用主动顶字，不穿过文字。实际升高为零时不生成假顶点，仍不回退执行下压。

弹跳上升中若已经合法进入 WIN 格，直接获胜，不必先到三格终点。否则升完才创建 BounceApex。一次有效顶点侧移后必须完成下降或进入新的弹跳顶点，不允许留在同一个顶点连续侧移。

## 2. 网格、规则与碰撞

### 2.1 坐标与数据

`(x,y,z)` 表示实体占据的整数格，Y 向上。地面方块在 Y=0，站在地面上的玩家占据 Y=1；不要把地面体素高度误当成角色脚下坐标。

每格允许多个实体 ID，通常至多一个阻挡体。**YOU 的实体与不带 BLOCK 的目标同格，是本版必需的正常状态，不是异常穿模。** 不得使用 `Dictionary<GridPos, Entity>` 作为唯一占位结构；应有格到实体集合的查询，并独立计算阻挡。

固定中性地形永久阻挡且不被颜色规则影响。文字永远提供实体阻挡、支撑，可推/顶/压，默认不自动下落；锁定文字不能移动，外观需明确标记。`RED` 文字本身不是 RED 颜色实体。

### 2.2 属性

| 属性 | 本版定义 |
|---|---|
| YOU | 接收玩家指令；不附送 BLOCK/FALL |
| BLOCK | 颜色实体具有实体阻挡和承托表面；不是固定不动。与非阻挡实体的成对交互见下一节 |
| FALL | 缺少有效下方承托时持续沿 -Y 运动到支撑面，不是只下降一格 |
| FLY | 持续沿 +Y 到受阻；有 BLOCK 才能承托并携带玩家 |
| WIN | 与另一个 YOU 同格即可获胜；不附送阻挡，不改变碰撞优先级 |
| JUMP | 有实际落地接触时弹起下落者；需同时有 BLOCK 才存在可撞接触面 |

六关通过可见固定碑文提供 `RED IS YOU`、`RED IS BLOCK`、`RED IS FALL`。PINK 不是天然终点：L02 初始没有有效 WIN，轮廓可进入但不会胜利；其他关通过固定碑文提供 `PINK IS WIN`。

### 2.3 非阻挡目标的双向交互——必要的补充实现约定

为使“玩家进入目标”和“目标下降到玩家所在格”含义一致，使用下列明确的成对碰撞规则，不能只在玩家行走函数里忽略目标：

| 相遇双方 | 阻挡 / 结果 |
|---|---|
| YOU 与不带 BLOCK 的颜色实体，不论哪一方移动 | 允许同格；不互相承托，不顶起、不压低、不作为弹跳接触面 |
| YOU 与带 BLOCK 的颜色实体 | 保留正常实体阻挡与接触；它带 WIN 也不能凭空穿入 |
| 非 BLOCK 颜色实体与固定地形、文字、非 YOU 的 BLOCK 方块 | 仍按世界障碍处理；FALL 能落到世界平台上，不穿入地基 |
| 任意两个非阻挡颜色实体 | 可以同格；仅符合不同 YOU/WIN 条件才获胜 |

这是 **YOU 与非阻挡颜色实体的双向传感交互**，不是 WIN 特判；不带 WIN 的空心颜色实体也适用。BLOCK 玩家不会把下降的空心目标挡在自己头顶一格。目标仍被固定地形承托，因此 L06 的塔冠可以下降至上层平台并停止。

给 WIN 自动移除 BLOCK 会隐藏规则冲突，禁止这样修补。在首批教学关，校验器直接报告 `WIN + BLOCK` 目标为不符合关卡基线；将来需要实体终点谜题时，应由玩家显式修改规则，而不是接触即胜兜底。

### 2.4 句子语法

```ebnf
Sentence = Subject, { AND, Subject }, IS, Property, { AND, Property } ;
Subject = RED | BLUE | PINK ;
Property = YOU | BLOCK | FALL | FLY | WIN | JUMP ;
```

只扫描同 Y 的世界 +X/+Z 连续直线；不扫描 -X/-Z/Y，不允许拐弯、对角线或视角拼接。多条句子属性取并集。`BLUE IS BLOCK [空格] FLY` 的前三词仍有效，FLY 未连接；补入 AND 后同时获得 BLOCK、FLY。左侧 AND 只预留解析，不在六关教学。

可动文字与固定碑文共享同一解析语法，固定碑文是显式、可追溯的规则源，不是隐藏的角色组件属性。所有同色实例共享规则，不按某个实体 ID 偷改行为。

### 2.5 冲突与限制

同时 FALL/FLY 暂定 FLY 优先，显示诊断；六关不利用该冲突。常态优先级不能取消已经开始的弹跳强制下降。非法实体化导致两个 BLOCK 同格时，回滚整条动作并反馈，不挤开、不先判胜。无 YOU、多个 YOU、未知词、旧版本等应被校验器识别；六关只允许一个 YOU。

边界在这批灰盒中是可见固定封闭边框；不加入隐藏死亡地面。自动结算检测重复状态和微步上限，超限回滚并给开发诊断，不能卡死编辑器。

## 3. 胜利、表现与四视角

### 3.1 唯一胜利谓词

```text
存在 a, b：
  a.id != b.id
  a 具有 YOU
  b 具有 WIN
  a.gridPosition == b.gridPosition
```

等式必须包含 X、Y、Z，不能仅比较平面或投影。没有邻接、距离容差、接触外壳兜底。`goal` 是灰盒中的实体 ID 约定，不是 WinEvaluator 唯一检查的 ID；判定来自属性。单个实体自己拥有 YOU+WIN 不会自我匹配获胜。

一个有效状态可以有 BLOCK 的 YOU 与非 BLOCK 的 WIN 同格；两个 BLOCK 非法重叠不能作为获胜捷径。加载关卡时解析和校验后同样可检查该谓词，但六个教学关都禁止初始就获胜。

### 3.2 判定时机：合法原子变化后，而不是动画帧

“即时”指逻辑，不是 Rigidbody 实时检测。每完成一格合法运动、一次原子推字/顶字/压字/载人组移动，先重算因此变化的规则、确认状态合法，再检查 WIN。

**原子组内部不能先检查半个结果。** 例如玩家推 WIN 成句的同时从旧格走到新格，只能在文字和玩家全部到位之后检查；不能因为目标刚激活就在玩家已准备离开的旧格误判。

规则激活也需要检查：若合法最终状态中玩家本来就与刚获得 WIN 的实体同格，立即获胜，不要求额外移动一次。跳跃、弹跳、FALL、FLY 经过目标所在逻辑格也计入，不要等落到下一决策点后才检查。

首次命中时记录 `Won { youId, winId, cell, cause }` 并终止该指令剩余自动运动。表现层只播放到这个已经提交的获胜微步，再播放填入/完成效果。这样没有“进入过目标但之后掉出去了所以不算”，也不会在用户看到获胜后继续播放无关坠落。

撤销恢复到**获胜指令开始前**，并清除终态；不是只退回胜利事件前一格。重开清空胜利与未播放的事件。只有终态不会自己消失；本稿不采用“锁存获胜后还继续模拟整个回合”的替代实现。

### 3.3 目标的视觉合同

不带 BLOCK 的颜色实体显示为明显可进入的轮廓，获得 WIN 后增加亮边、内部发光和向内汇聚效果。最主要的完成动作是“实心红块填入空心空间”。未激活的 PINK 轮廓仍可进入，但不播放完成效果，提示说明缺少 WIN。

轮廓尺寸、中心和格子严格对齐；内部不放实心遮挡模型。不得留下负责实际阻挡的立方体 Collider，仅靠颜色变透明是不够的。若用 Trigger 做指向/特效，不能让它成为独立判胜源。上方悬浮目标显示垂直投影及高度，镜头旋转不改变它的可进入性质。

邻格可显示指向目标的引导，但不能显示“已完成”或自动吸附进目标。已获 WIN 的不同颜色仍带自身图案标记，不只靠色相区别。

### 3.4 四槽观察

选择正交相机，起始建议 yaw 为 45°/135°/225°/315°，俯角约 35.264°；这是本项目的构图参数，不是对参考作品内部参数的断言。围绕固定焦点旋转，平滑过渡期间暂停世界输入，切换结束才启用新映射。

| 槽位 | W | D | S | A |
|---|---|---|---|---|
| 0 | +Z | +X | -Z | -X |
| 1 | +X | -Z | -X | +Z |
| 2 | -Z | -X | +Z | +X |
| 3 | -X | +Z | +X | -Z |

脚下展示四条网格边方向，不假装存在自由屏幕八方向。文字标签面向相机、句子连线绑定世界；切镜头不改变规则解析、运动、胜利或回合计数。被遮挡玩家用轮廓与必要的前景淡出；首次教学不靠完全不可见的背面词。

## 4. 事务、载人、撤销

### 4.1 一次指令

```text
检查版本、终态与当前运动阶段；保存整步快照
→ 构造合法玩家动作，预检原子组；无效则保持原状
→ 提交移动/推字/顶起；重算规则、校验、检查同格 WIN
→ 若获胜：提交 Won，停止；否则继续
→ 恢复动作开始时已有的顶点下降；新产生的顶点不在本指令内再次下降
→ 逐格下落/弹起/上浮，每个合法原子变化后同样检查 WIN
→ 无获胜时，其他实体结算到稳定，YOU 停在 Grounded 或 BounceApex
→ 提交一个完整回合快照与有序事件，供 Unity 播放
```

不能保留旧版“只在 ResolveUntilDecision 末尾检查胜利”的实现。终态 Won 是另一种合法停止点，可能位于原先不是决策点的空中格。

自动顺序固定：上浮按 Y 从高到低，下落按 Y 从低到高；同高度按稳定实体 ID 排序。检查重复状态时包括运动阶段、待恢复下降、冲击消费记录，不能只比较位置。复杂多实体争用/移动弹跳台仍不在 P0，不能依赖 GameObject 枚举顺序猜结果。

### 4.2 FLY 与非玩家弹跳

BLOCK+FLY 平台带动其正上方、实际站稳的 YOU，平台与乘客先检查整组目的格，再原子移动；乘客头顶堵住就整组停，不挤压，不把乘客甩下。纯投影上方的 BounceApex 玩家不是乘客。不承运其他箱塔；不同蓝色实例各自检查，不是强制联动刚体。

任何真正下落的实体都可被 BLOCK+JUMP 接触面弹起；非 YOU 实体也记录顶点，到下一条有效世界指令才原位恢复下降。仅 YOU 顶点可选择侧移。新顶点暂停是离散玩法约定，不靠动画速度决定。已有弹跳的有限下降必须完成，不能因为常态没有 FALL 就永久悬停。

### 4.3 快照

至少保存实体位置/类型/锁定状态、顶点记录（接触面 ID、接触格、实际顶点、实际升高、待强制下降）、胜负状态、获胜双方 ID/格子/原因。规则可从恢复状态重新解析。一次撤销还原整条指令造成的全部规则、重力、弹跳和获胜，不仅还原最先动的方块。

从高台撤回顶点后仍可换出口；从获胜撤回后仍可尝试别的动作。世界撤销不强制恢复镜头槽。编辑撤销与试玩撤销是不同栈；动画中撤销必须取消旧事件队列，不允许延迟回写旧 Transform。

## 5. 六关教学顺序与配方约定

先教“进入目标”，再教顶字、压字、弹跳、载人、综合。每关提示分三级：先指出对象，再解释关系，最后才给明确操作。提示由事件或主动查看驱动，不用倒计时；完成教学事件不能成为隐藏胜利条件。

下文每关都含可复建数据与实际参考回放。JSON 中 `bounds` 和 `solidBoxes` 的六数均按 `[xmin,xmax,ymin,ymax,zmin,zmax]`，端点包含，多个地形盒取并集。`fixedRules` 必须生成可见、可追溯、不可踩踏的基础碑文；列在 `entities` 的锁定文字则是真正占格并参与普通扫描的方块，两者不能混淆。

所有关卡共用：`schemaVersion=4`、`mechanicsVersion=LD-v0.4`、`supportMode=StrictBelow`、`jumpMode=LandingBounce3`、`bounceRiseCells=3`、`decisionMode=GroundedOrBounceApex`、`actionMode=FourWayMoveInPlaceJumpApexSteer`、`winMode=DistinctEntitiesSameCell`、`winCheckMode=AfterAtomicLogicChange`、`ruleAxes=[PositiveX,PositiveZ]`，以及第 3.4 节相机配置。`decisionMode` 描述未获胜时的操作阶段，不取消 Won 终态。

回放 `E/W/N/S` 是世界 +X/-X/+Z/-Z，不是键盘键名；`J` 是原地跳，在顶点按 Space 时解释为恢复下降；`WAIT` 是显式顶点下降；`CAM+` 是观察。表中 Won 表示已经在合法微步获胜并停止，不保证处于落稳状态。动作数不含 CAM，不是最短解证明。

## 6.3 L03｜落地写下重力

### 意图与场景

**落地压字只降一格；FALL 可继续落到底。** 玩家从 `(2,4,1)` 向 -Z 走落，落在 `(2,2,0)` 的 FALL 上，将其压到 `(2,1,0)`，自己停在 `(2,2,0)`。`BLUE IS FALL` 生效，蓝块从 `(4,4,0)` 降到 `(4,1,0)`。

右侧槽沿本版只有 Y=1，其上方通行格为 `(3,2,0)`，与玩家压字后同高。随后平走到蓝块上方 `(4,2,0)`，再进入 `(5,2,0)` 的目标。**不是用新动作代替定向跳，而是关卡本身不再要求登阶。**

### 文字槽与断口

FALL 左侧的固定立面、起点北侧支柱与边框限制初始文字的水平搬运。降低右槽沿后，仍必须检查玩家能否从侧边绕进去直接推词；不靠“本关禁止推 FALL”脚本封路。

蓝块未下落时，断口下方是低一格地面。走入会下降，无法靠原地跳横移回到高路；下降后的蓝块才补平这段路线。目标下面的固定支柱保持实体，不能让玩家从其正下方原地跳入目标绕过蓝桥。

### 分层引导

| 时机 | 观察提示 | 关系 / 操作提示 |
|---|---|---|
| 开场 | “这个词高了一格。” | 显示 FALL 与缺口的高度关系 |
| 高台边缘 | “从上面落下会怎样？” | “走出平台，落在 FALL 上。” |

## 6.5 L05｜让脚下成为电梯

### 意图与场景

**AND 保留承托能力，同时添加 FLY。** 初始物理词串是 `BLUE IS BLOCK [空格] FLY`。两个蓝块都能承托但不会升，AND 位于前蓝块上方、规则缺口前一格。

本版把登乘侧 `(3,1,2)`、`(3,1,3)` 填为地面，出生点改为 `(3,2,3)`。连续两次 -Z，玩家平走到后蓝块上方 `(3,2,1)`。第三次 -Z 把 AND 从 `(3,2,0)` 推到 `(3,2,-1)`，玩家进入 `(3,2,0)`，恰好站在前蓝块上。

句子生效后前蓝块载人到 Y=4、玩家到 Y=5；乘客头顶被 Y=6 顶盖挡住，整组停止。玩家 +X 到高平台，再 +X 进入空心目标。没有地面定向跳，也没有隐式登乘传送。

### 两块平台各自的职责

后平台提供推字的站位，前平台承接玩家推字后的新位置。不要只检查句子能否拼成，却让玩家在推字后走离平台。前平台载人时停在 Y=4；玩家离开后空载继续到 Y=5。后平台也可空载到 Y=5，不要求两者刚性同步。

### 分层引导

| 时机 | 观察提示 | 关系 / 操作提示 |
|---|---|---|
| 登乘前 | “蓝块已经能站，还少一种能力。” | 保留 BLOCK 高亮，FLY 暗显 |
| 缺口前 | “把两种能力连接起来。” | 高亮 AND 缺口 |
| 上浮 | 镜头调整焦点但不偷换方向槽 | 不把 FLY 表现成需要落地触发的弹跳 |
| 停靠 | 标出玩家头顶停止原因 | “现在平走到高台，再进入轮廓。” |

### 验收重点

登乘侧只抬高一格，不补出通往终点的连续阶梯。高台下面仍是实体，不能从下方原地跳穿目标。AND 未连接不升；原子载人净空包含玩家。终点邻格不能提前胜利。

## 6.6 L06｜借两次落差，迎回塔冠

### 意图与场景

**用两次落差取得高度，再让目标下降到可进入的位置。** 两个蓝台有相同 BLOCK+JUMP，分别位于 Y=1 和 Y=4；第一次从高处走落，第二次必须制造实际下降。

| 段落 | 台块格 | 接触格 | 正常顶点 | 一次侧移的落脚格 |
|---|---|---|---|---|
| 第一台 | `(2,1,0)` | `(2,2,0)` | `(2,5,0)` | `(3,5,0)` |
| 第二台 | `(5,4,0)` | `(5,5,0)` | `(5,8,0)` | `(6,8,0)` |

玩家走到 `(5,5,0)` 只是平走上第二台，不弹；再原地跳到 Y=6 并落回 Y=5，才弹到 Y=8。**这一停顿是本版的理解检查，不能用定向跳把“走上台”和“落到台”合并。**

到上层 `(8,8,1)` 后原地顶 FALL：从 `(8,9,1)` 到 `(8,10,1)`，完成 `PINK IS FALL`。塔冠从 `(10,13,0)` 降到 `(10,8,0)`，被 Y=7 固定平台承托；它一直不带 BLOCK，保留 WIN。玩家回主路，进入塔冠所在格完成关卡，不在 `(9,8,0)` 提前完成。

### 分层引导

| 时机 | 观察提示 | 关系 / 操作提示 |
|---|---|---|
| 第一段 | 只保留可查阅的 JUMP 词条 | 不重复强制教程 |
| 平走上第二台却未弹 | “你刚才真的向下落过吗？” | “原地跳起，再落到台上。” |
| 第二顶点 | 显示同样三格长度 | “更高的台，把出口也抬高了。” |
| 仰望塔冠 | “一定要继续向上吗？” | “目标也是受规则影响的颜色实体。” |
| 顶字完成 | 塔冠下降，空心轮廓保持可辨认 | “进入它，而不是站到旁边。” |

### 验收重点

两台正下方均有固定支撑；两个高台分别为 Y=4、Y=7，不补隐藏楼梯。塔冠落点必须对准实际可进入且有支撑的格子。不得通过固化 BLOCK 恢复旧“接触塔冠”的语义，也不得添加隐藏登顶坐标。

即使玩家在别的合法路径上让目标主动移动进自己所在格，也应按相同规则获胜，不设置“必须玩家最后移动”的额外条件。此关参考解选择最后走入，以维持清晰教学。

## 7. 程序框架与实施边界

### 7.1 继续使用轻量架构

在现有 Unity 2022 工程中实现，先检查 `AGENTS.md`、编辑器版本、渲染管线、输入后端和现有包。不要为本轮规则修改强制升级引擎、换渲染管线、安装重型框架或引入实时刚体玩法。

```text
Core/                          纯 C#，不引用 UnityEngine / UnityEditor
  GridPos / EntityId / EntityState / WorldState
  LevelDefinition / RuleToken / PropertySet / RuleSource
  RuleParser / RuleResolver
  OccupancyIndex               每格实体集合，阻挡与存在分开
  CollisionPolicy              YOU ↔ 非 BLOCK 颜色实体的双向查询
  CommandSimulator             四向移动 / 原地跳 / 顶点侧移与恢复下降
  AtomicMovePlanner            推字链、顶起、压低、载人的成组预检与提交
  LandingContactResolver / BounceResolver
  VerticalResolver / MotionState / ISupportPolicy
  WinEvaluator                 不同实体，同格，合法原子提交后检查
  LevelValidator
Application/
  GameSession                  输入事务、世界快照、撤销、重开、终态
  LevelRepository              文件与序列化，不让 View 自行读写源文件
  TutorialTracker              消费语义事件，不私自改物理或通关
UnityView/
  GridWorldView / EntityView / TargetVisual
  PlayerInputAdapter           根据阶段解释按键，不产生定向地面跳
  CameraSlotsController / RuleOverlayView
Editor/                        唯一可引用 UnityEditor 的层
  LevelEditorWindow / SceneGridPainter / ReplayInspector
```

这是职责划分，不要求机械生成几十个空文件。Core 与 Editor 的依赖边界必须保持；无需引入 ECS、通用依赖注入容器或完整语言编译器。表现对象不作为模拟位置/属性的唯一数据源。

### 7.2 模拟接口与事件

```text
Simulate(state, command)
  -> Accepted/Rejected
  -> ResultingWorldState
  -> Grounded/BounceApex 或 Outcome=Won
  -> OrderedEvents
```

先计划并预检同一组的目的格，再一次性提交，重建规则、校验、检查胜利。不要在分别设置 Transform 的中间阶段判胜。只有合法提交才能成为新的 WIN 检查点；非法实体化、循环回滚不能留下 Won 事件或新的撤销记录。

Python 检查器以内部 `_VictoryCommitted` 信号提前结束后续模拟，作为可执行设计示例；C# 可采用显式结果类型，不必照抄异常控制流。核心要求是保存终态并停止该指令后续运动，而不是采用哪种语法。

建议事件包括：

```text
EntityMoved / TextPushed / HeadBump / LandingPress
RuleActivated / RuleDeactivated
BounceStarted(surfaceId, contactCell, requestedRise)
BounceStep / LandingBounce(actualRise) / BounceApexReached / BounceBlocked
ApexSteer / ApexReleased / GravityFall / FlyOrRide / RideStopped
MoveRejected / Won(youId, winId, cell, cause)
```

若 BounceStep 已经触发 Won，后续 LandingBounce/BounceApexReached 不再生成；动画不能为了凑齐旧事件链继续上升。获胜镜头/特效与关卡切换由会话层响应终态，不重新做一套“差不多碰到了”的判断。

### 7.3 数据版本与迁移

辅助包的整体格式为 `DesignGraybox-v0.4`，各关有 `schemaVersion: 4`、`mechanicsVersion: LD-v0.4`。这是可复建的设计 JSON，不是已经接入工程的 Unity Scene 或最终存档协议。导入时展开 `solidBoxes` 为地形，`fixedRules` 转成可见只读碑文；保留实体 ID。

编辑器必须识别并拒绝静默混用 LD-v0.2 / LD-v0.3。旧 v0.3 的面邻接、决策点末尾判胜、定向跳回放均不兼容；只改版本号无法修复目标 BLOCK、坐标和路径。旧 PUSH/HOVER 也不能偷偷映射成当前属性。

## 8. 关卡编辑器预留

```text
→ 保存
```

磁盘 `LevelDefinition`、编辑草稿 `LevelDraft`、试玩 `WorldState` 必须是不同对象。通关时玩家与目标同格不能写回出生数据。画笔的一次拖刷作为一次编辑撤销；试玩撤销不影响草稿。

### 8.2 面板

| 面板 | 本版必需能力 |
|---|---|
| 图层 / 画笔 | Y 切片，当前层二维网格，上下层淡显，单格/矩形地形和实体绘制、擦除 |
| 格子 / 实体 | 同格的所有实体列表，不让玩家覆盖掉目标数据；ID、位置、词语/颜色、锁定、属性来源 |
| 规则 | 生效句子、无效词串、同层关系、碑文来源与实体高亮 |
| 目标 | WIN 格本身高亮；是否空心可进入；下方支撑、上方净空及同高入口检查 |
| 弹跳 | 接触格、三个上升微步、受阻点、顶点一次侧移出口、恢复下降结果 |
| FLY | 平台与乘客整组净空、停止高度、途中是否进入 WIN |
| 相机 | 四槽、初始槽、焦点、正交尺度、俯角、遮挡预览 |
| 教学 | 三级提示、语义事件、关联实体 ID，不作为通关额外条件 |
| 回放 | 世界指令与阶段检查点；逐原子微步查看；Won ID/坐标/原因；动作起点撤销 |

### 8.3 本轮替换的检查

目标预览必须把**目标格自身**标成唯一胜利格，删除旧“六个有效获胜邻格”覆盖层。可以画通往目标的候选入口，但必须标明那些只是入口，不是胜利格；可入格不等于整条路径已经可达。

保存/试玩前至少检查：WIN+BLOCK 与首批目标约定冲突、初始即胜、目标在实心地形中、出生点不稳、重复 ID、非法两个 BLOCK 同格、未知词、旧模式、定向跳指令、提示/回放引用失效。目标没有 WIN 的 L02 初态是有意教学，不应被强行补上 WIN；提示警告须允许与明确教学声明对应。

**不要把“有多实体同格”一概报错。** 一个 BLOCK 的玩家与非 BLOCK 目标同格是合法；多个 BLOCK 才是实体化冲突。同格编辑选择必须允许循环选择/列表选择，不让非阻挡目标被角色遮挡后无法编辑。

顶点预览采用真实的一次侧移，不加额外一格跳跃。普通原地跳预览没有水平箭头，不出现定向跳图标、鼠标落点选取或组合跳提示。L01/L03/L05 的平走入口必须能在该基线上重放，不靠预览器自己的自动登阶逻辑。

目标随 FALL/FLY 移动进入 YOU，以及 YOU 在弹跳中经过 WIN，应显示与实际模拟相同的终止微步。所有这些预览共同调用 Core，不在编辑器里另写近似物理。

## 9. 边缘支撑与未来扩展

六关使用 `StrictBelow`，玩家必须有直接脚底支撑。边缘支撑会改变蓝桥下落、弹跳接触和塔冠落点，暂不加入，以免一次教学同时改变多个空间规则。

保留 `ISupportPolicy.EvaluateSupport(world, entity)` 与按关卡保存的策略 ID。未来可在独立实验关尝试下层边缘承托：除正下方外，查询 `(±1,-1,0)`、`(0,-1,±1)` 的稳定承托；不把同层互托或仅角点接触默认算支撑。承托依赖必须落到有根的稳定结构。

这一实验仅是本项目候选算法，不声称复刻参考游戏。即使颜色块允许边缘支撑，玩家也不能因此踩空气；非 BLOCK 目标仍不向玩家提供支撑。实现新策略后必须重验所有关卡，不在同一个新版本中静默改变六关物理。

| Unity 验收项 | 预期 |

| 地面 Space+方向、长按方向再跳 | 不产生定向跳或缓存顶点侧移，需要新的顶点输入 |

| 六关四视角试玩 | 实际可读的目标、支撑、文字、净空；不要求记不可见关键信息 |

### 10.3 实施顺序

## 12. 文件、来源与使用方式

本版依据当前提供的 `RulePyramid_LevelDesign_v0.3.md` 及其配套 JSON/检查器和本轮确认重新编写，旧文件保留不覆盖。机制与关卡均为本项目的设计约定，不用参考作品的名字替代具体算法。本文件本身包含复建所需的共同参数、每关坐标和参考操作，可以单独交给 Codex；辅助包便于直接载入与运行检查。
