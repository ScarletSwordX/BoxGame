# 规则金字塔：落地弹跳、四视角与六关教学设计

> **版本：LD-v0.3｜用途：交给 Codex 搭建 Unity 2022 灰盒原型**  
> **范围：六个短教学关，而非六座大型迷宫。**  
> 本文包含机制约定、四视角控制、关卡意图、可复建坐标、参考解、编辑器预留和验收要求。
> **v0.3 关键变更：JUMP 改为落地弹跳；第 4、6 关重新设计，旧版横撞开门解法全部废弃。**
> **这是完整替换版，不是只改词义的补丁；请不要把本文规则与 v0.2 关卡数据混用。**

## 0. 阅读顺序与版本优先级

先读本节和第 1—5 节确定规则，再读六关；搭建时，以每关的坐标配方为准，示意图只解释意图。

本次明确把“下落时撞到”写成：**实体沿世界 -Y 下落，撞到另一个方块的上表面。** 不再有水平侧撞触发 JUMP 的行为。“被撞方块带 JUMP，下落方块上升三格”是本轮核心修改；顶点输入、碰顶处理与冲击优先级是为离散原型补齐的设计约定。

本轮用户需求高于此前原型讨论。旧方案中的 `PUSH / HOVER`、固定单视角、固定登顶判定，不再作为本版默认。延续的是：**整数网格、纯 C# 模拟核心、逻辑与表现分离、整步撤销、关卡数据与编辑草稿/试玩状态分离。**

本文件不是对原始《Baba Is You》或《凯瑟琳》的完整复刻。它为这一个原型定义了一套独立、可实现的规则。

### 0.1 用户已经提出的内容

- 玩家是颜色方块；可以前后左右移动、跳跃顶起方块，并通过下落让方块下降。
- 三维俯视/等距风格；四个可切换的视角槽位。
- 与指定的胜利方块相邻即可获胜。
- 颜色词：`RED / BLUE / PINK`；连接词：`IS / AND`。
- 属性词：`YOU / BLOCK / FALL / FLY / WIN / JUMP`。
- 做六关，以清晰引导和特殊用法为主；边缘支撑仍在考虑中。
- **本轮修改：JUMP 作用于被下落方块撞到的方块；响应是把下落方块向上移动三格。**

### 0.2 明确采用的机制约定

| 编号 | 本版约定 | 对关卡的影响 |
|---|---|---|
| A01 | `JUMP` 检查**落地接触面的所属实体**；它须有 BLOCK 才能被撞。实际向上弹三格的是下落实体，接触面不因 JUMP 自己移动 | 替换旧版横撞上移一格；重做 L04、L06 |
| A02 | 三格从**落地接触时，下落实体所占的格子**开始计数，不从开始坠落的位置，也不从弹跳台中心计数 | 台块在 Y=1，落地者在 Y=2，无遮挡顶点在 Y=5 |
| A03 | 碰撞路径逐格检查；被顶棚或阻挡体挡住时，提前结束上升，不穿透、不在被动弹跳中连顶其他方块 | L04/L06 主路径留足三格净空 |
| A04 | 为保留回合式解谜，弹起后进入 `BounceApex` 决策点；玩家可横移一格后下落，或原位下落 | 这是本稿补充的操作方案，不是自由空中操控，也不要求抢时间 |
| A05 | 横撞、从下方顶到 JUMP、静止站立、从等高平台直接走上去，都不触发；必须有实际向下位移 | L06 第二个平台复用“跳起再落地”的触发方式 |
| A06 | 同次落地先判断 JUMP；若已由 JUMP 处理，不再压低接触面一格 | 避免一次接触既压低弹跳台又弹起，改变高度基准 |
| A07 | 普通玩家落地冲击仍只把可移动方块压低 **1 格**；持续站立不继续下压 | L03 保留；下压与 FALL 仍不同 |
| A08 | 邻接仍为三维六面；不同 YOU/WIN 实体才成立；在**下一决策点**检查，不在动画途经时检查 | 稳定站立或可输入的弹跳顶点均可判胜；六条参考解均在地面/平台旁获胜 |
| A09 | 普通水平推动只用于文字；颜色块没有额外 PUSH 能力 | L04 的蓝块是弹跳台，不是能横推的箱子 |
| A10 | 规则仍只沿世界 +X/+Z、同一高度读取；镜头只影响观察和输入映射 | 不改文字语法和四槽镜头 |
| A11 | 六关关闭边缘支撑，采用 StrictBelow；保留策略接口 | 不在这次 JUMP 修改中同时改支撑规则 |

**A01 是此次需求修改；A02—A06 是让它可实现、可预测的补充定义。改变这些定义时，要同时重验坐标和参考操作，不能只改一个常量。**

## 1. 玩家究竟能做什么

### 1.1 操作表

| 行为 | 建议输入 | 确切结果 |
|---|---|---|
| 地面普通移动 | WASD / 方向键 | 按当前镜头映射，沿一条世界水平轴移动 1 格，然后处理下落 |
| 地面推文字 | 普通移动碰到可动文字 | 同方向推动文字 1 格并进入旧格；可推连续文字链，整体目的区域须有空间 |
| 地面原地跳跃 | Space | 向上 1 格；可顶起头顶一个可移动实体 1 格；然后下落 |
| 地面定向跳跃 | Space + 一个方向 | 先向上 1 格、再水平 1 格、然后下落；不是自由抛物线控制 |
| 自动下落 | 走出支撑面、主动跳跃后、恢复弹跳下降阶段 | 沿 -Y 到接触面；优先判断落地弹跳，否则按原有支撑/下压处理 |
| 弹跳顶点侧移 | 顶点时按一个方向 | 在顶点高度横移 **1 格** 到空位，立即恢复下落，直到落地或下一次弹跳顶点 |
| 弹跳顶点原位下降 | 顶点时 Space；回放记为 `WAIT` | 不额外上升，恢复下落；再次落到同一弹跳台，会形成下一次顶点决策 |
| 切视角 | Q / E | 四槽循环；包括在顶点观察时，也不推进模拟、不自动下降 |
| 撤销 | Z | 恢复一条已接受世界指令之前的完整状态，包括文字、规则、弹跳阶段与待下落状态 |
| 重开 | R | 恢复关卡初始数据，清空待结算运动，不改变磁盘源文件 |
| 查看规则 | 点击规则栏/对象 | 追踪生效句子和作用实体；只观察，不推进世界 |

同一帧只生成一条世界指令。**输入适配器要先读当前运动阶段，再解释 Space。**

地面时组合跳跃优先于普通移动；顶点时，方向键表示侧移，Space 表示原位恢复下落。顶点同时按 Space+方向时，适配器只发一次侧移，不额外加一格上升；直接向 Core 发送 `JE/JW/JN/JS` 这种地面定向跳指令则拒绝。没有按键不会自动选择方向。

顶点侧移若撞到墙、颜色块或文字，指令拒绝，保留顶点状态，不偷偷推进时间。**顶点不推字、不顶字，也不能反复横移留在空中**：一次有效侧移后必须完成下降结算。

不加入拉箱子、自由飞行、自由空中转向、二段跳、攀边悬挂、所有障碍自动翻越、手动下降一格按钮。“WAIT”只表示恢复已有弹跳的下降阶段，不是任意位置瞬移向下。

### 1.2 三种向上运动必须区分

| 名称 | 谁上升 | 触发 | 上升与后续控制 |
|---|---|---|---|
| 主动跳跃/顶起 | 玩家上升 1 格；头顶可动块可被顶高 1 格 | 地面主动跳跃指令 | 按原跳跃规则落地；没有新的空中停顿 |
| `JUMP` 落地弹跳 | **下落并撞上接触面的实体** | 接触面有 BLOCK+JUMP，且碰撞前确实下移过 | 从接触格向上最多 3 格，进入顶点决策；玩家可侧移一次 |
| `FLY` 持续上浮 | 被赋予 FLY 的颜色实体，以及合法乘客 | 生效规则后的自动结算 | 沿 +Y 到受阻，继续采用整组净空检查，不是固定弹三格 |

例：蓝色弹跳台在 `(2,1,0)`，带 `BLOCK + JUMP`；红方块从 `(2,3,0)` 落到 `(2,2,0)`，向下尝试进入蓝块占据的格子时发生接触。

```text
蓝块始终：               (2,1,0)
红块的落地接触格：       (2,2,0)
红块上升路径：           (2,3,0) → (2,4,0) → (2,5,0)
红块的无遮挡弹跳顶点：   (2,5,0)
```

因此 **`BLUE IS JUMP` 不是“蓝块自己跳”，也不是“红块必须有 JUMP 才会被弹”。** 它让蓝块的上表面成为弹跳接触面。JUMP 不会顺便赋予 BLOCK，单独无实体阻挡的 JUMP 不能产生落地碰撞。

### 1.3 顶起、下压的接触规则

顶起：**主动跳跃的上升阶段**撞到正上方的可移动文字或颜色实体，且它正上方为空，则把它上移 1 格。首版不连顶一串实体；上方链条太长就阻止该动作。固定地形和锁定文字不能被顶。

下压：玩家实际发生向下位移，且本次接触**未由 JUMP 消费**，落到一个可移动实体上时，若该实体下方为空，把它下移 1 格，玩家随之落在它上方。同一次动作最多产生一次下压，不连压到底。

直接踏上同高度平台、静止站立、被电梯携带，都不算一次新的落地冲击。原地跳起再落到可压低的方块上，算一次冲击；这允许重复跳跃，每次压低一格。

**“下压 1 格”与“FALL 自动落到底”不是同一规则。** 被压低的对象若自身带 FALL，接下来仍会继续按重力结算；没有 FALL 则停在新高度。

顶起一个有 FALL、下方又无支撑的方块，它可能立即落回。这是可预测的规则结果，不是为了保留顶起效果而暗加一回合悬停。

被动弹跳的上升不复用 HeadBump：路径上的箱子和文字阻挡上升，而不是被连顶三次。顶字仍是前两关教过的主动跳跃能力；本轮不把一次改动扩成“弹跳连锁搬箱”系统。

## 2. 世界、实体和文字的共同约定

### 2.1 坐标

`(x,y,z)` 表示方块占据的整数格，Y 向上，X/Z 为水平两轴。单格长宽高均为 1。

方块位于 `(x,y,z)` 时，角色站在其上方占据 `(x,y+1,z)`。例如地面体素在 Y=0，站在地上的玩家位于 Y=1。**配方中“地面高度”是方块所在高度，不是顶面高度。**

首版每格至多有一个阻挡体；为了以后支持不带 BLOCK 的颜色实体，运行时占用查询应允许一个格子容纳多个非阻挡实体，不能把逻辑结构写死成“每格只有一个任意实体”。六关初始布局不使用重叠。

### 2.2 三种实体

| 类别 | 默认行为 | 表现 |
|---|---|---|
| 固定中性地形 | 永远阻挡、承托，不能推、顶、压、升降；不属于 RED/BLUE/PINK | 石灰/深灰基座，区别于可改写的颜色方块 |
| 颜色实体 | 属性由当前颜色规则决定；没有 FALL/FLY 时，不自动改变高度 | RED / BLUE / PINK，辅以不同图案，不能只靠色相辨认 |
| 可动文字实体 | 始终占一格、可承托、可水平推/顶/压；**默认没有自动重力** | 白色文字方块，词义与颜色实体的颜色分类分离 |

`RED` 这个文字方块不是红色实体。因此 `RED IS YOU` 不会让玩家控制所有写着 RED 的文字。

锁定文字仍可参与普通句子扫描，但不能移动，外观必须有锁扣/底座标记；禁止暗中把“看起来能推”的字锁住。锁定规则条的处理见第 10 节。

### 2.3 六个属性的精确定义

| 属性 | 本版语义 | 不代表什么 |
|---|---|---|
| `YOU` | 将玩家指令发送给匹配颜色的实体 | 不自动附送重力、飞行或可改写胜利条件 |
| `BLOCK` | 对其他实体形成占位阻挡、支撑和接触面 | 不等于“固定不动”；BLOCK 仍可有 FALL、FLY、JUMP |
| `FALL` | 不受支撑时沿 -Y 下落，直到被支撑或落出有效区域 | 不等于“受玩家踩压才下降” |
| `FLY` | 沿 +Y 自动上浮到受阻；若承托玩家，则尝试一起移动 | 不等于悬停，也不是玩家任意方向自由飞行 |
| `WIN` | 成为可触发胜利的目标实体 | 不会把目标变成不可移动的特殊建筑 |
| `JUMP` | 该实体作为落地接触面时，把实际下落的撞击者从接触格向上弹最多 3 格 | 不使属性持有者自行上升；不响应水平侧撞、静止站立或从下方顶碰 |

颜色实体不带 BLOCK 时，不阻挡、不能被当台阶或被头顶/踩压；用轮廓/半透明表示。其自身仍可按 FALL/FLY 位移；恢复 BLOCK 不能导致两个阻挡体挤在同一格。

六关均用固定规则明确提供玩家的基础能力：

```text
RED IS YOU
RED IS BLOCK
RED IS FALL
```

这避免“玩家隐藏地拥有重力、其他颜色却没有”的例外。六关不会操作这三条规则；基础碑文可以折叠显示，但查看规则时必须能追溯。

六关只使用一个 RED 实体，也不修改 YOU。多 YOU 同步控制、控制权转移、玩家失去 FALL 的空中行动，均不在本轮关卡验收范围内；不要为了用完 YOU 的玩法而塞进最后一关。

### 2.4 规则语法

```ebnf
Sentence = Subject, { AND, Subject }, IS, Property, { AND, Property } ;
Subject  = RED | BLUE | PINK ;
Property = YOU | BLOCK | FALL | FLY | WIN | JUMP ;
```

这里用户所说的 YOU/BLOCK 等，在程序中叫“属性”，不是实体实例。`IS` 是赋属性关系，`AND` 是连接词。

- 只读世界 `+X` 和 `+Z` 上连续、同 Y 的直线。无反向读取、Y 轴读取、拐弯或透视拼接。
- 所有生效句子作用于全关卡同颜色实体，不限定句子所在楼层。
- `BLUE IS BLOCK AND FLY` = 蓝色同时有 BLOCK、FLY。
- `RED AND BLUE IS BLOCK AND FALL` 展开成两种颜色各有两个属性；语法可预留，六关不使用左侧 AND。
- `BLUE IS BLOCK [空格] FLY` 中，前三个词仍是一句有效规则；未连接的 FLY 不生效。
- 多条规则取并集，重复属性不叠加倍率。无 AND 的两个连续属性不算一条更长句子。
- 首版不支持 `RED IS BLUE` 的变色/变形，也不支持 NOT、OR、HAS、TEXT 等额外语法。

### 2.5 冲突和失败不能交给引擎碰撞随机处理

| 情况 | 约定 |
|---|---|
| 同一颜色同时 FALL、FLY | 本稿暂定 FLY 优先；界面提示“上浮覆盖下落”。六关不依赖这个冲突，必须单独测试后才开放给玩家 |
| 弹跳路径上方被堵住 | 在第一处阻挡前结束上升；不穿透，不整体回滚已经发生的落地；实际升高不足 3 格须有反馈 |
| JUMP 与落地压低同时可能触发 | 优先 JUMP，不再对接触面执行 LandingPress；被顶棚完全挡住也不改成下压 |
| 顶点下一步方向被挡 | 拒绝该指令，保留位置、顶点阶段与待下落标记；允许改选方向、WAIT、撤销或旋转 |
| 改规则后两个阻挡体实体化到同一格 | 回滚本次完整动作并给出原因；不能静默穿模或随机挤开 |
| 无有效 YOU | 进入无控制提示，允许撤销/重开，不能锁死 UI |
| 多个有效 YOU | 留给后续同步控制实现；P0 关卡校验禁止生成此组合，不能静默挑第一个 |
| 上浮时乘客头顶受阻 | 整组停止，不挤压、不穿透，也不把乘客遗留在半空 |
| 出界 | 灰盒边界用可见固定边框表达；将来加入虚空时，落出底界进入可撤销失败状态，不传送回出生点 |
| 自动结算不收敛 | 检测重复状态/微步上限，回滚并报开发诊断；禁止卡死编辑器 |

## 3. 胜利与四视角

### 3.1 胜利判定

在整条动作结算到**下一决策点**之后，存在两个不同实体 `a`、`b`，满足：

```text
a has YOU
b has WIN
a.id != b.id
abs(a.x-b.x) + abs(a.y-b.y) + abs(a.z-b.z) == 1
```

即通关。左右、前后、正上方、正下方都算；同格、边接触、角接触、只在屏幕投影上接触，都不算。

判定由属性决定，不用固定 `GoalTrigger` 或要求玩家必须到预先写死的塔顶坐标。地图中“指定胜利块”由 `PINK IS WIN` 等句子指定。六关暂时都以 PINK 为目标，但“粉色天生是终点”不是规则。

没有额外要求“必须踩上目标”，也不在跳跃/上浮/弹跳动画途经邻格时提前判胜。`YOU AND WIN` 出现在同一个孤立实体上不会自己与自己邻接而获胜。

**v0.3 的决策点包括稳定站立和 `BounceApex`。** 在真正可输入的顶点与目标面邻接，可以获胜；仅在上升中途经过目标旁边不算。本组六条参考解没有利用空中获胜，避免在首次弹跳教学中再引入胜利时机谜题。

### 3.2 摄像机

采用正交相机和四个 90° 间隔的方位槽，借鉴用户提出的俯视构图，不做视错觉拓扑。Unity 的正交相机模式可由 `Camera.orthographic` 配置。[S3]

建议初始俯角取 `atan(1/sqrt(2)) ≈ 35.264°`，四个 yaw 取 `45° / 135° / 225° / 315°`。这是本项目的起始构图参数，**不是对《纪念碑谷》内部镜头参数的考证**。最终允许在 Inspector 调整。

旋转围绕关卡焦点平滑过渡；过渡期间暂不接受世界指令，以免旧映射和新映射混用。旋转结束后再更新键位提示。切镜头不重算规则、不施加重力、不记一回合。

### 3.3 镜头相对输入的明确映射

本稿采用随槽位旋转的输入，而非世界固定 WASD。对应的画面方向是沿菱形网格四条边，不假装存在一条恰好“屏幕正上”的网格方向。

| 槽位 / yaw | W | D | S | A |
|---|---|---|---|---|
| 0 / 45° | +Z | +X | -Z | -X |
| 1 / 135° | +X | -Z | -X | +Z |
| 2 / 225° | -Z | -X | +Z | +X |
| 3 / 315° | -X | +Z | +X | -Z |

脚下显示随槽位更新的小型方向提示。输入最终转换成世界 `Move(+X)` 等指令再交给模拟器。**关卡回放记录世界方向，不能记录 W/D 键名**，否则转镜头会破坏测试。

### 3.4 旋转是观察工具，不是另一套规则

文字标签朝向相机以保证阅读，实体与语法连线仍绑定世界坐标。活跃规则有连线/高亮，规则栏显示文字来源；选中 BLUE IS FLY 时，同时描边所有受影响蓝块。

被遮住的玩家显示轮廓，必要时对前景地形淡出。高处悬浮块下方显示垂直投影和高度标记。禁止用完全不可见的背面字块做首次教学，也不要把每关都设计成“转一圈找隐藏答案”。

## 4. 物理结算和电梯承托

### 4.1 一次世界动作的事务：结算到决策点，不要求全部落地

```text
读取当前 Grounded / BounceApex 阶段，检查指令类型
→ 保存完整世界快照（含所有实体的顶点/待下落状态）
→ 尝试玩家动作；若拒绝，整条指令不推进世界
→ 已接受指令才恢复“动作开始时已有”的弹跳下降阶段
→ 处理移动/推字/主动顶起/下落接触，文字改变后重算规则
→ 接触面是 BLOCK+JUMP：逐格向上最多三格，记录新的 BounceApex
→ 接触面不是 JUMP：处理支撑与玩家本回合首次落地压低
→ 其他实体继续按 FLY / FALL / 承托规则结算
→ 本回合新产生的 BounceApex 不再继续下降；其余变化结算到稳定
→ 检查非法状态，再在下一决策点检查六面邻接胜利
→ 提交状态和有序事件序列，供动画播放
```

**不允许保留旧版“弹起之后同一事务内立刻落到底”的 ResolveUntilStable。** 否则玩家没有机会利用弹跳高度；再次落回 JUMP 还可能把整条事务变成无限弹跳循环。

规则变化仍发生在同一条指令中。顶点停顿是明确的运动阶段，不是依赖动画播放速度的物理例外。初始六关都从稳定支撑状态开始，不在加载时自动播放未说明的第一跳。

自动运动使用确定顺序：上浮由高到低，下落由低到高，同高度按稳定 ID；有新顶点的实体跳过后续自动下落。复杂相向运动或多人争用一个格子仍需独立冲突测试，不能依赖 Dictionary 或 GameObject 枚举顺序。

所有隐式循环都要检测重复状态与微步上限；用于检测的状态必须包括顶点阶段、待下落标记、已消费冲击等，不能只比较坐标。

### 4.2 FLY 载人

有 BLOCK 的上浮块可带动**当前直接站在其上方的玩家**。把平台和乘客视为本次上移的一个组：先检查整组目的格，再同时提交位置。乘客头顶受阻则整组停止。

单个飞行颜色块不会无条件推动头顶的其他箱子或文字；除明确的乘客外，碰到其他阻挡体就停止。首版不实现多层箱塔整体运输。没有 BLOCK 的 FLY 实体不能承托玩家。处于 BounceApex 的玩家也不因为投影碰巧在某个 FLY 方块上方就被当作乘客；须先完成下落，建立实际承托关系。

第 5 关有两个同色平台，但不是一个刚体：各自按照相同属性运动；前块带玩家，后块空载，受阻后最终高度可以不同。这是规则对实例的作用，不应做成“所有蓝块必须同时成功才能升高”的联动箱系统。

### 4.3 撤销

撤销覆盖玩家、全部颜色实体、文字位置、规则变化、胜负状态和本次动作内全部连锁。**新增必存项：每个实体是否处于 BounceApex、接触面 ID、接触格、实际顶点、待恢复下落标记。** 规则可由恢复后状态重新解析，不必把 Unity 场景当成快照。

从高台撤销回弹跳顶点，必须仍能侧移或原位下降；不能只恢复空中坐标，却立刻被下一帧重力拖下去。再撤销触发弹跳的动作，恢复到起跳/走落之前。相同顶点原位落下再弹起属于一次有效的物理回合，虽然起止坐标相同，仍可记录和撤销。

视觉镜头槽位不属于世界撤销内容；撤销不会强行把玩家转回旧视角。编辑器自身的撤销和游戏回合撤销使用不同的栈。

### 4.4 JUMP 落地响应的实现合同

用碰撞双方的角色命名，避免误把 JUMP 当成撞击者能力：

```text
mover   = 正在沿 -Y 下落的实体
surface = mover 下方、实际挡住它的实体

条件：本次下降阶段确实有至少一次 -Y 位移
      surface 有 BLOCK 和 JUMP

contactCell = mover 当前的最后一个合法空格
依次检查 contactCell + Up * 1、*2、*3：
    第一个阻挡格之前停止；不穿透，也不推动上方物体
actualRise > 0：
    保存 mover 的 BounceApex，暂停这次新产生的下降阶段
actualRise == 0：
    mover 被承托在接触格，给出顶棚阻挡反馈，不生成空顶点
本次接触已处理，绝不再执行 LandingPress(surface)
```

起点再高，反弹也只有三格；不会把跌落势能换成额外高度，也不会在相同顶点上通过连续按 Jump 叠加高度。

JUMP 必须由接触面具有，撞击者有没有 JUMP 不影响被弹；一般 FALL 颜色方块也适用，不仅限于 YOU。相反，没有 BLOCK 的颜色实体没有可撞的接触面。

### 4.5 如何处理非玩家方块与连续弹跳

采用一个统一的离散阶段约定，而不是给非玩家方块偷偷关闭 JUMP：

**任何被弹起的实体都在本次动作生成 BounceApex；只有 YOU 能在自己的顶点选择一次水平侧移。** 非 YOU 顶点保持到下一条被接受的世界指令，再原位恢复下降；拒绝指令、镜头旋转、查看规则，都不会消耗它。

同一次动作中新产生的顶点不再下落，所以“落回原台再弹”必须跨过下一条输入边界，单条模拟不会无限循环。重复弹跳可以持续多个回合，但每一回合都有有限结果。

一次已经开始的被动弹跳是有限运动过程，不是 FLY。它离开顶点后必须完成下落；即使实体的常态不带 FALL，也不能因为运动暂停而永久变成悬浮方块。一般文字默认不自动下落，本组六关不安排被动弹射文字，但运动记录要保留 `resumeForcedFall`，不能把有限弹跳阶段写成颜色/FALL 的专属硬编码。

本轮不使用“移动中的 FLY+JUMP 台”“多个下落者同回合抢同一格”等组合。接口保留通用接触信息；开放这些组合前补独立验收，不以简化验算工具代替完整并发求解。原有 FALL/FLY 优先级仅用于常态升降，不得取消已提交的弹跳下降阶段。

## 5. 六关教学结构

教学顺序仍然是“观察与邻接 → 改写文字高度 → 从上方写规则 → 弹跳 → 连续上浮 → 综合”。不修改 YOU，不教学左侧 AND，也不为用完词汇而添加第七个复杂机制。

| 关卡 | 名称 | 新认识 | 复用 | 参考世界动作数 |
|---|---|---|---|---:|
| 01 | 靠近，而不是重合 | 四视角、六面邻接、一格定向跳跃 | 无 | 9（另有 1 次观察旋转） |
| 02 | 把一句话顶完整 | 顶字改变句子高度；粉色须由 WIN 成为目标 | 行走、推字与下落 | 6 |
| 03 | 落地写下重力 | 落地压字一格；FALL 会继续落到承托面 | 文字同层、定向跳跃 | 3 |
| 04 | 落下去，弹上来 | 被踩的蓝块有 JUMP，落下的红块弹三格；顶点可以选择出口 | 推字成句、走出高处形成下落 | 6 |
| 05 | 让脚下成为电梯 | AND 叠加；FLY 持续载人，不同于 JUMP 的固定脉冲 | 站上平台、推字 | 4 |
| 06 | 借两次落差，迎回塔冠 | 相同弹力因弹跳台高度不同而达到不同高度；目标也受 FALL 影响 | 两次落地弹跳、顶字、重力、邻接 | 12 |

这里的“动作数”包含顶点横移；一个完整弹跳不是零成本外挂动作。数字是参考路径长度，不是最短解证明或游玩时长估计。L03/L05 继续保持短，重点展示因果。

### 5.1 引导的三个层次

第一层只指出值得观察的对象；第二层提示关系；第三层才给明确操作。高级提示由玩家主动打开，或在数次无效尝试后提示可查看，不用倒计时催促。

教学记录使用语义事件，例如 `RuleActivated`、`HeadBump`、`LandingPress`、`LandingBounce`、`BounceApexReached`、`ApexSteer`、`RideStopped`；不要靠“玩家进入某个坐标就假定他懂了”。事件记录用于提示与测试，不给胜利判定添加隐藏教学门槛。

成功后允许一句简短总结，再进入下一关。不插入长篇机制说明，不一次弹出全部词汇表。

### 5.2 统一布局说明

下文坐标配方中：

- `bounds = [xmin,xmax,ymin,ymax,zmin,zmax]`，端点都包含。
- `solidBoxes` 的每项也用上述六个数，表示填满这个长方体；相交地形取集合并集。
- 列出的文字实体实际参与同层扫描。`锁定=是` 的字不能移动。
- `fixedRules` 是不可改写的基础碑文，**必须在关卡中有可见表现和规则来源，不是暗藏的能力**。它们独立于可动文字区域，不可被当作额外台阶；详见编辑器规范。
- 边界采用可见固定边框；未列出的边界内格子为空。不能擅自加斜坡、自动攀爬或额外可站立装饰。
- 教学台可以外包金字塔美术，但装饰不参与碰撞；不能把完整实心金字塔直接填到配方之外，造成意外通路。

回放记号：`E=+X`、`W=-X`、`N=+Z`、`S=-Z`；`J` 为地面原地跳；`JE/JS` 为地面定向跳；`WAIT` 为顶点原位下落；`CAM+` 为观察转镜头。这里的 E **不是键盘 E**。

同一 `E` 在地面是普通移动，在 BounceApex 是一次侧移；回放记录世界方向，重放时由确定的运动阶段解释。各检查点除坐标外必须比较阶段。

## 6.1 L01｜靠近，而不是重合

### 关卡意图

先建立“这是一个真实三维、按格子行动的世界”，以及“胜利需要碰面，不是屏幕上看着碰到”。不要在第一关让玩家移动规则。

场景是一段绕过高墙的短路。开始视角让玩家看见目标，但中墙挡住直接路线；后侧通道和一格高差引导观察旋转、绕行、定向跳跃。

### 关键过程

1. 从起点向 +Z 绕到中墙后侧；转镜头能看清通道，但旋转不是通关条件。
2. 沿 +X 接近右侧高一级平台，用一次定向跳登上去。
3. 到 `(3,2,1)` 时，玩家与目标 `(4,2,0)` 仅斜角相邻，不通关。
4. 再走到 `(3,2,0)`，共用一个面，通关。

### 引导与反馈

| 时机 | 低剧透提示 | 更明确提示 |
|---|---|---|
| 开场 | “让红方块靠近发光的粉方块。” | “要有一个面相邻，不必站到它里面。” |
| 撞中墙 | “试着看看另一面。” | “Q / E 切换观察角度，地图不会改变。” |
| 到一格台阶前 | “这一级可以跳上去。” | “按住一个方向，再按跳跃键。” |
| 斜角停留 | 两者之间显示未连接的面标记 | “斜角不算相邻。” |

### 防绕解与验收重点

中墙高到不能被一格跳跃直接越过。不要在目标下方留一个可站立、与目标垂直面邻接的格子，否则玩家可能从下面提前获胜。允许从其他合法面靠近目标，不强制指定一条路线。

检查四个镜头槽位的遮挡和键位提示。玩家应能解释“旋转只让我看清，不会真的把路接起来”。

## 6.2 L02｜把一句话顶完整

### 关卡意图

把“文字不仅能水平搬动，还能被顶到另一个高度”变成一次明确发现；同时证明粉色并不天生等于胜利。

```text
目标规则行 Y=3：  [PINK] [IS] [ 空位 ]
初始文字 Y=2：           [WIN]
高台上的玩家先把 WIN 推到空位正下方，
再从浅槽绕到它下面，将它顶高一格。
```

### 关键过程

1. 玩家在 `(1,2,0)`，向 +X 把 WIN 从 `(2,2,0)` 推到 `(3,2,0)`。
2. 从侧边浅槽下降，绕到 `(3,1,0)`，恰好站在 WIN 正下方。
3. 原地跳：WIN 到 `(3,3,0)`，与 PINK、IS 在同一高度，`PINK IS WIN` 成立。
4. 粉块这时才出现胜利光环；玩家走到 `(4,1,0)`，与它相邻。

### 引导与反馈

| 时机 | 第一级 | 第二/三级 |
|---|---|---|
| 开场 | “粉方块还没有成为目标。” | 高亮缺词的 PINK IS 行，不直接显示解法箭头 |
| 推字前 | “先把 WIN 移到缺口下面。” | 标出 `(3,2,0)` 的垂直对齐虚线 |
| 到浅槽 | “字也有高度。” | “站在字下面，跳一下。” |
| 成句 | 显示 `PINK IS WIN` 连线并同步点亮粉块 | “你改变的是规则，不只是搬开了一块石头。” |

### 特殊用法

**词语不必在句子所在平面内水平拼进去，可以从下方写入句子。** 这是本游戏区别于纯平面搬字的第一项教学。

### 防绕解与验收重点

未成句时，与粉块相邻不能赢。WIN 的初始高度与句子不同，禁止扫描器因为屏幕投影对齐就误判。字推过头可以撤销；不要在浅槽末端设置不可恢复死亡。

PINK/IS 是明确有锁扣的固定字，避免玩家直接把整句降下来绕开顶字教学。上方 WIN 目的格必须空着。

## 6.3 L03｜落地写下重力

### 关卡意图

让玩家亲手发现两件相关但不同的事：**落到文字上能把它压低一格；给蓝块赋 FALL 后，蓝块会继续下落到支撑面。**

```text
起点在较高的侧平台。
FALL 字位于句子上方一格：
Y=2                 [FALL]
Y=1  [BLUE] [IS]    [空位]

下落压字：FALL 从 Y=2 到 Y=1。
规则生效：远处蓝块从 Y=4 落至 Y=1，补上落脚点。
```

### 关键过程

1. 玩家从 `(2,4,1)` 向 -Z 走出平台，落到 FALL 字上。
2. FALL 从 `(2,2,0)` 压到 `(2,1,0)`，玩家停在 `(2,2,0)`；`BLUE IS FALL` 生效。
3. 蓝块从 `(4,4,0)` 下落到 `(4,1,0)`，停在地基上，成为台阶。
4. 玩家向 +X 定向跳到槽口边框 `(3,3,0)`，再向 +X 落到蓝块顶面 `(4,2,0)`，邻接目标。

### 为什么有一个文字槽

FALL 所在位置两侧有固定立面，前侧是起点支柱，后侧是边界。字在初始高度不能被随意水平搬走；槽底和周边也限制下降后的回收。

这个约束通过**真实地形和可见边框**实现，不是给 FALL 私自添加“仅本关禁止水平移动”的脚本。右侧槽沿较高，因此出槽要复用第 1 关的定向跳跃。

### 引导与反馈

| 时机 | 第一级 | 第二/三级 |
|---|---|---|
| 开场 | “这个词高了一格。” | 用同层虚线显示缺口，而非用大箭头直接给出下落路径 |

| 落地 | 先强调文字下降 1 格，再显示规则生效 | “落地压字一格；FALL 让蓝块一直落到支撑上。” |
| 走上蓝块 | 展示稳定接触阴影 | 不再提示，交给玩家复用跳跃 |

### 防绕解与验收重点

初始蓝块不能在未获得 FALL 时自行掉下来。站在字上不持续下沉；一次落地只压一格。固定右槽沿、目标支柱和蓝块落点不能被替换为直接连通的平台，否则 FALL 会变成纯演出。

重点检查“从旁边跳入文字槽”“在字上原地跳后下压”等合法替代解法；它们仍使用落地写规则，可以接受。绕过一切文字操作直接到目标则是需要修复的绕解。

## 6.4 L04｜落下去，弹上来

### 关卡意图

本关取代旧版“撞蓝墙、让蓝墙升一格”的门洞，专门建立正确因果：

> **蓝块获得的是“把落下来的东西弹起”的能力。你需要先落到它上面，才能到达更高处。**

只放一个弹跳台、一个明确出口、一处推字成句操作。第一次弹起停在顶点时给出侧移提示；不让玩家通过试错反应时机理解新机制。

### 空间关系

```text
沿 Z=0 看侧剖面（P=玩家，B=弹跳台，#=固定地形）：

Y=5                顶点 ─→ 高台落脚格 ─→ 目标旁
Y=4                 ↑       #
Y=3    起点 → 边缘 →↓       #
Y=2       #         接触格   #
Y=1       #          B      #
Y=0    ########################
                    X=2     X=3

B 在 Y=1，落地者在 Y=2，弹三格到 Y=5。
不是 B 升高，也不是从出发高度 Y=3 再加三格。
```

### 关键过程

1. 玩家在 `(0,3,0)` 向 +Z 推一次 JUMP，字从 `(0,3,1)` 进入 `(0,3,2)`，拼成 `BLUE IS JUMP`。基础碑文已有 `BLUE IS BLOCK`。
2. 回到 `(0,3,0)`，向 +X 到 `(1,3,0)` 的边缘；从这里看见蓝台与高处出口。
3. 再向 +X 走出边缘。红块先到 `(2,3,0)`，实际下降一格，在 `(2,2,0)` 与蓝台上表面接触。
4. 蓝台不动，红块上升经过 Y=3、4、5，到 `(2,5,0)`；暂停在 `BounceApex`。
5. 玩家可以转镜头查看，但这不是计时操作。按 +X 一次，红块到 `(3,5,0)`，落在 Y=4 的固定台面上，退出顶点阶段。
6. 再沿 +X 到 `(4,5,0)`，与粉目标 `(5,5,0)` 面相邻获胜。

### 引导与反馈

| 时机 | 第一级提示/表现 | 第二、三级提示 |
|---|---|---|
| 开场 | “上面的平台，比普通跳跃更高。” | 高亮蓝台，不直接画完整解法 |
| 看规则 | “让蓝色成为弹跳台。” | 同时描边 BLUE、JUMP 和实际蓝块；不要只在玩家身上显示能力图标 |
| 站到边缘 | “从上面落下去。” | “横着撞不算；要落到蓝块顶面。” |
| 第一次接触 | 蓝台轻微压缩的纯表现动画，红块上升；显示三格标尺 | 标出接触格 Y=2 和顶点 Y=5，逻辑蓝块坐标仍为 Y=1 |
| 第一次顶点 | “现在可以选一个方向。” | 显示 +X 方向的真实落脚预览；“不用抢时间，方向键横移一格。” |
| 成功 | “弹跳台不动，落下的方块被弹起来。” | 对比三格弹力与一格主动跳跃 |

顶点 Space/WAIT 会让玩家原位落回并再次弹起，提供可恢复尝试，不自动替玩家选出口。该输入必须结束于下一个顶点，不能在一个回合里无限弹下去。

### 防绕解：文字槽不能成为备用楼梯

可动 JUMP 使用真实地形组成的小槽：初始位置左右有固定块，目标位置右侧/后侧有挡块，左侧是锁定 IS，目标格正上方有顶盖。这样玩家能从前方推入，却不能绕到字后面把它推出来，搬到缺口当悬浮台阶。

**目标格顶盖 `(0,4,2)` 是重要结构，不是装饰。** 不加它时，玩家可能从上方掉进空槽后侧，再把 JUMP 推回出发区。文字槽和锁定字必须可见、可查看，不用脚本禁推来代替几何。

高台固定体素最高到 Y=4，普通玩家在蓝台顶部只能站到 Y=2，主动跳至多到 Y=3，无法直接进入高台。蓝台下方为固定地基，不能通过反复普通下压降低它；从下方顶高它的站位也不存在。

前后边墙阻止从 Z 方向绕到终点；墙面在前景时可淡出显示，但其碰撞不能随相机切换改变。上升柱的三个格必须保持畅通。

### 验收重点

先不拼 JUMP，走落到蓝台上，应停在 `(2,2,0)` 而不是被弹；普通定向跳也到不了高台。拼好规则后，应在同一个接触位置产生顶点 `(2,5,0)`。横撞蓝台不得使它移动。

在简化参考模型内，排除所有落地弹跳转移后，已遍历 57 个可达状态，没有找到通关状态。这只检验该模型中的无弹跳绕解，不是所有 Unity 行为的证明。

## 6.5 L05｜让脚下成为电梯

### 关卡意图

用一个有明确必要性的 AND：**同一块平台既需要阻挡/承托，又需要上浮。** 玩家在自己脚下的设施仍可承托时完成句子，再被带到高处。

与上一关的对照只说一件事：**JUMP 要实际落地接触，给固定三格上升；FLY 从规则生效开始持续上升，到受阻才停。** 本关没有任何 JUMP 方块，避免初学时把“站上电梯”误认为触发弹跳。

初始规则：

```text
BLUE IS BLOCK [空位] FLY
```

所以蓝块目前能站，但不会升。AND 位于玩家前方；推入空位后变成：

```text
BLUE IS BLOCK AND FLY
```

### 关键过程

1. 从 `(3,1,3)` 走到 `(3,1,2)`，定向跳到后蓝块上方 `(3,2,1)`。
2. 向 -Z 推 AND：AND 从 `(3,2,0)` 到 `(3,2,-1)`；玩家前进到 `(3,2,0)`，正好站在**前蓝块**上。
3. 句子生效，前蓝块载玩家上浮。玩家头顶遇到 `(3,6,0)` 的固定顶盖，最终玩家 Y=5，前蓝块 Y=4。
4. 玩家向 +X 走上高平台 `(4,5,0)`，邻接目标 `(5,5,0)`。

### 为什么必须有两个蓝块

只有脚下一个蓝块时，玩家推字后通常会走离平台，电梯升了却没有载到人。这里后蓝块提供出发落脚点，前蓝块承接玩家推字后的新位置。

**检查“推字之后玩家还站在哪里”，不能只检查“规则能否拼出来”。** 这也是程序和关卡共同需要遵守的关键状态。

### 引导与反馈

| 时机 | 第一级 | 第二/三级 |
|---|---|---|
| 开场 | “蓝块已经能站，还少一种能力。” | 固定高亮 BLUE IS BLOCK；FLY 保持未连接状态 |

| 推字后 | 规则连线与蓝块上浮同一事务响应 | 相机只跟随重构焦点，不改变 yaw 槽位 |
| 碰顶 | 显示乘客头顶接触，整组停止 | “现在可以走到高台。” |

### 防绕解与验收重点

未补 AND 时不能提前启动 FLY。推字那一步必须让玩家落在前蓝块上，而非空地上。顶盖必须按“玩家+平台”的整组净空计算，不能把玩家挤进顶盖。

后蓝块空载，可以比前蓝块多升一格；这不是 bug。不要把两个蓝块强行做成刚性联动。高平台足够高，不能从下方靠常规一格跳跃直接到达，也不能利用规则台文字连续垫脚绕上去。

## 6.6 L06｜借两次落差，迎回塔冠

### 关卡意图

综合题不再加入新词，而是复用“落地接触”“高度相对关系”和“目标也是规则对象”。

> **同一种 JUMP，把你从低处弹到中层，再从中层弹到上层；最后用 FALL 让高处的目标降到身边。**

两个蓝台位于不同高度，都由 `BLUE IS BLOCK AND JUMP` 赋予同样能力。第一个台要求从边缘走落；第二个与玩家脚下等高，需要主动跳起再落到它上面。这样检查玩家是否理解触发条件，而不是只会“看见蓝块就按前进”。

### 两段高度关系

| 段落 | 弹跳台格子 | 红块接触格 | 上升三格后的顶点 | 下一落脚格 |
|---|---|---|---|---|
| 第一段 | `(2,1,0)` | `(2,2,0)` | `(2,5,0)` | `(3,5,0)`，下方是 Y=4 固定台面 |
| 第二段 | `(5,4,0)` | `(5,5,0)` | `(5,8,0)` | `(6,8,0)`，下方是 Y=7 固定台面 |

**两次弹力都是 3，不是第二次偷偷加大弹力。** 改变的是弹跳台的空间高度。每个顶点出口只需要一次水平位移，不存在隐藏的空中连按。

### 关键过程

1. 从 `(0,3,0)` 走到 `(1,3,0)`，继续 +X 走落到第一蓝台：接触格 Y=2，弹到 `(2,5,0)`。
2. 在顶点向 +X 侧移到 `(3,5,0)`，落在中层平台；再走到 `(4,5,0)`。
3. 第二蓝台在 `(5,4,0)`，顶部对应玩家 Y=5。直接走上去只建立支撑，**没有实际下落，所以不会弹起**。
4. 参考解在 `(4,5,0)` 发出 `JE`：红块先到 `(5,6,0)`，落回 `(5,5,0)`，触发第二台，弹到 `(5,8,0)`。另一合法解是先走上第二台，再原地跳起落下。
5. 从第二顶点向 +X 侧移到 `(6,8,0)`，到达上层平台，继续前往 `(8,8,1)` 的文字下方。
6. 原地跳，顶起 FALL：从 `(8,9,1)` 到 `(8,10,1)`，与同层 PINK、IS 组成 `PINK IS FALL`。
7. 粉色塔冠从 `(10,13,0)` 下落到 `(10,8,0)`，由 Y=7 固定平台承托；它保留 BLOCK、WIN。
8. 玩家回到 Z=0，走到 `(9,8,0)`，与塔冠面邻接获胜。

### 引导与反馈

| 时机 | 第一级提示/表现 | 第二、三级提示 |
|---|---|---|

### 防绕解与验收重点

第一台 Y=1、第二台 Y=4，各有直接固定支撑，不能受正常落地压低影响。两级出口的固定地形高度要分别是 Y=4、Y=7，不能为了美术补出一格一格能走上的侧边楼梯。

规则词位于上层；玩家不能把 FALL 从起点搬来充当额外台阶。塔冠初始 Y=13，不能擅自降至常规可接近的高度；落点有固定支撑，下降不需要新增挤压伤害或虚空失败规则。

第二段允许“从中台定向跳落到蓝台”和“先走上蓝台，再原地跳”两种解法。它们都满足真正的落地触发，**不要用隐藏脚本强制玩家使用 JE**。

在简化参考模型中，排除所有弹跳转移时，无弹跳可达子集只有 2 个状态；允许第一台、排除第二台弹跳时可达子集为 6 个状态。两个子集均已遍历，未找到通关。这不证明整体唯一解，只用于发现新版弹跳是否被明显绕过。

## 7. 是否加入边缘支撑

### 7.1 本稿结论：六关不依赖它，接口保留

不是认为边缘支撑不值得做，而是本轮同时在教文字高度、下压、FALL、JUMP、FLY。再加入“下方明明空着却不会掉”的支撑例外，会直接改变第 3、6 关的推理。

此外，本稿已允许**没有 FALL/FLY 的颜色块保持高度**。边缘支撑的额外价值主要在“有 FALL 时，如何靠邻近低层结构维持悬臂”，而不是简单再提供一种悬停。

首轮六关全部保存 `supportMode: StrictBelow`；不要在全局开启一个新物理开关后，继续使用未重新验算的旧关卡。

### 7.2 实验版应当精确定义，不用“像凯瑟琳那样”代替算法

《凯瑟琳》的官方商店介绍可以确认它通过移动方块造路并向上攀登。[S2] **本段不声称完整还原该作具体支撑算法，下面是本项目提出的可选模型。**

实验策略名：`LowerEdgeAnchor`。当一个受 FALL 的颜色方块位于 p 时，除直接下方外，还允许它由下面一层、四个正交侧向偏移格提供边缘承托：

```text
p + ( 0,-1, 0)  直接下方
p + ( 1,-1, 0)  下层右侧
p + (-1,-1, 0)  下层左侧
p + ( 0,-1, 1)  下层前侧
p + ( 0,-1,-1)  下层后侧
```

这些下层侧向格对应的是立方体水平边的接触关系。先不允许 `(1,-1,1)` 这种仅角点接触，也不允许同高度相邻两块彼此声称有支撑。

被引用的承托块本身必须稳定：沿依赖链最终到固定地形，或本版规则明确允许静止悬停的非 FALL/非 FLY 阻挡体。只向更低 Y 建立依赖，避免同层互相支撑导致两块空中自锁。

这项策略只改变颜色 FALL 体的支撑查询；玩家站立仍需直接脚底接触，不能沿“边缘支撑关系”踩空气。它不阻止 FLY 向上，也不让文字自动获得 FALL。

### 7.3 接口与单独试验

```csharp
// 策略接收纯数据，不读 Collider、Transform 或 GameObject。
public interface ISupportPolicy
{
    SupportResult EvaluateSupport(WorldState world, EntityId entity);
}
```

先实现 `StrictBelowSupportPolicy`；另一个只留注册位置和配置值，不提前开发整套算法。真正加入时做独立实验关，而非替换六关中的任一教学题。

实验必须能看见支撑边高亮，并测试：直接托住、下层边托住、角点不托住、承托块被移除后坍塌、两个无根块不能互托、切视角不改变支撑。随后重新重放全部原关卡。

## 8. 关卡的体验打磨与试玩问题

### 8.1 首轮观察什么

不要只记通关耗时。记录玩家是否理解了因果：

| 关卡 | 试玩后用一句话确认 |
|---|---|
| L01 | “你刚才为什么还差一步才赢？” |
| L02 | “为什么这个 WIN 要顶高，而不是只推到旁边？” |
| L03 | “文字只降了一格，蓝块为什么降了更多？” |
| L04 | “哪块有 JUMP，实际被弹起来的是哪块？三格从哪里算？” |
| L05 | “补上 AND 后，蓝块为什么既能载人又能升？” |
| L06 | “为什么走上第二个蓝台不弹？为什么两个相同台能到不同高度？目标又为什么能下降？” |

让玩家先尝试说明，再判断是否需要补提示；不要把“按箭头照做成功”当成已经理解。

### 8.2 不要用隐藏脚本制造假解谜

不因进入某个触发框就让蓝块下降；下降必须来自 FALL。不因“完成教学”就给玩家加一格跳跃高度。不把第 5 关的平台设为路线动画；它必须在相同 FLY/承托规则下运行。

教学事件可以改变提示和镜头焦点，不可以改变玩法属性。关卡不可解时，应修改地形配方或规则，不加 `if(levelId == ...)` 的特殊通关代码。

### 8.3 金字塔包装

六关可作为同一金字塔的六个独立教学台；每关的上升位置在关卡选择画面中递进。首版不要求六关物理无缝相连，也不把前一关搬过的文字状态继承到下一关。

中性装饰可以形成收分的阶梯轮廓，但避免外围天然出现连续可爬楼梯。碰撞几何必须严格来自关卡数据；灯光、浮雕、背景塔身不参与逻辑。

## 9. 程序框架：维持轻量，按当前机制扩展

### 9.1 工程原则

继续用 Unity 2022 现有工程。先检查 `AGENTS.md`、Unity 版本、渲染管线、输入后端和已有包；不为本稿强制迁移 Unity 6、切换渲染管线或安装重型框架。

本版采用：**纯 C# 规则/模拟核心 + 会话服务 + Unity 表现与输入 + 独立编辑器适配层**。不需要 ECS/DOTS、通用依赖注入容器、大型事件总线或通用语言编译框架。

```text
Core/                         不依赖 UnityEngine / UnityEditor
  GridPos, EntityId, WorldState
  LevelDefinition, RuleToken, PropertySet
  RuleParser, RuleResolver
  CommandSimulator            地面移动/推字/主动跳跃/顶点侧移
  LandingContactResolver      下落接触：JUMP 优先，否则支撑/下压
  BounceResolver              三格上升扫描；不复用主动 HeadBump
  MotionState                 Grounded/BounceApex/待恢复下落
  VerticalResolver            FALL/FLY/承托，结算到下一决策点
  ISupportPolicy
  WinEvaluator, LevelValidator

Application/
  GameSession                 整步快照、撤销、重开、加载关卡
  LevelRepository             JSON 读取/保存接口
  TutorialTracker             只消费事件，不改物理

UnityView/
  GridWorldView               数据生成模型、按事件播放动画
  PlayerInputAdapter          镜头相对键位 → 世界指令
  CameraSlotsController       四槽、过渡、输入暂停
  RuleOverlayView             规则连线、对象高亮、提示

Editor/                       唯一允许引用 UnityEditor 的部分
  LevelEditorWindow
  SceneGridPainter
```

这是职责划分，不要求机械拆成同名的几十个空文件。小型辅助类可以合并；模拟核心和 Editor 依赖边界不能合并。

### 9.2 核心状态

使用稳定实体 ID 和整数坐标；颜色、词语、锁定状态、属性来源单独存储。规则集可以重建，不依赖场景文字组件里的字符串作为运行时唯一数据源。

一次 `Simulate(command)` 返回新状态、当前决策阶段和有序事件列表。运动阶段属于 Core，不由 Animator 参数判断。游戏和编辑器必须共同调用 `ResolveUntilDecision`；Unity FixedUpdate 不得在已提交的 BounceApex 上继续施加隐藏重力。

参考检查器记录的一次无遮挡弹跳结果事件序列是 `PlayerFell/GravityFall → BounceStep × 3 → LandingBounce → BounceApexReached`；其中 LandingBounce 是携带接触格与 actualRise 的结果通知。玩家下一次方向输入才生成 `ApexSteer → 落地/新弹跳`。事件只描述已求出的动作，不是另一个物理数据源。

一次 `Simulate(command)` 返回新状态和有序事件列表。Unity 的 Transform 是状态的展示结果，不用于下一步规则判断。动画播放完成前锁住世界输入；撤销中断动画后以恢复状态重建表现，不能留下半格位置。

建议事件包括：

```text
EntityMoved / TextPushed / HeadBump / LandingPress
RuleActivated / RuleDeactivated
LandingBounce / BounceStep / BounceApexReached / BounceBlocked
ApexSteer / ApexReleased / GravityFall / FlyStep / RideStopped
MoveRejected / Won / NoControllableEntity
```

### 9.3 新版数据必须显式版本化

关卡文件至少保存 `schemaVersion`、`mechanicsVersion`。**LD-v0.2 的 JUMP 是横撞响应，LD-v0.3 是落地弹跳；相同词面不代表兼容。** 导入旧版时要求显式选择迁移并让回放失效，不能只替换版本字符串。L01/02/03/05 的布局虽可复用，也须在新版本重新验算。

旧 PUSH/HOVER 同样应报告不兼容，不能把 HOVER 静默映射成持续上升的 FLY。

运行时/存档另外保存 `MotionState`，不是让关卡初始 JSON 含一堆默认悬空阶段。首版关卡编辑器只允许稳定出生点，运动状态由试玩记录生成。

## 10. 关卡编辑器的设计预留

### 10.1 先做 Unity 内开发者工具

首版采用 **IMGUI EditorWindow + SceneView 3D Grid Painter**。IMGUI 是工具窗口的界面实现方式；“类 Tilemap、按 Y 切层绘制”是编辑交互方式，两者不是互斥方案。

`SceneView.duringSceneGui` 可用于 Scene 视图的自定义交互/界面。[S4] Unity 的 `GridLayout` 可作为视图侧的格子转换辅助，但核心仍用独立的整数坐标结构。[S5]

当前不要求打包给玩家使用的运行时编辑器；数据、编辑操作和校验独立于 UnityEditor，为以后换成运行时 UI 保留复用点。

### 10.2 最小工作流

```text
新建/读取 JSON
→ 在 Y 切片中画固定地形和实体
→ 配置文字与规则碑文、四视角初始构图、提示事件
→ 校验并查看活跃规则
→ 复制草稿进入试玩
→ 回放参考解 / 手动试玩 / 撤销
→ 停止试玩，回到未被污染的草稿
→ 保存
```

三个对象必须分离：磁盘 `LevelDefinition`、编辑草稿 `LevelDraft`、试玩 `WorldState`。停止试玩不自动把被玩家推乱的文字覆盖进关卡源文件。

### 10.3 编辑面板

| 面板 | P0 必须支持 | 本轮不要扩大为 |
|---|---|---|
| 图层 | Y 层选择、当前层二维网格、上下层半透明参照 | 通用体素建模软件 |
| 画笔 | 固定地形、RED/BLUE/PINK、文字词表、擦除、矩形填充 | 自定义物理材质/自由网格 |
| 实体检查 | ID、位置、颜色/词语、锁定标记 | 每实体可编程脚本 |
| 规则 | 自动解析、当前有效句子、无效词串、关联对象高亮 | 任意布尔表达式编辑器 |
| 基础碑文 | 锁定句子的词序编辑与展示位置 | 隐藏硬编码属性表 |
| 相机 | 四槽预览、初始槽、焦点、正交尺度、俯角 | 自由轨道与镜头剪辑系统 |
| 教学 | 提示文本、触发事件、关联实体 ID、提示层级 | 通用剧情流程图系统 |
| 测试 | 从出生点试玩、返回编辑、导入/记录世界指令回放；显示 Grounded/BounceApex | 首版自动求解所有关卡 |
| 弹跳预览 | 接触格、三格上升柱、顶棚截断、顶点四向出口和下落终点 | 自由抛物线编辑器/连续物理轨迹调参 |

拖拽一批格子的画笔操作算一次编辑撤销；游戏回合撤销与它分开。切层和切镜头属于观察，不改关卡实体数据。

### 10.4 固定碑文的实现，不能造成数据和地图脱节

固定基础规则可以做成关卡边缘的只读碑文条：由有序词元生成、对玩家可见、支持点击追溯。碑文条不进入行走区，不提供额外可踩台阶；它与活动文字共享同一个句子语法解析器，得到的规则一起汇总。

这里的固定碑文属于显式规则源，不是把 RED 的能力写在 CharacterController 里。编辑器应显示“规则来自碑文”或“规则来自坐标词串”。

每关配方中另外列出的锁定 PINK、IS 等文字，则是真正占格的规则字，参与普通轴向扫描；不可与背景碑文混为一类，以免第 2、3 关的几何出错。

### 10.5 几项特别值得保留的检查

- 文字扫描预览在切相机后不能改变；切层可观察 Y 错位，但不影响模拟器的实际解析。
- 一键显示所有目标块的 6 个有效邻接格，提示其中被地形堵住的格子，查找从背面/下方提前赢的绕解。
- 显示可动字上方和下方一格的阻挡，用于检查顶字/压字能否成立。
- 显示 FLY 平台和乘客的净空、预期停止高度，不只画平台自身的路径。
- 选择 JUMP 实体，显示“属性持有者/下落撞击者”两个角色，以及接触格 Y+1、正常顶点 Y+4；不是简单从台块中心画三格箭头。
- 对上升三格逐格标注可通过/受阻；悬空词块也必须进入阻挡预览，不能只检查固定地形。
- 在弹跳顶点预览四个水平出口：同层可否进入，之后落到哪里，会否再次弹跳；顶点位移不默认具有额外一格跳跃。
- 测试面板显示 `Grounded / BounceApex`、接触面 ID 和待下落状态；支持“推进到下一决策点”，不是只看实体高度。
- 录制回放保存世界指令及检查点运动阶段；从平台撤销回顶点后，必须能继续正确重放。
- 若顶点四向均受阻且 WAIT 只能原位循环，给出可访问性警告；不要自动改造地图或关闭 JUMP。
- `supportMode` 随关卡保存；切换实验支撑策略后把既有回放标记为“需重新验证”。
- 保存前检查目标 ID 引用、提示事件引用、出生位置、地形重叠、无控制对象、未知词汇和旧机制版本。

可视化预览必须调用同一套纯数据模拟/校验函数，不能写一套与游戏不一致的“编辑器模拟重力”。

### 11.3 实施次序
